| **10항** | **15~25매** | **25매** ⭐ |

### 25매 선택 이유
- **각 청구항당 평균 2~3매** (10항 × 2.5 = 25)
- **시스템 + 알고리즘 + 하드웨어 + 실시예** 4영역 균형
- **변리사 표준 작성 분량** (총 60~80 시간)
- **심사관 이해도 ↑** (구체적 입증)
- **PCT 진입 시 추가 도면 불필요** (25매로 5개국 충분)

## 🅐 카테고리 A — 시스템 전체 구성 (3매)

### 【도면 1】 FireNavi 통합 시스템 전체 구성도
- **청구항 매핑**: 청구항 1 (System 독립항)
- **도시 내용**: 4중 결합 (a)WiFi 위치추적부 + (b)AI 다중 엔진부 + (c)차등 적용부 + (d)3-Tier 분산 처리부의 통합 블록 다이어그램
- **표시 요소**: 화살표로 데이터 흐름, 각 부의 명칭 + 부호 (예: 100=시스템, 110=위치추적부, 120=엔진부 ...)
- **목적**: 발명의 전체 구조 한눈에 파악

### 【도면 2】 데이터 흐름 아키텍처
- **청구항 매핑**: 청구항 1, 9
- **도시 내용**: 입력(센서) → 처리(AI) → 출력(가이드)의 데이터 파이프라인
- **표시 요소**: 입력 데이터 종류 (WiFi RSSI, CCTV, IoT) · 처리 단계 (예측·분석·결정) · 출력 (개인 경로·진동·음성)
- **목적**: 데이터 흐름의 기술적 효과(Technical Effect) 입증

### 【도면 3】 시스템 운영 환경 개념도
- **청구항 매핑**: 청구항 1, 9
- **도시 내용**: 시설(크루즈·빌딩) 내부 배치, WiFi AP·엣지 서버·거주자 카드의 물리적 위치
- **표시 요소**: 시설 단면도 + WiFi 신호 영역 + 데이터 전송 경로
- **목적**: 산업이용가능성 명확화

## 🅑 카테고리 B — WiFi 위치추적부 (2매)

### 【도면 4】 WiFi 실내 위치추적부 구성도
- **청구항 매핑**: 청구항 1 (a), 청구항 5
- **도시 내용**: 객실 키 카드 내 임베디드 WiFi 모듈 → AP 신호 수집 → 위치 산출 흐름
- **표시 요소**: 카드 구조 (모듈 위치) · WiFi AP 3각 측위 · 좌표 산출 알고리즘 박스
- **목적**: 2~3m 정밀도 실현 방식 입증

### 【도면 5】 RF 지문 맵 자가 캘리브레이션 흐름도
- **청구항 매핑**: 청구항 5
- **도시 내용**: 7일 일상 동선 수집 → 무감독 학습 → RF 지문 생성 → 드리프트 감지 → 재학습 사이클
- **표시 요소**: 단계별 박스 + 시간 가중 함수 `F(x,y) = Σ wₜ · RSSI_t(APᵢ)` 표시
- **목적**: 자가 캘리브레이션의 진보성 입증

## 🅒 카테고리 C — AI 다중 엔진부 (5매)

### 【도면 6】 3 AI 엔진 동기 작동 통합 구조
- **청구항 매핑**: 청구항 1 (b), 청구항 2, 3
- **도시 내용**: 제1·2·3 엔진의 100ms 동기 사이클 + Lock-free 이중 버퍼 + 시간 스탬프 검증
- **표시 요소**: 3 엔진 박스 (병렬) · 이중 버퍼 (Buffer A/B) · 시간 스탬프 검증 모듈
- **목적**: 청구항 1의 (b) 핵심 메커니즘 시각화

### 【도면 7】 Lock-free 이중 버퍼 동작 메커니즘
- **청구항 매핑**: 청구항 2
- **도시 내용**: 두 메모리 버퍼의 원자적 포인터 교환 + 엔진 응답 지연 시 차단 없음
- **표시 요소**: Buffer A (Read) · Buffer B (Write) · Atomic Swap 박스 + 타임라인
- **목적**: §112 기재요건 + 신규성 입증

### 【도면 8】 제1 엔진 (Prediction) — 화재·연기 확산 예측
- **청구항 매핑**: 청구항 3 (i)
- **도시 내용**: Navier-Stokes CFD + LSTM 신경망 + Beer-Lambert 가시거리의 통합 파이프라인
- **표시 요소**: 입력(센서) → CFD 시뮬레이션 → LSTM 예측 → Beer-Lambert 산출 → 출력(위험맵)
- **목적**: 알고리즘 결합의 진보성

### 【도면 9】 제2 엔진 (Behavior) — 군중 동역학 시뮬레이션
- **청구항 매핑**: 청구항 3 (ii)
- **도시 내용**: Social Force Model + Kernel Density Estimation의 결합 흐름
- **표시 요소**: 거주자 위치 입력 → Social Force 계산 → KDE 밀도 분석 → 흐름 예측 출력
- **목적**: 6,000명 동시 처리의 기술적 효과

### 【도면 10】 제3 엔진 (Decision) — 개인별 경로 결정
- **청구항 매핑**: 청구항 3 (iii)
- **도시 내용**: A* Dynamic Pathfinding + 4-Factor Risk Map + PPO 강화학습
- **표시 요소**: Risk Map 격자 + A* 경로 탐색 시각화 + RL 정책 업데이트
- **목적**: 개인별 차등 경로 메커니즘

## 🅓 카테고리 D — 개인별 안전 마진 차등 적용부 (3매)

- **도시 내용**: 입력(등록정보·이동패턴·카드) → ML 분류 모델 → 6 유형 출력
- **표시 요소**: 입력 데이터 박스 3개 · 분류 모델 (의사결정나무 또는 신경망) · 출력 6 유형 (고령자·장애인·어린이·임산부·환자·동반보호자)
- **목적**: 분류 메커니즘의 구체화

### 【도면 12】 α=2.0 가중치 적용 + 의학적 근거 시각화
- **청구항 매핑**: 청구항 4 (ii)
- **도시 내용**: 3대 의학·통계 근거 → α=1.5~2.5 가중치 도출 → 경로 비용 산출
- **표시 요소**: CO LC50 그래프 (일반 vs 취약) · 이동속도 비교 · 구조 시간 비교 → α 결정 도식
- **목적**: 진보성 (학제 간 결합) 입증

### 【도면 13】 보호자 5m 동기화 시나리오
- **청구항 매핑**: 청구항 4 (iii)
- **도시 내용**: 취약자 + 보호자 위치 → 5m 분리 감지 → 경로 재계산 → 동기화
- **표시 요소**: 시설 평면도 + 취약자(빨강) + 보호자(파랑) + 분리 감지 알림 + 새 경로
- **목적**: 보호자 매칭 시스템 시각화
