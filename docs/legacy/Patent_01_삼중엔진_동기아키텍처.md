# 특허 명세서 — PAT-NEW-01

## 발명의 명칭

**화재 대피 시스템에서 예측 엔진, 행동 엔진 및 결정 엔진의 100ms 이내 실시간 동기 연동을 통한 개인별 대피 경로 생성 방법 및 시스템**

---

## 기술분야

본 발명은 화재 대피 기술에 관한 것으로, 보다 구체적으로는 화재 확산 예측, 군중 행동 분석, 경로 결정이라는 이질적 연산을 수행하는 세 개의 독립 AI 엔진을 100ms 이내의 파이프라인 사이클로 동기 연동하여 수천 명의 개인별 대피 경로를 실시간으로 생성하는 방법 및 시스템에 관한 것이다.

---

## 배경기술

종래의 화재 대피 시스템은 고정된 비상구 안내판과 방송 시스템에 의존하며, 화재의 동적 변화를 반영하지 못한다.

최근 연구에서는 CFD(전산유체역학) 기반 연기 확산 예측, Social Force Model 기반 군중 시뮬레이션, A* 알고리즘 기반 경로 탐색이 각각 독립적으로 연구되어 왔다. 그러나 이 세 가지 연산은 서로 다른 계산 특성을 갖는다:

| 연산 유형 | 계산 특성 | 단독 실행 시간 |
|----------|----------|-------------|
| CFD 연기 예측 | 편미분 방정식 수치 해석, GPU 집약적 | 수 초 ~ 수 분 |
| 군중 행동 분석 | N-body 상호작용, O(N²) 복잡도 | 수백 ms |
| 경로 탐색 | 그래프 탐색, 동적 가중치 갱신 | 수십 ms |

종래 기술의 문제점은 다음과 같다:

1. 세 가지 연산을 직렬로 수행하면 전체 응답 시간이 수 초 이상이 되어 실시간 대피 안내가 불가능하다.
2. 세 가지 연산을 단순 병렬로 수행하면 데이터 정합성이 보장되지 않아 경로 결정 시점에 이미 무효화된 예측 데이터를 사용하게 된다.
3. 기존 연구에서는 세 가지 연산을 동일 시스템 내에서 100ms 이내에 동기 연동하는 구체적 방법을 제시하지 못하고 있다.

---

## 해결하려는 과제

본 발명은 상기 문제점을 해결하기 위하여 안출된 것으로, 계산 특성이 이질적인 세 개의 AI 엔진을 파이프라인 구조로 연동하되, 엔진 간 데이터 교환에 이중 버퍼링과 시간 스탬프 기반 정합성 검증을 적용하여, 전체 사이클 시간을 100ms 이내로 유지하면서 데이터 정합성을 보장하는 방법을 제공하는 것을 목적으로 한다.

---

## 과제의 해결수단

### 1. 시스템 구성

본 발명에 따른 시스템은 다음 구성요소를 포함한다:

**(a) 예측 엔진 (Prediction Engine)**
- LSTM 네트워크에 의한 실시간 추론 모듈 (Fast Path)
- CFD 수치 해석에 의한 정밀 보정 모듈 (Slow Path)
- 이중 경로(Dual-Path) 출력 병합기

**(b) 행동 엔진 (Behavior Engine)**
- KDE 기반 밀집도 산출 모듈
- Social Force 연산 모듈
- 공간 분할 그리드 (Spatial Hash Grid, 셀 크기 5m × 5m)

**(c) 결정 엔진 (Decision Engine)**
- 위험지도 합성 모듈
- A* 경로 탐색 모듈 (MinHeap 기반)
- 출구 배정 최적화 모듈

**(d) 동기 버스 (Synchronization Bus)**
- 이중 버퍼 메모리 (Buffer A / Buffer B)
- 시간 스탬프 레지스터
- 정합성 검증기

### 2. 파이프라인 동기 연동 방법

#### 단계 S100: 이중 경로 예측 (Prediction Engine)

예측 엔진은 두 개의 경로를 동시에 실행한다:

**Fast Path (LSTM 실시간 추론):**
```
(S101) IoT 센서로부터 현재 시점 t의 환경 데이터 벡터 X(t)를 수신한다.
       X(t) = [T₁...Tₙ, CO₁...COₙ, S₁...Sₙ, H₁...Hₙ]
       여기서 T=온도, CO=일산화탄소, S=연기감지, H=HVAC 상태이고,
       n은 센서 수이다.

(S102) X(t)와 이전 k개 시간 단계의 데이터 {X(t-1),...,X(t-k)}를
       LSTM 네트워크의 입력 텐서로 구성한다.
       입력 텐서 형상: (batch=1, sequence_length=k, features=4n)

(S103) LSTM 네트워크를 통해 t+Δt₁, t+Δt₂, t+Δt₃ 시점의
       공간별 위험도 예측 맵 P_fast(x,y,t+Δtᵢ)를 산출한다.
       여기서 Δt₁=10초, Δt₂=30초, Δt₃=60초이다.
       산출 소요 시간: 15ms 이내.

(S104) P_fast에 시간 스탬프 ts_pred = t를 부여한다.
```

**Slow Path (CFD 정밀 보정):**
```
(S105) 백그라운드 스레드에서 Navier-Stokes 방정식의 수치 해석을
       5~10초 주기로 수행하여 정밀 예측 맵 P_slow를 산출한다.

(S106) P_slow 산출 완료 시, LSTM 모델의 가중치를 온라인 보정한다:
       Loss = MSE(P_fast, P_slow)
       LSTM_weights ← LSTM_weights - lr × ∇Loss
       여기서 lr = 0.001이다.
```

**이중 경로 병합:**
```
(S107) 현재 사이클에서 P_slow가 갱신되지 않았으면,
       예측 출력 P_out = P_fast로 설정한다.
       P_slow가 갱신되었으면,
       P_out = β × P_fast + (1-β) × P_slow로 설정한다.
       여기서 β는 P_slow의 경과 시간에 비례하여
       β = min(1.0, elapsed / T_slow)이고,
       T_slow는 Slow Path 주기(초)이다.
       즉, P_slow가 오래될수록 P_fast의 비중이 증가한다.
```

#### 단계 S200: 이중 버퍼 데이터 교환

```
(S201) 예측 엔진은 P_out과 ts_pred를 이중 버퍼의 Buffer A에 기록한다.
       이때 행동 엔진과 결정 엔진은 Buffer B를 읽고 있다.

(S202) 기록 완료 후, 버퍼 포인터를 원자적(atomic)으로 교환한다:
       swap(Buffer_A_ptr, Buffer_B_ptr)
       이 교환은 lock-free 방식으로 수행되어 대기 시간이 0이다.

(S203) 행동 엔진은 교환된 버퍼(이전 Buffer A, 현재 Buffer B)로부터
       P_out과 ts_pred를 읽는다.
```

#### 단계 S300: 행동 분석 (Behavior Engine)

```
(S301) WiFi 위치추적 모듈로부터 전체 N명의 위치 좌표를 수신한다.
       Positions = {(x₁,y₁,z₁), ..., (xₙ,yₙ,zₙ)}

(S302) 공간 분할 그리드에 각 인원을 할당한다.
       그리드 셀 크기: 5m × 5m
       셀 (i,j)에 할당된 인원 집합: Cell(i,j)
       이 단계에서 KDE 연산의 복잡도가 O(N²)에서
       O(N × k)로 감소한다. (k: 인접 셀 수, 최대 9)

(S303) 각 셀에 대해 KDE 밀집도를 산출한다.
       D(i,j) = |Cell(i,j)| / Area(i,j)

(S304) Social Force Model로 각 에이전트의 합력을 계산한다.
       이때 P_out에서 제공된 화재 위치를 F_fire 항에 반영한다.
       F_fire(agent_a) = C × exp(-d(agent_a, fire) / R) × n_af
       여기서 C=5000N, R=20m이다.

(S305) 밀집도 맵 D_out과 유형별 속도 맵 V_out을 산출한다.
       시간 스탬프 ts_behav = t를 부여한다.
       산출 소요 시간: 30ms 이내 (N=6000 기준).

(S306) D_out, V_out을 이중 버퍼를 통해 결정 엔진에 전달한다.
       (S201~S203과 동일한 이중 버퍼 교환 방식)
```

#### 단계 S400: 경로 결정 (Decision Engine)

```
(S401) P_out(예측), D_out(밀집도)를 이중 버퍼로부터 수신한다.

(S402) 시간 스탬프 정합성을 검증한다:
       |ts_pred - ts_behav| ≤ Δt_max
       여기서 Δt_max = 200ms이다.
       초과 시 이전 사이클의 데이터를 보간하여 사용한다:
       P_interpolated = P_out(ts_pred) + (t - ts_pred) × ∂P/∂t

(S403) Dynamic Risk Map을 합성한다:
       R(x,y,t) = 0.35×F(x,y,t) + 0.30×S(x,y,t)
                 + 0.20×D(x,y,t) + 0.15×C(x,y)
       여기서 F, S는 P_out으로부터, D는 D_out으로부터,
       C는 BIM 내화등급 데이터로부터 각각 추출한다.

(S404) R(x,y,t)를 그래프 가중치로 변환한다:
       각 노드 n의 통과 비용 = base_cost(n) × (1 + γ × R(n))
       여기서 γ = 10.0 (위험도 증폭 계수)이다.

(S405) N명 각각에 대해 A* 경로 탐색을 수행한다.
       MinHeap 기반 우선순위 큐를 사용하며,
       탐색 범위를 현재 위치 반경 200m 이내로 제한한다.
       산출 소요 시간: 40ms 이내 (N=6000 기준).

(S406) 경로 결과를 각 대피자의 모바일 디바이스로 전송한다.
```

#### 단계 S500: 사이클 반복

```
(S501) S100~S400을 연속적으로 반복한다.
       1 사이클 = S100(15ms) + S200(0ms) + S300(30ms)
                 + S200(0ms) + S400(40ms) + S200(0ms)
               = 약 85ms (< 100ms)

(S502) 잔여 시간(15ms)은 다음 사이클의 S100 선행 실행에 할당한다.
       이를 통해 파이프라인 버블을 최소화한다.
```

### 3. 시간 스탬프 기반 정합성 보장

```
각 엔진의 출력 데이터에는 해당 데이터가 참조한
센서 입력의 시점을 나타내는 시간 스탬프가 부여된다.

결정 엔진은 경로 산출 직전에 두 입력의 시간 스탬프 차이를 검증한다:

if |ts_pred - ts_behav| > 200ms:
    # 데이터 불일치 → 선형 보간으로 보정
    ratio = (t_current - ts_old) / (ts_new - ts_old)
    Data_corrected = Data_old + ratio × (Data_new - Data_old)
else:
    # 정합성 확인 → 그대로 사용
    Data_corrected = Data_received
```

### 4. 장애 허용 (Fault Tolerance)

```
(a) 예측 엔진 장애 시:
    결정 엔진은 마지막 유효한 P_out을 사용하되,
    경과 시간에 따라 가중치를 감쇄한다:
    P_fallback = P_last × exp(-elapsed / τ_decay)
    여기서 τ_decay = 5초이다.

(b) 행동 엔진 장애 시:
    군중 밀집도를 균일 분포로 가정한다:
    D_fallback(x,y) = N_total / Total_Area

(c) 네트워크 단절 시:
    각 데크/층의 엣지 서버가 해당 구역에 대해
    독립적으로 S100~S400을 실행한다.
    이 경우 구역 간 경계의 경로 연속성은
    인접 엣지 서버 간 P2P 통신으로 보장한다.
```

## 청구범위

**[청구항 1]**
화재 대피 시스템에서 개인별 대피 경로를 생성하는 방법에 있어서,
(a) 예측 엔진이 IoT 센서 데이터를 LSTM 네트워크에 입력하여 미래 시점의 공간별 위험도 예측 맵을 15ms 이내에 산출하는 단계;
(b) 상기 예측 맵을 이중 버퍼의 제1 버퍼에 기록하고, 버퍼 포인터를 원자적으로 교환하는 단계;
(c) 행동 엔진이 교환된 버퍼로부터 예측 맵을 읽고, WiFi 위치추적 데이터와 결합하여 구역별 밀집도 맵을 30ms 이내에 산출하는 단계;
(d) 상기 밀집도 맵을 이중 버퍼를 통해 결정 엔진에 전달하는 단계;
(e) 결정 엔진이 상기 예측 맵과 밀집도 맵의 시간 스탬프 차이가 소정 임계값(200ms) 이내인지 검증하는 단계;
(f) 검증된 데이터를 가중합하여 동적 위험지도를 합성하고, 이를 그래프 가중치로 변환하여 N명 각각에 대한 최적 경로를 40ms 이내에 산출하는 단계;
를 포함하며, 상기 (a)~(f) 단계의 전체 사이클 시간이 100ms 이내인 것을 특징으로 하는 AI 기반 실시간 대피 경로 생성 방법.

**[청구항 2]**
제1항에 있어서,
상기 예측 엔진은 LSTM에 의한 Fast Path와 CFD에 의한 Slow Path를 병행 실행하고, Slow Path 결과로 LSTM 가중치를 온라인 보정하며, 두 경로의 출력을 Slow Path의 경과 시간에 반비례하는 가중치로 병합하는 것을 특징으로 하는 방법.

**[청구항 3]**
제1항에 있어서,
상기 행동 엔진은 N명의 위치를 5m×5m 공간 분할 그리드에 할당하여 KDE 연산 복잡도를 O(N²)에서 O(N×k)로 감소시키는 것을 특징으로 하는 방법(여기서 k는 인접 셀 수).

**[청구항 4]**
제1항에 있어서,
상기 시간 스탬프 차이가 소정 임계값을 초과하는 경우, 이전 사이클의 데이터와 현재 사이클의 데이터를 선형 보간하여 보정 데이터를 생성하는 단계를 더 포함하는 것을 특징으로 하는 방법.

**[청구항 5]**
제1항 내지 제4항 중 어느 한 항의 방법을 실행하기 위한 프로그램이 기록된 컴퓨터 판독 가능 기록매체.

**[청구항 6]**
예측 엔진, 행동 엔진, 결정 엔진 및 동기 버스를 포함하는 AI 기반 실시간 대피 경로 생성 시스템에 있어서,
상기 동기 버스는 이중 버퍼 메모리와 시간 스탬프 레지스터를 포함하고,
상기 세 엔진은 상기 동기 버스를 통해 lock-free 방식으로 데이터를 교환하며,
전체 파이프라인 사이클 시간이 100ms 이내인 것을 특징으로 하는 시스템.

## 발명의 효과

1. 이질적 계산 특성을 갖는 세 엔진을 100ms 이내로 동기 연동함으로써, 초단위로 변하는 화재 상황에서 실시간 경로 갱신이 가능하다.
2. 이중 버퍼링에 의해 엔진 간 대기 시간(lock contention)이 0이 되어 파이프라인 효율이 극대화된다.
3. 시간 스탬프 기반 정합성 검증에 의해, 엔진 간 처리 속도 차이로 인한 데이터 불일치가 방지된다.
4. Dual-Path(Fast/Slow) 예측 구조에 의해, 실시간성(LSTM)과 정밀도(CFD)를 동시에 확보한다.
5. 장애 허용 설계에 의해, 단일 엔진 장애 시에도 감쇄된 품질로 대피 안내를 지속한다.
