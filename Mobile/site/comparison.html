왜 스마트폰 우선으로 전환했는가

v2.0의 핵심 주장이 코드와 불일치했고, 하드웨어 진입장벽이 5~10년이었습니다.
“시설에 설치하지 않고, 이미 있는 폰을 활용한다” — 이 한 줄이 모든 것을 바꿨습니다.
TAM 11.5배 확대, 진입 6~12개월, 데이터 밀도 56배, 그리고 정직 모드.

왜 피벗했는가

5대 사유 — 코드 정직성과 시장 현실 사이의 거리

v2.0은 학술적으로 깊고 디자인은 훌륭했지만, AI 챔피언 심사 기준과 실제 코드 사이에 큰 격차가 있었습니다. v3.0은 그 격차를 정직하게 메꾼 결과물입니다.

사유 01

코드와 마케팅 주장의 불일치

v2.0이 내세운 “3개 AI 엔진 실시간 작동·0.5초 재계산·WiFi 2~3m 측위”는 실제 코드 0줄. 명칭만 있는 마케팅이었습니다.

신경망·RL·측위 = 미구현
사유 02

하드웨어 진입장벽 = 5~10년

크루즈 1척 설치비 $1.1~1.7M, 드라이독 14~30일, 선급 재인증 1~2년. 시연조차 거의 불가능한 비현실 모델.

설치비 $1.5M · 인증 2년
사유 03

시장 협소 — 크루즈 30척/년 한정

크루즈 신조 시장 전체가 연 30척. SAM은 $18B에 멈췄고, 1척 영업이 1년~2년 단위였습니다.

전 세계 신조 30척/년
사유 04

이미 있는 폰 = 56배 데이터 밀도

4,000명 × 폰 7센서 = 28,000+ 데이터 포인트. IoT 500개 대비 56배. 후각·시각·판단력까지 갖춘 분산 인간센서.

28,000 vs 500 = ×56
사유 05

SaaS 전환으로 TAM 11.5배

Capex 모델($18B SAM)에서 SaaS 모델($208B TAM)로 확대. WiFi 보유 모든 공간 = 모든 시설이 대상.

$18B → $208B (×11.5)

6개 결정적 차이 — 왜 v3.0이 이기는가

v2.0 · 설치 비용

$1.5M / 시설 (Capex)

전용 IoT 500개 + 비콘 + 게이트웨이 + 서버 + 설치 인건비 + 선급 재인증 비용. 1회성 청구가 가능한 클라이언트가 극소수.

v3.0 · 설치 비용

$50K / 시설 (SaaS 기본)

기존 WiFi 점검 + 앱 배포 + 1차 캘리브레이션. 95% 비용 절감으로 1순위 종합병원·호텔·빌딩 즉시 도입 가능.

v2.0 · 데이터 밀도

IoT 500개 (고정·단일 모달)

천장 설치형 열·연기 센서. 위치 고정 → 화재 확산 후 인지. 시각·후각 정보 없음. 군중 행동 직접 관측 불가.

v3.0 · 데이터 밀도

4,000명 × 7센서 = 28,000+ (이동·멀티모달)

가속도·자이로·GPS·WiFi·마이크·카메라·고도. 인접 거주자의 후각으로 30~120초 앞서 감지. 군중 흐름 실시간 관측.

v2.0 · 측위 정확도

전용 디바이스 2~3m (코드 0)

“WiFi 2~3m 측위 작동”이라 명시했으나 실제 측위 코드와 하드웨어 모두 0개. 마케팅 주장.

v3.0 · 측위 정확도

WiFi + IMU + Graph SLAM 1~3m 목표

기존 WiFi 신호 강도 + 폰 IMU + 4,000개 폰의 상호 보정(SLAM)으로 인프라프리 1~3m 목표. 패치 D 특허 출원.

v2.0 · 활성화 방식

앱 실행 필요 (패닉 시 실패)

거주자가 직접 앱을 열어야 위치·정보 수신 가능. 패닉 상태에서 앱 실행률은 평균 12~28% (NFPA 2022). 핵심 사용자가 가장 큰 위험에 노출.

v3.0 · 활성화 방식

SOLAS 음향 자동 트리거 (zero-touch)

표준 화재경보음 패턴(900Hz/1850Hz · T3 패턴)을 폰 마이크가 자동 감지 → 4,000대 동시 활성화. 사용자 행위 0건. 패치 A 특허.

v2.0 · 시장 진입

5~10년 (선급 인증 사이클)

1척 영업 → 설계 변경 → 드라이독 → 인증 → 운영 = 평균 18~36개월. 보수적인 선사는 더 길게 잡음.

v3.0 · 시장 진입

6~12개월 (앱 + SaaS)

WiFi 점검(2주) → 앱 배포(2주) → 캘리브레이션(2주) → 운영. 신축이 아닌 기존 시설에 즉시 도입 가능.

v2.0 · 도메인 확장

크루즈 신조 30척/년 한정

선급·SOLAS 규제로 특정 분야 외 확장 어려움. 비즈니스 다각화 경로 불명확.

v3.0 · 도메인 확장

WiFi 보유 모든 공간 — 7개 즉시 진입 가능

종합병원($25B) → 5성급 호텔($30B) → 초고층 빌딩($40B) → 학교·경기장·지하철·공항($113B). 코드 99% 재사용.

TAM 11.5배 확대

$18B → $208B · 도메인별 시장 규모

v2.0의 SAM은 크루즈 신조 시장에 한정됐습니다. v3.0은 WiFi 보유 모든 공간으로 확장 — TAM이 11.5배 늘어났습니다.

GTM 재정렬

진입 순서가 완전히 뒤집혔습니다

v2.0은 진입장벽이 가장 높은 크루즈를 1순위로 잡았습니다. v3.0은 가장 낮은 종합병원부터 시작 — 매출 회수 시기가 5년 빨라집니다.

❌ v2.0 진입 순서 (Capex 1순위 = 진입장벽 최고)

  1. 크루즈 신조 (Fincantieri 협의) 진입장벽 최고 · 18~36개월 영업
  2. 크루즈 개조 시장 드라이독 30일 필요
  3. 대형 여객선 선급 재인증 1~2년
  4. 호텔·리조트 B2B 전용 IoT 영업
  5. 병원·빌딩 신규 인프라 설치 필요

✅ v3.0 진입 순서 (SaaS 1순위 = 진입장벽 최저)

  1. 종합병원·요양시설 Q4 2026 · 6~12개월 영업
  2. 5성급 호텔·리조트 2027 Q2 · 글로벌 체인
  3. 초고층 빌딩 2027 Q4 · 부동산 운영사
  4. 학교·경기장·공연장 2028 Q1 · 교육부·KOLA
  5. 지하철·공항 2028 Q3 · 공공 입찰
  6. 크루즈 (장기) 2029~ · 선급 협의 병행

핵심 변화: 크루즈가 1순위에서 6순위(장기)로 격하됐지만 완전 폐기는 아닙니다. v3.0 시스템 성숙도가 충분해진 2029년 이후 선급(KR/DNV) 협력으로 진입 — v2.0 학술 자산이 이때 결정적 신뢰도를 제공합니다.

v2.0 자산의 v3.0 활용

버려지는 것은 없습니다

v3.0은 v2.0의 폐기가 아니라 진화입니다. 9개 수학 모델, 6유형 핸디캡 보호, 5건 알고리즘 특허, Canvas 시뮬레이션 — 모두 v3.0의 핵심 자산으로 이전됐습니다.

v2.0 자산 → v3.0 위치·확장 활용 방식
3개 AI 엔진 알고리즘 (Prediction·Behavior·Decision) → Stage 5 라우터로 흡수 v3.0 Stage 5(화재맵+경로) 내부 모듈로 재배치. 마케팅 주장에서 실제 알고리즘 프로토타입으로 정직 모드 표현.
6유형 Health-Aware (α=2.0 안전 마진) → 30유형으로 확대 (6 카테고리) 신체·거동·부상·감각·인지·언어 6개 카테고리로 정밀 분류. α=2.0 알고리즘은 그대로 유지하면서 적용 대상 확장.
9개 수학 모델 (A*·Beer-Lambert·Greenshields 등) → 13개로 확대 (+4 신규) 기존 9개 + Bayesian Fusion · Acoustic Pattern Match · Graph SLAM · Kalman Fusion 4종 추가.
5건 알고리즘 특허 (PAT-01~05) → 9건 이중 방어 (+v3-P-A~D) 알고리즘 5건은 그대로 유지. 시스템 특허 4건 신규 추가 — 경쟁사는 두 영역 모두 회피해야 모방 가능.
Canvas 2D 시뮬레이션 페이지 3종 → PoC 데모 베이스 + Stage 5 시연용 simulation.html은 v3.0 Stage 5 라우터 시연으로 그대로 작동. d-insurance-risk-model.html은 보험사 협상 자료로 유지.
럭셔리 디자인 시스템 (Bordeaux × Navy × Gold) → 전체 v3.0 사이트에 일관 적용 theme.css의 컬러 팔레트와 타이포그래피는 v2.0에서 검증된 자산. v3.0 사이트 전체에서 그대로 사용 중.
학술 자료 (total_firenavi.md 등) → 선사·보험사 협상 자료로 보존 선사·학계·보험사는 v2.0 학술 깊이를, 시설 운영자·투자자는 v3.0 즉시 도입성을 — 청중별 자료 매핑.
“v3.0은 v2.0의 폐기가 아닌 진화입니다. v2.0 자산은 학술적 신뢰도를 제공하고, v3.0 자산은 즉시 시장 진입을 가능하게 합니다. 두 자산을 함께 가진 점이 FireNavi의 진짜 경쟁력입니다.” — PIVOT_v2_to_v3.md, FireNavi Strategy Note
정직 모드 표현 가이드

무엇을 폐기·대체했는가

AI 챔피언 심사는 정직성을 평가합니다. v2.0의 마케팅 과장을 코드가 뒷받침하는 표현으로 교체했습니다. 이 자기 점검 자체가 신뢰도를 높입니다.

“0.5초마다 6,000명 재계산”
→
“5초마다 화재맵 갱신 + 변경 시 개인 경로 즉시 보정”
이유: 실제 측정 1~2.5초/명. 6,000명 동시 처리 코드 미구현. 5초 화재맵 + 트리거 기반 개인 경로 보정이 실제 작동 방식.
“WiFi 2~3m 측위 작동”
→
“WiFi+IMU+SLAM 1~3m 목표, 인프라프리”
이유: v2.0 시점 측위 코드와 비콘 하드웨어 모두 0개. v3.0에서 인프라프리 측위로 재설계, 패치 D 특허 출원.
“3개 AI 엔진 실시간 작동”
→
“3개 AI 엔진 알고리즘 프로토타입 + ML 모델 통합 예정”
이유: 신경망·RL 코드 0줄. 알고리즘 조합은 작동하지만 “AI 엔진” 명칭은 마케팅 과장. 프로덕션 단계 ML 통합을 별도 표시.
“$230K 하드웨어 · ROI 2,466배”
→
“$50K 기본 + 옵션 확장 · ROI 3~6개월 회수”
이유: 실제 v2.0 총비용은 인증·드라이독 포함 $1.1~1.7M. ROI 2,466배는 비현실적 계산. v3.0은 SaaS로 ROI를 시간 기반(3~6개월)으로 재정의.
“Fincantieri 협력 협의 중”
→
“선급(KR/DNV)·조선소 협력 의사 타진”
이유: 공식 협약 없음. 사실 그대로 “의사 타진” 단계로 표현. 과장 → 사실 기반으로 교체.
“IoT 500개 = 충분한 데이터”
