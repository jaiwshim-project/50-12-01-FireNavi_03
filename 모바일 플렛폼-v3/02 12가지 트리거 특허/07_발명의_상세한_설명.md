### 2.2 스마트폰 센서 수집 모듈 (110)

#### 2.2.1 마이크 신호 처리 (111)

마이크 신호 처리부(111)는 다음의 알고리즘을 수행한다.

**[알고리즘 1: 화재경보음 패턴 인식]**

```
입력: 마이크 원시 음향 신호 s(t)
출력: 화재경보음 감지 여부 (True/False)

1. FFT 변환: S(f) = FFT(s(t))
2. 주파수 피크 검출: peaks = findPeaks(S(f))
3. 화재경보 주파수 매칭:
   if (2800Hz ≤ peaks[0] ≤ 3200Hz) AND (펄스 간격 0.4~0.6초):
      return True
   else:
      return False
```

**[알고리즘 2: 비상 음성 키워드 인식]**

```
입력: 마이크 음향 신호
출력: 비상 키워드 감지 여부 + 키워드 종류

1. STT (Speech-to-Text) 엔진 적용: text = STT(audio)
2. 비상 키워드 리스트와 매칭:
   keywords = ["불", "연기", "대피", "위험", "도와주세요", 
               "Fire", "Smoke", "Help", "Evacuate", "Emergency"]
   if any(keyword in text for keyword in keywords):
      return True, matched_keyword
   else:
      return False, None
```

**[알고리즘 3: 비명·폭발음 패턴 인식]**

```
입력: 마이크 음향 신호 s(t)
출력: 비명/폭발음 감지 여부

1. 음압 변화율 계산: dP/dt = diff(s(t)) / dt
2. 고주파 성분 추출: HF = highPassFilter(s(t), cutoff=2000Hz)
3. 판정:
   if (|dP/dt| > threshold_1) AND (energy(HF) > threshold_2):
      return True
   else:
      return False
```

#### 2.2.2 가속도계·자이로센서 신호 처리 (112)

**[알고리즘 4: 급진동·충격 감지]**

```
입력: 가속도계 3축 데이터 a(t) = [ax, ay, az]
출력: 충격 이벤트 감지 여부

1. 가속도 크기 계산: |a| = sqrt(ax² + ay² + az²)
2. 중력 가속도 제거: |a'| = |a| - 9.8
3. 판정:
   if |a'| > 3G (약 29.4 m/s²):
      return True, "충격"
   else:
      return False
```

**[알고리즘 5: 낙상 감지]**

```
입력: 가속도계 a(t), 자이로센서 ω(t)
출력: 낙상 이벤트 감지 여부

1. 급격한 가속도 변화 감지: 
   if |a(t)| > 2G:
      flag_1 = True
2. 자이로 회전 감지:
   if |ω(t)| > 150°/s:
      flag_2 = True
3. 이후 무이동 감지 (2초간):
   if variance(a(t+1s ~ t+3s)) < 0.1:
      flag_3 = True
4. 판정:
   if flag_1 AND flag_2 AND flag_3:
      return True
   else:
      return False
```

#### 2.2.3 조도센서 신호 처리 (113)

**[알고리즘 6: 조도 급감 감지]**

```
입력: 조도센서 데이터 L(t) (단위: lux)
출력: 조도 급감 이벤트 감지 여부

1. 기준 조도 설정: L_base = avg(L(t-10s ~ t))
2. 현재 조도: L_current = L(t)
3. 판정:
   if (L_base > 200 lux) AND (L_current < 50 lux):
      return True, "조도 급감"
   else:
      return False
```

#### 2.2.4 WiFi/BLE 신호 처리 (114)

**[알고리즘 7: WiFi AP 신호 이상 감지]**

```
입력: WiFi AP RSSI 리스트 rssi_list(t)
출력: WiFi 신호 이상 여부

1. 기준 RSSI 계산: rssi_base = avg(rssi_list(t-30s ~ t))
2. 현재 RSSI 변화율: Δrssi = rssi_list(t) - rssi_base
3. 판정:
   if (|Δrssi| > 20 dBm) OR (AP 접속 불가) OR (AP 리스트 50% 이상 변화):
      return True, "WiFi 신호 이상"
   else:
      return False
```

## 3. 재난 이벤트 온톨로지 매핑부 (200)

### 3.1 온톨로지 구조

재난 이벤트 온톨로지는 다음과 같은 클래스 계층 구조를 가진다.

```
DisasterEvent (재난 이벤트) [최상위 클래스]
│
├─ Fire (화재)
│  ├─ 속성: location, intensity, timestamp
│  └─ 관계: causes → Smoke, triggers → Evacuation
│
├─ Smoke (연기)
│  ├─ 속성: density, spread_rate, visibility
│  └─ 관계: causes → VisibilityLoss, blocks → Exit
│
├─ Explosion (폭발)
│  ├─ 속성: magnitude, location
│  └─ 관계: causes → StructureDamage, triggers → Panic
│
├─ Panic (패닉)
│  ├─ 속성: crowd_density, movement_pattern
│  └─ 관계: causes → Congestion, increases → InjuryRisk
│
├─ Congestion (혼잡)
│  ├─ 속성: density, bottleneck_location
│  └─ 관계: blocks → Exit, increases → EvacuationTime
│
├─ PowerFailure (정전)
│  ├─ 속성: affected_area, duration
│  └─ 관계: causes → VisibilityLoss, disables → Elevator
│
├─ ExitClosure (출구 폐쇄)
│  ├─ 속성: exit_id, closure_reason
│  └─ 관계: blocks → EvacuationRoute
│
├─ Fall (낙상)
│  ├─ 속성: user_id, location
│  └─ 관계: causes → Injury, requires → Rescue
│
├─ NoResponse (미응답)
│  ├─ 속성: user_id, last_location, duration
│  └─ 관계: indicates → Injury, requires → Rescue
│
├─ FacilityAlarm (설비 경보)
│  ├─ 속성: facility_type, alarm_type
│  └─ 관계: confirms → Fire/Smoke
│
└─ ManualEmergency (운영자 비상 명령)
   ├─ 속성: operator_id, command_type
   └─ 관계: overrides → AllAutomaticDecisions
```

### 3.3 추론 규칙

온톨로지 추론 엔진은 다음의 규칙을 적용한다.

**규칙 1: 화재 → 연기 예측**
```
IF Fire 노드 활성화 (신뢰도 > 0.7)
THEN Smoke 노드 활성화 (예상 시간: t+30s, 신뢰도 0.6)
```

**규칙 2: 연기 + 정전 → 시야 차단**
```
IF (Smoke 노드 활성화) AND (PowerFailure 노드 활성화)
THEN VisibilityLoss 위험도 = 0.9
```

**규칙 3: 패닉 + 혼잡 → 압사 위험**
```
IF (Panic 노드 활성화) AND (Congestion 노드 밀도 > 5명/m²)
THEN CrushRisk 위험도 = 0.8
```

**규칙 4: 낙상 + 미응답 → 부상자 의심**
```
IF (Fall 노드 활성화) AND (NoResponse 노드 활성화)
THEN InjurySuspected = True, RescuePriority +0.3
```

## 4. 신뢰도 점수 산출부 (300)

### 4.1 신뢰도 점수 함수 상세

**DCS(E, t) = w₁·I + w₂·F + w₃·T + w₄·S + w₅·M + w₆·V + w₇·H**

각 인자의 정의 및 산출 방법:

#### 4.1.1 신호 강도 (I)

**신호 강도**는 신호의 물리적 크기를 나타낸다.

- 음향 신호: 음압 레벨 (dB)
- 가속도 신호: 가속도 크기 (G)
- 조도 신호: 조도 변화량 (lux)

**정규화:** I = (신호 크기 - 최소값) / (최대값 - 최소값)  
**범위:** 0 ≤ I ≤ 1

#### 4.1.2 발생 빈도 (F)

**발생 빈도**는 일정 시간 창(예: 60초) 내 신호 발생 횟수이다.

**F = min(1.0, N_occurrences / N_threshold)**

- N_occurrences: 60초 내 신호 발생 횟수
- N_threshold: 기준 횟수 (예: 5회)

#### 4.1.3 시간적 연속성 (T)

**시간적 연속성**은 신호가 연속적으로 유지되는 시간이다.

**T = min(1.0, duration / duration_threshold)**

- duration: 신호 지속 시간 (초)
- duration_threshold: 기준 시간 (예: 30초)

#### 4.1.4 공간적 근접성 (S)

**공간적 근접성**은 인접 위치에서 유사 신호가 발생했는지 여부이다.

```
adjacent_locations = findAdjacentLocations(current_location, radius=10m)
for loc in adjacent_locations:
    if similarSignalExists(loc, signal_type):
        S += 0.2
S = min(1.0, S)
```

#### 4.1.5 다수 단말 일치성 (M)

**다수 단말 일치성**은 동일 구역 내 복수 단말에서 유사 신호가 발생했는지 여부이다.

**M = min(1.0, N_matched / N_threshold)**

- N_matched: 동일 구역 내 유사 신호 감지 단말 수
- N_threshold: 기준 단말 수 (예: 3대)

**예시:**
- 구역 A 내 10대 단말 존재
- 그 중 7대가 "비명" 신호 감지
- M = min(1.0, 7 / 3) = 1.0 (최고 신뢰도)

#### 4.1.6 교차검증 (V)

**교차검증**은 스마트폰 센서 신호와 시설 설비 신호의 일치 여부이다.

| 상황 | V 값 |
|------|------|
| 스마트폰 + 설비 신호 일치 | 1.0 |
| 설비 신호만 존재 | 0.8 |
| 스마트폰 신호만 존재 | 0.5 |
| 신호 없음 | 0.0 |

#### 4.1.7 신고 이력 신뢰도 (H)

**신고 이력 신뢰도**는 사용자의 과거 신고 이력을 반영한다.

**H = 1.0 - (허위 신고 횟수 / 총 신고 횟수)**

- 신규 사용자: H = 0.7 (기본값)
- 허위 신고 0회: H = 1.0
- 허위 신고 3회 / 총 10회: H = 0.7

### 4.2 가중치 설정

가중치는 재난 유형 및 신호원에 따라 동적으로 조정된다.

| 인자 | 화재 | 패닉 | 정전 |
|------|------|------|------|
| w₁ (신호 강도) | 0.20 | 0.15 | 0.15 |
| w₂ (발생 빈도) | 0.15 | 0.20 | 0.10 |
| w₃ (시간 연속성) | 0.15 | 0.10 | 0.15 |
| w₄ (공간 근접성) | 0.10 | 0.15 | 0.10 |
| w₅ (다수 단말 일치성) | 0.20 | 0.25 | 0.20 |
| w₆ (교차검증) | 0.15 | 0.10 | 0.25 |
| w₇ (신고 이력) | 0.05 | 0.05 | 0.05 |
| **합계** | 1.00 | 1.00 | 1.00 |

### 4.3 신뢰도 점수 산출 예시

**예시 1: 크루즈선 객실 화재**

수집된 신호:
- 화재경보음 (마이크): 신호 강도 0.9
- 조도 급감 (조도센서): 신호 강도 0.8
- 사용자 SOS 신고 (1명)
- 인접 객실 3개에서 유사 신호 발생
- 화재감지기 경보 (설비)

신뢰도 점수 산출:
- I = 0.9 (화재경보음 강도)
- F = 0.6 (60초 내 3회 발생)
- T = 0.8 (24초간 지속)
- S = 1.0 (인접 객실 3곳에서 유사 신호)
- M = 1.0 (동일 구역 내 4개 단말 일치)
- V = 1.0 (스마트폰 + 설비 신호 일치)
- H = 0.8 (사용자 신고 이력)

**DCS(Fire, t) = 0.20×0.9 + 0.15×0.6 + 0.15×0.8 + 0.10×1.0 + 0.20×1.0 + 0.15×1.0 + 0.05×0.8**  
**= 0.18 + 0.09 + 0.12 + 0.10 + 0.20 + 0.15 + 0.04 = 0.88**

→ **대피 모드** (0.7 ≤ DCS < 0.9)

## 5. 재난 모드 결정부 (400)

### 5.1 모드 결정 알고리즘

```python
def determineDisasterMode(DCS, has_no_response):
    if DCS < 0.3:
        return "정상 모드"
    elif 0.3 <= DCS < 0.5:
        return "주의 모드"
    elif 0.5 <= DCS < 0.7:
        return "확인 모드"
    elif 0.7 <= DCS < 0.9:
        return "대피 모드"
    elif DCS >= 0.9:
        if has_no_response:
            return "구조 모드"
        else:
            return "대피 모드"
```

### 5.2 모드별 동작 상세

#### 5.2.1 주의 모드 (Attention Mode)

**트리거 조건:** 0.3 ≤ DCS < 0.5

**시스템 동작:**
1. 사용자 단말에 경고 아이콘 표시 (화면 상단 알림 바)
2. 센서 샘플링 주기 증가: 10초 → 5초
3. 배경 모니터링 강화: 추가 신호 수집 대기
4. 관제센터에 주의 알림 전송 (우선순위: 낮음)

**사용자 인터페이스:**
- 화면 상단 노란색 경고 아이콘
- 알림 메시지: "주변 상황을 주의 깊게 살펴주세요"

#### 5.2.2 확인 모드 (Confirmation Mode)

**트리거 조건:** 0.5 ≤ DCS < 0.7

**시스템 동작:**
1. 전체 화면 마이크로 설문 팝업 표시
2. 사용자 응답 대기 (제한 시간: 30초)
3. 응답에 따라 신뢰도 점수 보정
4. 무응답 시 자동 대피 모드 전환

**마이크로 설문 예시:**

#### 5.2.3 대피 모드 (Evacuation Mode)

**트리거 조건:** 0.7 ≤ DCS < 0.9

**시스템 동작:**
1. 개인별 대피 경로 화면 전체에 표시
2. 위험 구역 회피 경로 자동 생성
3. 다중 안내 (진동 + 음성 + 시각)
4. 관제센터에 대피 시작 알림
5. 실시간 경로 갱신 (5초 주기)

**사용자 인터페이스:**

#### 5.2.4 구조 모드 (Rescue Mode)

**트리거 조건:** DCS ≥ 0.9 **+** 미응답자 존재

**시스템 동작:**
1. 미응답자·무이동자·취약계층·부상 의심자 자동 분류
2. 구조 우선순위 자동 산정
3. 관제센터 및 구조대 단말에 실시간 정보 전송

5. 구조 완료 시까지 실시간 위치 추적

## 6. 대피 연동부 (500)

### 6.1 위험지도 생성부 (510)

**위험도 함수:**

**R(x, y, t) = max(DCS_Fire(x,y,t), DCS_Smoke(x,y,t), DCS_Congestion(x,y,t))**

**색상 코드:**
- 🟢 녹색 (R < 0.3): 안전
- 🟡 노란색 (0.3 ≤ R < 0.5): 주의
- 🟠 주황색 (0.5 ≤ R < 0.7): 경고
- 🔴 빨간색 (R ≥ 0.7): 위험

**갱신 주기:** 5초

### 6.2 개인별 경로 추천부 (520)

**경로 탐색 알고리즘 (수정 A*):**

```python
def findOptimalEvacuationRoute(user_location, user_profile, risk_map):
    # 비용 함수
    def cost(node):
        distance = euclideanDistance(current_node, node)
        risk = risk_map.getRisk(node.x, node.y, current_time)
        congestion = getCongestion(node.x, node.y)
        
        # 취약계층 가중치
        if user_profile.is_vulnerable:
            risk_weight = 2.0  # 취약계층은 위험 회피 강화
        else:
            risk_weight = 1.0
        
        return distance + risk_weight * risk + 0.5 * congestion
    
    # A* 알고리즘 실행
    path = astar_search(user_location, nearest_safe_exit, cost_function=cost)
    
    # 대체 경로 생성
    alternative_paths = []
    for exit in safe_exits:
        alt_path = astar_search(user_location, exit, cost_function=cost)
        alternative_paths.append(alt_path)
    
    return path, alternative_paths
```

**취약계층별 경로 차별화:**

| 취약계층 유형 | 경로 우선순위 |
|---------------|---------------|
| 휠체어 사용자 | 경사로 > 엘리베이터 > 계단 (최후) |
| 시각장애인 | 직선 경로 > 단순 구조 |
| 고령자 | 계단 최소화 > 휴식 지점 경유 |
| 어린이 | 보호자 동기화 > 최단 경로 |
| 임산부 | 이동 거리 최소화 > 급경사 회피 |

### 6.3 관제센터 연동부 (530)

**전송 정보:**

1. **재난 발생 정보**
   - 위치: (x, y, z)
   - 재난 유형: Fire / Smoke / Panic 등
   - 신뢰도 점수: DCS
   - 발생 시간: timestamp

2. **사용자 분포**
   - 층별 인원 수: {1층: 50명, 2층: 30명, 3층: 20명}
   - 구역별 밀집도: {구역 A: 5명/m², 구역 B: 2명/m²}

3. **미응답자 위치**
   - 미응답자 목록: [{user_id, location, duration}, ...]
   - 실시간 업데이트 (5초 주기)

4. **대피 진행 상황**
   - 대피 완료율: 60%
   - 남은 인원: 40명
   - 예상 완료 시간: 5분 30초

### 6.4 구조대 연계부 (540)

**구조 우선순위 산정:**

**RPS = w₁·R(x, y, t) + w₂·V + w₃·T_no_response**

- **R(x, y, t)**: 구조 대상 위치의 위험도 (0~1)
- **V**: 취약계층 가중치 (일반: 0.5, 고령자: 0.8, 휠체어: 1.0)
- **T_no_response**: 미응답 지속 시간 (분 단위, 정규화: min/10)
- **w₁, w₂, w₃**: 가중치 (0.5, 0.3, 0.2)

**예시:**
- 휠체어 사용자: R=0.9, V=1.0, T=2.5분 → RPS = 0.5×0.9 + 0.3×1.0 + 0.2×0.25 = 0.8 (최우선)
- 일반 성인: R=0.7, V=0.5, T=1.0분 → RPS = 0.5×0.7 + 0.3×0.5 + 0.2×0.1 = 0.52 (2순위)

- **데이터 암호화**: AES-256 (저장), TLS 1.3 (전송)
- **접근 제어**: OAuth 2.0 (사용자 인증), RBAC (관제센터 권한)
- **프라이버시**: 위치 데이터는 재난 상황에서만 수집, 평상시 익명화
