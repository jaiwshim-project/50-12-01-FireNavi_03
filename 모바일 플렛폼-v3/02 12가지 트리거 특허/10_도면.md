# 도면 상세 설명

## 도면 번호 및 구조

본 특허출원에는 **총 10개의 도면**이 포함되며, 각 도면은 발명의 구성 및 동작을 명확히 설명하기 위한 것입니다.

---

## 도 1: 시스템 전체 구성도 (블록도) - 대표도

### 도면 번호
**도 1**

### 도면 종류
블록도 (Block Diagram)

### 목적
본 발명의 전체 시스템 구성을 한눈에 파악할 수 있도록 5개 주요 구성부와 3개 보조 구성부를 블록으로 표현

### 포함 요소 및 부호

#### 주요 구성부
- **100**: 다중 외부 자극 수집부
- **200**: 재난 이벤트 온톨로지 매핑부
- **300**: 신뢰도 점수 산출부
- **400**: 재난 모드 결정부
- **500**: 대피 연동부

#### 보조 구성부
- **600**: 통신부
- **700**: 데이터베이스
- **800**: 제어부

### 데이터 흐름
```
[100 다중 외부 자극 수집부]
    ↓ 외부 자극 신호
[200 재난 이벤트 온톨로지 매핑부]
    ↓ 의미 노드
[300 신뢰도 점수 산출부]
    ↓ 재난 신뢰도 점수 (DCS)
[400 재난 모드 결정부]
    ↓ 재난 모드 (주의/확인/대피/구조)
[500 대피 연동부]
    ↓ 위험지도, 경로, 알림
[600 통신부] → 사용자 단말, 관제센터, 구조대
```

### 블록 간 화살표
- 실선 화살표: 주요 데이터 흐름
- 점선 화살표: 피드백 또는 보조 데이터 흐름

### 도면 크기 및 레이아웃
- **크기**: A4 세로 (210mm × 297mm)
- **여백**: 상하좌우 25mm
- **블록 크기**: 60mm × 30mm (직사각형)
- **화살표 굵기**: 0.5mm
- **글자 크기**: 부호 12pt, 명칭 10pt

## 도 2: 다중 외부 자극 수집부(100) 세부 구성도

### 도면 번호
**도 2**

### 도면 종류
블록도 (Block Diagram)

### 목적
12종 트리거를 수집하는 다중 외부 자극 수집부(100)의 내부 구조를 상세히 표시

### 포함 요소 및 부호

#### 제1 계층: 수집부(100)
- **100**: 다중 외부 자극 수집부

#### 제2 계층: 하위 모듈
- **110**: 스마트폰 센서 수집 모듈
- **120**: 사용자 입력 수집 모듈
- **130**: 시설 설비 신호 수집 모듈
- **140**: 관제센터 신호 수집 모듈

#### 제3 계층: 세부 구성 요소
##### 스마트폰 센서 수집 모듈(110)
- **111**: 마이크 신호 처리부
  - 화재경보음 패턴 인식
  - 비상 음성 키워드 인식
  - 비명·폭발음 패턴 인식
- **112**: 가속도계·자이로센서 신호 처리부
  - 급진동·충격 감지
  - 낙상 감지
- **113**: 조도센서 신호 처리부
  - 조도 급감 감지
  - 비상등 점멸 패턴 감지
- **114**: WiFi/BLE 신호 처리부
  - WiFi AP 신호 이상 감지
  - BLE 비콘 신호 이상 감지

##### 사용자 입력 수집 모듈(120)
- **121**: SOS 신고 처리부
- **122**: 마이크로 설문 응답 처리부

##### 시설 설비 신호 수집 모듈(130)
- 화재감지기 신호
- 연기감지기 신호
- 스프링클러 신호
- 비상방송 신호

##### 관제센터 신호 수집 모듈(140)
- 운영자 비상 명령 수신

### 데이터 흐름
각 모듈에서 수집된 12종 트리거 신호는 다중 외부 자극 수집부(100) 출력으로 통합되어 온톨로지 매핑부(200)로 전송됨

### 도면 크기 및 레이아웃
- **크기**: A4 세로
- **레이아웃**: 계층형 트리 구조
- **블록 크기**: 
  - 제1 계층: 80mm × 30mm
  - 제2 계층: 60mm × 25mm
  - 제3 계층: 50mm × 20mm

## 도 3: 재난 이벤트 온톨로지 구조도

### 도면 번호
**도 3**

### 도면 종류
네트워크 그래프 (Network Graph) 또는 트리 구조도

### 목적
재난 이벤트 온톨로지의 계층 구조 및 노드 간 관계를 시각화

### 포함 요소 및 부호

#### 최상위 클래스
- **DisasterEvent**: 재난 이벤트 (최상위 클래스, 원형 노드)

#### 하위 노드 (의미 노드)
- **Fire**: 화재 (빨간색 원형 노드)
- **Smoke**: 연기 (회색 원형 노드)
- **Explosion**: 폭발 (주황색 원형 노드)
- **Panic**: 패닉 (노란색 원형 노드)
- **Congestion**: 혼잡 (파란색 원형 노드)
- **PowerFailure**: 정전 (검은색 원형 노드)
- **ExitClosure**: 출구 폐쇄 (갈색 원형 노드)
- **Fall**: 낙상 (보라색 원형 노드)
- **NoResponse**: 미응답 (회색 원형 노드)
- **FacilityAlarm**: 설비 경보 (초록색 원형 노드)
- **ManualEmergency**: 운영자 비상 명령 (빨간색 사각형 노드)

#### 노드 간 관계 (화살표)
- **Fire → causes → Smoke**: 화재는 연기를 발생시킴
- **Fire → triggers → Evacuation**: 화재는 대피를 촉발함
- **Smoke → causes → VisibilityLoss**: 연기는 시야 차단을 발생시킴
- **Smoke → blocks → Exit**: 연기는 출구를 차단함
- **Explosion → causes → StructureDamage**: 폭발은 구조물 손상을 발생시킴
- **Explosion → triggers → Panic**: 폭발은 패닉을 촉발함
- **Panic → causes → Congestion**: 패닉은 혼잡을 발생시킴
- **Panic → increases → InjuryRisk**: 패닉은 부상 위험을 증가시킴
- **Congestion → blocks → Exit**: 혼잡은 출구를 차단함
- **PowerFailure → causes → VisibilityLoss**: 정전은 시야 차단을 발생시킴
- **Fall → causes → Injury**: 낙상은 부상을 발생시킴
- **Fall → requires → Rescue**: 낙상은 구조를 필요로 함
- **NoResponse → indicates → Injury**: 미응답은 부상을 암시함

### 표현 방식
- 노드: 원형 또는 사각형 (색상 구분)
- 화살표: 실선 화살표 (관계 유형 라벨 표시)
- 라벨: "causes", "triggers", "blocks", "increases", "requires", "indicates"

### 도면 크기 및 레이아웃
- **크기**: A4 가로 (297mm × 210mm) 권장
- **레이아웃**: 중앙에 DisasterEvent, 주변에 하위 노드 방사형 배치
- **노드 크기**: 직경 25mm (원형)
- **화살표 굵기**: 0.3mm

## 도 4: 신뢰도 점수 산출 과정 흐름도

### 도면 번호
**도 4**

### 도면 종류
흐름도 (Flowchart)

### 목적
신뢰도 점수 산출 알고리즘의 단계별 처리 과정을 표현

### 포함 단계 및 부호

#### 입력
- **S310**: 외부 자극 신호 입력

#### 7가지 인자 산출
- **S320**: 신호 강도(I) 산출
- **S330**: 발생 빈도(F) 산출
- **S340**: 시간적 연속성(T) 산출
- **S350**: 공간적 근접성(S) 산출
- **S360**: 다수 단말 일치성(M) 산출
- **S370**: 교차검증(V) 산출
- **S380**: 신고 이력 신뢰도(H) 산출

#### 가중 합산
- **S390**: 가중 합산
  - **수식**: DCS = w₁·I + w₂·F + w₃·T + w₄·S + w₅·M + w₆·V + w₇·H

#### 출력
- **S395**: 재난 신뢰도 점수(DCS) 출력

### 흐름도 구조
```
┌─────────────┐
│ S310: 입력  │
└──────┬──────┘
       │
       ├─────┬─────┬─────┬─────┬─────┬─────┐
       │     │     │     │     │     │     │
   ┌───▼─┐ ┌─▼──┐ ┌─▼──┐ ┌─▼──┐ ┌─▼──┐ ┌─▼──┐ ┌─▼──┐
   │ I   │ │ F  │ │ T  │ │ S  │ │ M  │ │ V  │ │ H  │
   └───┬─┘ └─┬──┘ └─┬──┘ └─┬──┘ └─┬──┘ └─┬──┘ └─┬──┘
       │     │     │     │     │     │     │
       └─────┴─────┴─────┴─────┴─────┴─────┘
                       │
                  ┌────▼────┐
                  │S390:가중합산│
                  └────┬────┘
                       │
                  ┌────▼────┐
                  │S395:출력│
                  └─────────┘
```

### 도면 크기 및 레이아웃
- **크기**: A4 세로
- **레이아웃**: 상하 흐름
- **블록 크기**: 60mm × 20mm (직사각형)

## 도 5: 4단계 재난 모드 전환 상태 전이도

### 도면 번호
**도 5**

### 도면 종류
상태 전이도 (State Transition Diagram)

### 목적
재난 신뢰도 점수(DCS)에 따른 재난 모드 자동 전환 로직을 시각화

### 포함 상태 및 부호

#### 5개 상태 (원형 노드)
- **S1**: 정상 모드 (Normal Mode)
- **S2**: 주의 모드 (Attention Mode)
- **S3**: 확인 모드 (Confirmation Mode)
- **S4**: 대피 모드 (Evacuation Mode)
- **S5**: 구조 모드 (Rescue Mode)

### 상태 전이 조건 (화살표 + 라벨)

#### 상향 전환 (즉시)
- **S1 → S2**: DCS ≥ 0.3
- **S2 → S3**: DCS ≥ 0.5
- **S3 → S4**: DCS ≥ 0.7
- **S4 → S5**: DCS ≥ 0.9 **AND** 미응답자 존재

#### 하향 전환 (히스테리시스 2분)
- **S2 → S1**: DCS < 0.3 (2분 유지 후)
- **S3 → S2**: DCS < 0.5 (2분 유지 후)
- **S4 → S3**: DCS < 0.7 (2분 유지 후)
- **S5 → S4**: 구조 완료 (2분 유지 후)

### 상태별 동작 요약 (노드 내부 텍스트)
- **S1**: 정상 모니터링
- **S2**: 경고 아이콘 + 센서 샘플링 증가
- **S3**: 마이크로 설문 출력 + 사용자 응답 수집
- **S4**: 개인별 대피 경로 안내 + 위험지도 표시
- **S5**: 구조 대상 위치 전송 + 구조 우선순위 산정

### 표현 방식
- 상태: 원형 노드 (직경 40mm)
- 화살표: 실선 (상향 전환), 점선 (하향 전환)
- 조건: 화살표 위 라벨 표시

### 도면 크기 및 레이아웃
- **크기**: A4 가로
- **레이아웃**: 좌→우 흐름 (S1 → S2 → S3 → S4 → S5)

## 도 6: 대피 모드 사용자 인터페이스

### 도면 번호
**도 6**

### 도면 종류
화면 모형 (Screen Mockup)

### 목적
대피 모드(S4)에서 사용자가 스마트폰에서 보는 화면 예시를 시각화

### 화면 구성

#### 상단 (헤더)
- **아이콘**: 🚨 (빨간색)
- **제목**: "대피 지시"
- **배경색**: 빨간색 (RGB: 255, 0, 0)
- **글자색**: 흰색

#### 중앙 (위험지도)
```
┌─────────────────────┐
│   [위험지도]        │
│   🟢🟢🟢🟡🟡        │
│   🟢 👤 🟢🟡🔴      │  ← 현재 위치
│   🟢🟢➡️🟡🔴        │
│   🟢🟢🟢🟡🟡        │
└─────────────────────┘
```

- **색상 범례**:
  - 🟢 녹색: 안전 (R < 0.3)
  - 🟡 노란색: 주의 (0.3 ≤ R < 0.5)
  - 🟠 주황색: 경고 (0.5 ≤ R < 0.7)
  - 🔴 빨간색: 위험 (R ≥ 0.7)

- **현재 위치**: 👤 (파란색 원형 마커)
- **대피 경로**: ➡️ (파란색 화살표)

#### 하단 (안내 메시지)
- **텍스트**:
  - "현재 위치: 3층 복도"
  - "대피 경로: 3층 → 계단 B → 1층 출구 B"
  - "다음 지시: 오른쪽으로 20m 이동"
  - "예상 대피 시간: 2분 30초"

- **버튼**: [대체 경로 보기]
- **버튼 색상**: 파란색 (RGB: 0, 122, 255)

### 스마트폰 테두리
- **크기**: 가로 75mm × 세로 150mm
- **모서리**: 둥근 모서리 (반지름 10mm)
- **색상**: 검은색

### 도면 크기 및 레이아웃
- **크기**: A4 세로
- **레이아웃**: 중앙에 스마트폰 화면 배치

## 도 7: 위험지도 생성 예시

### 도면 번호
**도 7**

### 도면 종류
건물 평면도 + 색상 코드

### 목적
실시간 위험지도 생성 결과를 건물 평면도에 색상으로 표현

### 평면도 구성

#### 건물 정보
- **층**: 3층
- **구역**: A, B, C, D, E (5개 구역)
- **출구**: 출구 A, 출구 B (2개)

#### 구역별 색상 코드
```
┌──────────────────────────────┐
│  [3층 평면도]               │
│                              │
│  ┌───🟢───┬───🟡───┬───🔴───┐  │
│  │ 구역 A │ 구역 B │ 구역 C │  │
│  │(안전) │(주의) │(위험) │  │
│  │       │       │  🔥   │  │
│  └───────┴───────┴───────┘  │
│                              │
│  ┌───🟢───┬───🟠───┐          │
│  │ 구역 D │ 구역 E │          │
│  │(안전) │(경고) │          │
│  │ 👤   │       │          │
│  └───────┴───────┘          │
│                              │
│  🚪 출구 A        🚪 출구 B  │
└──────────────────────────────┘
```

- **구역 A**: 녹색 (R = 0.2, 안전)
- **구역 B**: 노란색 (R = 0.4, 주의)
- **구역 C**: 빨간색 (R = 0.9, 위험) - 🔥 화재 발생 지점
- **구역 D**: 녹색 (R = 0.1, 안전) - 👤 사용자 현재 위치
- **구역 E**: 주황색 (R = 0.6, 경고)

#### 화살표 (대피 경로)
- 구역 D (현재 위치) → 구역 A → 출구 A (파란색 화살표)

### 범례
```
┌────────────────┐
│ 범례           │
├────────────────┤
│ 🟢 안전        │
│ 🟡 주의        │
│ 🟠 경고        │
│ 🔴 위험        │
│ 🔥 화재 발생   │
│ 👤 현재 위치   │
│ 🚪 출구        │
└────────────────┘
```

### 도면 크기 및 레이아웃
- **크기**: A4 가로
- **레이아웃**: 좌측 평면도, 우측 범례

## 도 8: 구조 모드 구조대 단말 인터페이스

## 도 9: 전체 방법 흐름도

### 도면 번호
**도 9**

### 도면 종류
흐름도 (Flowchart)

### 목적
방법 청구항(청구항 21)에 대응하는 전체 프로세스를 단계별로 표현

### 포함 단계 및 부호

#### 주요 단계
- **S100**: 다중 외부 자극 수집 단계
  - 스마트폰 센서, 사용자 입력, 시설 설비, 관제센터 신호 수집

- **S200**: 온톨로지 매핑 단계
  - 외부 자극 신호 → 재난 이벤트 온톨로지 의미 노드 변환

- **S300**: 신뢰도 점수 산출 단계
  - I, F, T, S, M, V, H 인자 종합 → DCS 산출

- **S400**: 재난 모드 결정 단계
  - DCS에 따라 주의/확인/대피/구조 모드 결정

- **S500**: 대피 연동 단계
  - 위험지도 생성, 개인별 경로 추천, 관제센터 알림, 구조대 연계

- **S600**: 동적 갱신 단계
  - 5초 주기로 S100~S500 반복

## 도면 제작 가이드라인

### 1. 형식 요구사항
- **크기**: A4 용지 (210mm × 297mm)
- **여백**: 상하좌우 각 25mm 이상
- **선 굵기**: 0.3mm 이상 (명확한 인식 가능)
- **글자 크기**: 부호 12pt, 설명 10pt 이상
- **해상도**: 300dpi 이상 (디지털 제출 시)

### 2. 색상 사용
- **흑백 출력 가능**: 색상 사용 시 흑백에서도 구별 가능하도록 패턴 추가
- **색상 코드 범례**: 도면 하단에 범례 표시
- **예시**:
  - 🟢 녹색 (안전) → 흑백 시 연한 회색 + 점무늬
  - 🔴 빨간색 (위험) → 흑백 시 짙은 회색 + 사선무늬

### 3. 부호 표기 규칙
- **100 단위**: 주요 구성부
- **10 단위**: 하위 모듈
- **1 단위**: 세부 구성 요소
- **일관성**: 모든 도면에서 동일 부호 사용

### 4. 도면과 명세서 일치
- 도면의 모든 부호는 명세서 "부호의 설명"에 기재
- 명세서의 설명은 도면과 일치해야 함
- 도면 번호는 명세서 인용과 일치

### 5. 도면 제작 도구 권장
- **블록도/흐름도**: Microsoft Visio, Draw.io, Lucidchart
- **화면 모형**: Figma, Adobe XD, Sketch
- **평면도**: AutoCAD, SketchUp, PowerPoint
- **일반 도형**: Microsoft PowerPoint, Adobe Illustrator

다중 외부 자극 수집부(100)는 스마트폰 센서, 사용자 입력, 시설 설비, 및 관제센터로부터 12종의 외부 자극 신호를 수집하여 재난 이벤트 온톨로지 매핑부(200)로 전달한다. 재난 이벤트 온톨로지 매핑부(200)는 수집된 외부 자극 신호를 재난 이벤트 온톨로지의 의미 노드로 변환한다. 신뢰도 점수 산출부(300)는 7가지 인자(I, F, T, S, M, V, H)를 종합하여 재난 신뢰도 점수(DCS)를 산출한다. 재난 모드 결정부(400)는 산출된 DCS에 따라 정상(S1), 주의(S2), 확인(S3), 대피(S4), 구조(S5) 모드 중 하나를 결정한다. 대피 연동부(500)는 위험지도를 생성하고, 개인별 대피 경로를 추천하며, 관제센터 및 구조대와 연동한다.

### 도 2 설명문
**도 2는 도 1의 다중 외부 자극 수집부(100)의 세부 구성을 나타낸 블록도이다.**

도 2를 참조하면, 다중 외부 자극 수집부(100)는 스마트폰 센서 수집 모듈(110), 사용자 입력 수집 모듈(120), 시설 설비 신호 수집 모듈(130), 및 관제센터 신호 수집 모듈(140)을 포함한다.

스마트폰 센서 수집 모듈(110)은 마이크 신호 처리부(111), 가속도계·자이로센서 신호 처리부(112), 조도센서 신호 처리부(113), 및 WiFi/BLE 신호 처리부(114)를 포함한다. 마이크 신호 처리부(111)는 화재경보음, 비상 음성 키워드, 비명 및 폭발음을 감지한다. 가속도계·자이로센서 신호 처리부(112)는 급진동, 충격 및 낙상을 감지한다. 조도센서 신호 처리부(113)는 조도 급감 및 비상등 점멸 패턴을 감지한다. WiFi/BLE 신호 처리부(114)는 WiFi AP 및 BLE 비콘 신호의 이상을 감지한다.

사용자 입력 수집 모듈(120)은 SOS 신고 처리부(121) 및 마이크로 설문 응답 처리부(122)를 포함한다. 시설 설비 신호 수집 모듈(130)은 화재감지기, 연기감지기, 스프링클러, 및 비상방송 신호를 수집한다. 관제센터 신호 수집 모듈(140)은 운영자의 비상 명령을 수신한다.

### 도 3 설명문
**도 3은 본 발명에서 사용되는 재난 이벤트 온톨로지의 구조를 나타낸 네트워크 그래프이다.**

도 3을 참조하면, 재난 이벤트 온톨로지는 최상위 클래스인 DisasterEvent로부터 Fire(화재), Smoke(연기), Explosion(폭발), Panic(패닉), Congestion(혼잡), PowerFailure(정전), ExitClosure(출구 폐쇄), Fall(낙상), NoResponse(미응답), FacilityAlarm(설비 경보), ManualEmergency(운영자 비상 명령) 등의 의미 노드로 분기한다.

각 노드 간의 관계는 화살표로 표시되며, 예를 들어 Fire는 Smoke를 발생시키고(causes), Evacuation을 촉발(triggers)한다. Smoke는 시야 차단(VisibilityLoss)을 발생시키고, 출구를 차단(blocks)한다. Explosion은 구조물 손상(StructureDamage)을 발생시키고, Panic을 촉발한다. 이러한 온톨로지 구조를 통해 수집된 외부 자극 신호는 의미 있는 재난 이벤트로 변환되며, 재난의 인과관계 및 확산 경로를 추론할 수 있다.

### 도 4 설명문
**도 4는 본 발명에 따른 신뢰도 점수 산출 과정을 나타낸 흐름도이다.**

도 4를 참조하면, 신뢰도 점수 산출 과정은 다음과 같은 단계로 구성된다. 먼저, 외부 자극 신호가 입력되면(S310), 신호 강도(I)를 산출한다(S320). 이어서 발생 빈도(F)(S330), 시간적 연속성(T)(S340), 공간적 근접성(S)(S350), 다수 단말 일치성(M)(S360), 교차검증(V)(S370), 및 신고 이력 신뢰도(H)(S380)를 산출한다.

산출된 7가지 인자는 가중 합산되어(S390) 재난 신뢰도 점수(DCS)로 출력된다(S395). 가중 합산은 다음 수식을 따른다:  
**DCS = w₁·I + w₂·F + w₃·T + w₄·S + w₅·M + w₆·V + w₇·H**

여기서 w₁~w₇은 각 인자의 가중치이며, 재난 유형 및 환경에 따라 조정될 수 있다.

### 도 5 설명문
**도 5는 본 발명에 따른 4단계 재난 모드 전환 로직을 나타낸 상태 전이도이다.**

도 5를 참조하면, 시스템은 정상 모드(S1), 주의 모드(S2), 확인 모드(S3), 대피 모드(S4), 구조 모드(S5)의 5가지 상태를 가진다.

상향 전환은 재난 신뢰도 점수(DCS)가 임계값을 초과하면 즉시 발생한다. 정상 모드(S1)에서 DCS ≥ 0.3이면 주의 모드(S2)로 전환되고, DCS ≥ 0.5이면 확인 모드(S3), DCS ≥ 0.7이면 대피 모드(S4), DCS ≥ 0.9이고 미응답자가 존재하면 구조 모드(S5)로 전환된다.

하향 전환은 히스테리시스 제어를 적용하여 DCS가 임계값 미만으로 2분 이상 유지될 경우에만 발생한다. 이는 재난 모드의 불필요한 반복 전환을 방지한다.

각 상태에서의 주요 동작은 다음과 같다: S1에서는 정상 모니터링, S2에서는 경고 아이콘 표시 및 센서 샘플링 증가, S3에서는 마이크로 설문 출력, S4에서는 개인별 대피 경로 안내, S5에서는 구조 대상 위치 전송 및 우선순위 산정이 수행된다.

### 도 6 설명문
**도 6은 대피 모드(S4)에서 사용자 스마트폰에 표시되는 인터페이스의 예시를 나타낸 화면 모형이다.**

도 6을 참조하면, 스마트폰 화면 상단에는 빨간색 배경의 "대피 지시" 제목과 경보 아이콘이 표시된다. 중앙에는 건물 평면도 기반의 위험지도가 표시되며, 각 구역은 위험도(R)에 따라 녹색(안전), 노란색(주의), 주황색(경고), 빨간색(위험)으로 색상 구분된다.

현재 위치는 파란색 마커(👤)로 표시되고, 추천 대피 경로는 파란색 화살표(➡️)로 표시된다. 하단에는 현재 위치, 대피 경로, 다음 지시, 예상 대피 시간 등의 안내 메시지가 텍스트로 표시되며, [대체 경로 보기] 버튼이 제공된다.

### 도 7 설명문
**도 7은 본 발명에 따른 위험지도 생성 결과를 건물 평면도에 표현한 예시이다.**

도 7을 참조하면, 3층 평면도는 5개 구역(A, B, C, D, E)과 2개 출구(출구 A, 출구 B)로 구성된다. 각 구역은 실시간으로 산출된 위험도(R)에 따라 색상으로 표시된다.

구역 C는 빨간색으로 표시되어 화재 발생 지점(🔥)을 나타내며, 위험도는 R=0.9이다. 구역 E는 주황색으로 표시되어 연기 확산 중(R=0.6)임을 나타낸다. 구역 B는 노란색(R=0.4)으로 주의가 필요하며, 구역 A 및 D는 녹색(R<0.3)으로 안전하다.

사용자의 현재 위치(👤)는 구역 D에 있으며, 추천 대피 경로는 구역 D → 구역 A → 출구 A로 표시된다. 우측에는 색상 범례가 표시되어 사용자가 위험도를 직관적으로 이해할 수 있도록 돕는다.

### 도 8 설명문
**도 8은 구조 모드(S5)에서 구조대 태블릿에 표시되는 구조 대상 목록 인터페이스의 예시를 나타낸 화면 모형이다.**

도 8을 참조하면, 태블릿 화면 상단에는 빨간색 배경의 "구조 대상 목록" 제목과 소방차 아이콘이 표시된다. 중앙에는 우선순위별로 정렬된 구조 대상자 목록이 카드 형태로 표시된다.

각 카드에는 우선순위, 이름, 위치, 위험도, 미응답 지속 시간, 및 [접근 경로 보기] 버튼이 포함된다. 우선순위는 위험도, 거동 불편, 미응답 지속 시간을 종합하여 자동으로 산정된다.

예를 들어, 우선순위 1위는 "김OO (휠체어 사용자), 3층 객실 302, 위험도 0.9, 미응답 2분 30초"로 표시된다. 하단에는 [실시간 위치 추적] 및 [경로 최적화] 버튼이 제공되어 구조대가 효율적으로 구조 작업을 수행할 수 있도록 지원한다.

### 도 9 설명문
**도 9는 본 발명에 따른 재난 위험도 자동 판단 방법의 전체 프로세스를 나타낸 흐름도이다.**

도 9를 참조하면, 본 발명의 방법은 다음과 같은 단계로 구성된다. 먼저, 다중 외부 자극 수집 단계(S100)에서 스마트폰 센서, 사용자 입력, 시설 설비, 관제센터로부터 12종의 외부 자극 신호를 수집한다.

이어서 재난 이벤트 온톨로지 매핑 단계(S200)에서 수집된 신호를 재난 이벤트 온톨로지의 의미 노드로 변환한다. 신뢰도 점수 산출 단계(S300)에서는 7가지 인자(I, F, T, S, M, V, H)를 종합하여 재난 신뢰도 점수(DCS)를 산출한다.

재난 모드 결정 단계(S400)에서는 산출된 DCS에 따라 정상/주의/확인/대피/구조 모드 중 하나를 결정한다. 대피 연동 단계(S500)에서는 위험지도를 생성하고, 개인별 대피 경로를 추천하며, 관제센터 및 구조대와 연동한다.

마지막으로 동적 갱신 단계(S600)에서 5초 주기로 S100~S500 단계를 반복하여 재난 상황을 실시간으로 모니터링하고 대응한다.

### 도 10 설명문
**도 10은 실시예 1(크루즈선 객실 복도 화재)에서의 시간별 동작 순서를 나타낸 타임라인 다이어그램이다.**

도 10을 참조하면, t=0초에 객실 A에서 화재경보음이 감지되고, 객실 B 및 C에서 조도 급감이 발생하며, 복도의 화재감지기 경보가 울리고, 승객 3명이 SOS를 신고한다.

t=5초에는 수집된 신호가 재난 이벤트 온톨로지의 Fire 및 Smoke 노드로 매핑되며, 교차검증(V=1.0)이 수행된다. t=10초에는 신호 강도(I=0.9), 발생 빈도(F=0.6), 다수 단말 일치성(M=1.0), 교차검증(V=1.0)을 종합하여 DCS=0.88이 산출된다.

t=15초에는 DCS가 0.7을 초과하므로 대피 모드가 활성화된다. t=20초에는 위험지도가 생성되고, 일반 성인 20명에게는 계단 A로, 휠체어 사용자 2명에게는 경사로 B로 개인별 대피 경로가 추천된다. 동시에 관제센터에 알림이 전송된다.

t=180초(3분)에는 객실 D 승객이 30초 이상 무응답 상태이므로 구조 모드로 전환되며, 해당 승객이 구조 우선순위 1위로 지정되어 구조대에 위치가 전송된다. 최종적으로 전체 승객은 4분 30초 내에 대피를 완료하고, 미응답자 1명은 6분 20초에 구조가 완료된다.
