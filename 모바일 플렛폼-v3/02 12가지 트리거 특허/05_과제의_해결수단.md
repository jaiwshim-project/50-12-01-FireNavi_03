# 과제의 해결 수단

## 1. 발명의 개요

상기 과제를 해결하기 위하여, 본 발명은 **다중 외부 자극의 온톨로지 매핑 및 신뢰도 점수 기반 재난대피 모드 자동 활성화 시스템 및 방법**을 제공한다.

본 발명의 시스템은 크게 **(1) 다중 외부 자극 수집부, (2) 재난 이벤트 온톨로지 매핑부, (3) 신뢰도 점수 산출부, (4) 재난 모드 결정부, (5) 대피 연동부**로 구성된다.

## 2. 다중 외부 자극 수집부

### 2.1 스마트폰 센서 신호 수집

본 발명의 일 실시예에 따르면, 사용자 단말(스마트폰, 웨어러블 디바이스 등)에 내장된 복수의 센서로부터 다음의 신호를 수집한다.

#### (1) 마이크 기반 음향 신호
- **화재경보음 패턴 인식**: 주파수 분석(FFT)을 통해 화재경보기의 특정 주파수 패턴(예: 3,000Hz, 0.5초 간격 펄스)을 감지한다.
- **비상 음성 키워드 인식**: 음성 인식(STT) 엔진을 통해 "불", "연기", "대피", "위험", "도와주세요", "Fire", "Smoke", "Evacuation", "Help" 등의 비상 키워드를 감지한다.
- **비명·폭발음·파손음 패턴 인식**: 급격한 음압 변화, 고주파 성분, 펄스 형태를 분석하여 비정상 음향을 감지한다.
- **안내방송 비상 키워드 인식**: "비상", "대피", "출구", "화재", "Emergency", "Evacuate" 등의 키워드를 감지한다.

#### (2) 가속도계·자이로센서 기반 움직임 신호
- **급진동·충격 감지**: 가속도 임계값(예: 3G 이상) 초과 시 충격 이벤트로 판단한다.
- **낙상 감지**: 가속도 급격한 변화 + 자이로 회전 + 이후 무이동 패턴을 조합하여 낙상을 감지한다.
- **다수 사용자 동시 이동 이상 감지**: 동일 구역 내 복수 단말에서 급격한 이동 시작, 정체, 역방향 이동 패턴을 감지한다.

#### (3) 조도센서 기반 조명 신호
- **조도 급감 감지**: 기준 조도(예: 200 lux) 대비 급격한 감소(예: 50 lux 이하)를 감지하여 정전 또는 연기로 인한 시야 차단을 판단한다.
- **비상등 점멸 패턴 감지**: 규칙적인 조도 점멸 패턴(예: 1Hz 점멸)을 감지하여 비상등 작동을 인식한다.

#### (4) WiFi/BLE 수신부 기반 무선 신호
- **WiFi AP 신호 이상**: RSSI 값의 급격한 변화, AP 접속 불가, AP 리스트 변화를 감지하여 전력 차단 또는 화재로 인한 설비 손상을 추정한다.
- **BLE 비콘 신호 이상**: 정상 작동 중이던 BLE 비콘의 신호 소실을 감지하여 위치별 이상 상황을 추정한다.

### 2.2 사용자 입력 신호 수집

#### (5) 사용자 SOS 신고
- 사용자가 앱 화면의 **SOS 버튼**을 누르거나, **특정 제스처**(예: 전원 버튼 3회 연속 누름)를 수행하면 긴급 신고 신호가 발생한다.
- 신고 시 사용자 위치, 시간, 사용자 ID가 자동으로 수집된다.

#### (6) 마이크로 설문 응답
- 시스템이 **확인 모드**에서 사용자에게 짧은 설문을 출력한다.
- 예: "불꽃이 보이나요? (예/아니오)", "연기가 나나요?", "출구가 막혔나요?", "부상자가 있나요?", "도움이 필요하나요?"
- 사용자 응답은 신뢰도 점수 산출에 반영된다.

#### (7) 미응답·무이동 상태 감지
- 시스템이 사용자에게 확인 요청을 보냈으나 **일정 시간(예: 30초) 내 응답 없음**
- 또는 **일정 시간(예: 2분) 동안 위치 이동 없음**
- 이 경우 미응답자 또는 무이동자로 분류하여 구조 우선순위에 반영한다.

### 2.3 시설 설비 신호 수집

#### (8) 선박·건물 설비 신호
- **화재감지기**: 온도, 연기 농도 기준 초과 시 경보 신호
- **연기감지기**: 연기 입자 농도 기준 초과 시 경보 신호
- **스프링클러**: 작동 신호
- **비상방송 시스템**: 비상 방송 송출 신호
- **비상등**: 점멸 시작 신호
- **엘리베이터**: 비상 정지 신호
- **출입문**: 비상 개방 또는 폐쇄 신호
- **HVAC(공조) 시스템**: 연기 배출 모드 전환 신호

### 2.4 관제센터 신호 수집

#### (9) 관제센터 비상 푸시
- 관제센터 운영자가 수동으로 발령하는 **비상 명령** 신호
- 예: "3층 복도 화재 발생", "전체 대피 지시", "출구 B 폐쇄"
- 이 신호는 **최고 신뢰도**를 가지며, 즉시 대피 모드로 전환하는 트리거로 작동한다.

### 2.5 12종 재난 트리거 종합

본 발명의 **12종 재난 트리거**는 다음과 같다.

| 번호 | 트리거 | 신호원 | 감지 방법 |
|------|--------|--------|-----------|
| 1 | 화재경보음 | 마이크 | 주파수 패턴 인식 |
| 2 | 비상 음성 키워드 | 마이크 | STT + 키워드 매칭 |
| 3 | 비명·폭발음·파손음 | 마이크 | 음압 급변 + 고주파 분석 |
| 4 | 안내방송 비상 키워드 | 마이크 | STT + 키워드 매칭 |
| 5 | 급진동·충격·낙상 | 가속도계, 자이로센서 | 임계값 초과 + 패턴 분석 |
| 6 | 다수 사용자 이동 이상 | 가속도계, WiFi | 동일 구역 내 급격한 이동 변화 |
| 7 | 조도 급감·비상등 점멸 | 조도센서 | 임계값 하회 + 점멸 패턴 |
| 8 | WiFi/BLE 이상 | WiFi/BLE 수신부 | RSSI 급변, 신호 소실 |
| 9 | 사용자 SOS 신고 | 사용자 입력 | 버튼 또는 제스처 |
| 10 | 미응답·무이동 | 시스템 감시 | 응답 시간 초과, 위치 변화 없음 |
| 11 | 설비 경보 | 시설 설비 | 화재감지기, 연기감지기, 스프링클러 등 |
| 12 | 관제센터 명령 | 관제센터 | 운영자 수동 발령 |

## 3. 재난 이벤트 온톨로지 매핑부

### 3.1 온톨로지 구조

본 발명은 수집된 이질적 신호를 **재난 이벤트 온톨로지**(Disaster Event Ontology)의 **의미 노드**(Semantic Node)로 정규화한다.

온톨로지는 다음과 같은 계층 구조를 가진다.

```
재난 이벤트 (DisasterEvent) [최상위 클래스]
├─ 화재 (Fire)
├─ 연기 (Smoke)
├─ 폭발 (Explosion)
├─ 패닉 (Panic)
├─ 혼잡 (Congestion)
├─ 정전 (PowerFailure)
├─ 출구 폐쇄 (ExitClosure)
├─ 낙상 (Fall)
├─ 미응답 (NoResponse)
├─ 설비 경보 (FacilityAlarm)
└─ 운영자 비상 명령 (ManualEmergency)
```

### 3.2 매핑 규칙

각 외부 자극 신호는 다음의 매핑 규칙에 따라 하나 이상의 의미 노드로 변환된다.

| 외부 자극 신호 | 매핑되는 의미 노드 |
|----------------|---------------------|
| 화재경보음 | Fire |
| 비상 음성 키워드 ("불", "연기") | Fire, Smoke |
| 비명·폭발음 | Explosion, Panic |
| 안내방송 비상 키워드 | ManualEmergency |
| 급진동·충격 | Explosion |
| 낙상 | Fall |
| 다수 사용자 이동 이상 | Panic, Congestion |
| 조도 급감 | PowerFailure, Smoke |
| 비상등 점멸 | ManualEmergency |
| WiFi/BLE 이상 | PowerFailure |
| 사용자 SOS | Panic |
| 미응답·무이동 | NoResponse |
| 화재감지기 | Fire |
| 연기감지기 | Smoke |
| 스프링클러 작동 | Fire |
| 출입문 폐쇄 | ExitClosure |
| 관제센터 명령 | ManualEmergency |

### 3.3 다중 노드 매핑

하나의 신호가 복수의 의미 노드에 매핑될 수 있다. 예를 들어:
- "연기" 음성 키워드 → Fire, Smoke 노드
- 조도 급감 → PowerFailure, Smoke 노드

이 경우 각 노드별로 별도의 신뢰도 점수가 산출되며, 최종적으로 가장 높은 신뢰도를 가진 노드가 재난 유형으로 결정된다.

### 3.4 온톨로지 기반 추론

온톨로지는 단순 분류를 넘어 **추론 규칙**을 포함한다.

**추론 규칙 예시:**
- **규칙 1**: Fire 노드 발생 → 연기 확산 예측 → Smoke 노드 활성화
- **규칙 2**: Smoke 노드 + PowerFailure 노드 → 시야 차단 위험 증가
- **규칙 3**: Panic 노드 + Congestion 노드 → 압사 위험 증가
- **규칙 4**: Fall 노드 + NoResponse 노드 → 부상자 의심 → 구조 우선순위 상승

## 4. 신뢰도 점수 산출부

### 4.1 신뢰도 점수 함수

각 재난 이벤트 노드의 **재난 신뢰도 점수**(Disaster Confidence Score, DCS)는 다음의 함수로 산출된다.

**DCS(E, t) = w₁·I(E, t) + w₂·F(E, t) + w₃·T(E, t) + w₄·S(E, t) + w₅·M(E, t) + w₆·V(E, t) + w₇·H(E, t)**

여기서:
- **E**: 재난 이벤트 노드 (예: Fire, Smoke, Panic 등)
- **t**: 시간
- **I(E, t)**: 신호 강도 (Signal Intensity) — 신호의 물리적 크기 (예: 음압, 가속도 크기)
- **F(E, t)**: 발생 빈도 (Frequency) — 일정 시간 창 내 신호 발생 횟수
- **T(E, t)**: 시간적 연속성 (Temporal Continuity) — 신호가 연속적으로 유지되는 시간
- **S(E, t)**: 공간적 근접성 (Spatial Proximity) — 인접 위치에서 유사 신호 발생 여부
- **M(E, t)**: 다수 단말 일치성 (Multi-Device Consensus) — 동일 구역 내 복수 단말에서 유사 신호 발생 여부
- **V(E, t)**: 교차검증 (Cross-Validation) — 스마트폰 센서 신호와 시설 설비 신호의 일치 여부
- **H(E, t)**: 신고 이력 신뢰도 (Historical Reliability) — 사용자의 과거 신고 이력 (허위 신고 여부)
- **w₁ ~ w₇**: 가중치 계수 (Σw = 1)

### 4.2 신호원별 가중치

신호원별로 기본 신뢰도가 다르므로, 가중치를 차등 부여한다.

| 신호원 | 기본 가중치 | 비고 |
|--------|-------------|------|
| 시설 설비 (화재감지기, 연기감지기 등) | 1.0 | 최고 신뢰도 |
| 관제센터 비상 명령 | 1.0 | 최고 신뢰도 |
| 사용자 SOS 신고 (확인된 사용자) | 0.8 | 높은 신뢰도 |
| 음향 패턴 인식 (화재경보음 등) | 0.7 | 중상 신뢰도 |
| 센서 신호 (급진동, 조도 급감 등) | 0.6 | 중간 신뢰도 |
| 사용자 SOS 신고 (신규 사용자) | 0.5 | 중간 신뢰도 |

### 4.3 다수 단말 일치성 (M)

**다수 단말 일치성**은 오경보 방지의 핵심 요소이다.

**M(E, t) = min(1.0, N_matched / N_threshold)**

여기서:
- **N_matched**: 동일 구역 내 유사 신호를 감지한 단말 수
- **N_threshold**: 기준 단말 수 (예: 3대)

**예시:**
- 구역 A에서 1대 단말만 "비명" 감지 → M = 0.33 (낮은 신뢰도)
- 구역 A에서 5대 단말이 "비명" 감지 → M = 1.0 (높은 신뢰도)

### 4.4 교차검증 (V)

**교차검증**은 스마트폰 센서 신호와 시설 설비 신호의 일치 여부를 평가한다.

**V(E, t) = 1.0** (스마트폰 신호 + 설비 신호 일치)  
**V(E, t) = 0.5** (스마트폰 신호만 존재)  
**V(E, t) = 0.8** (설비 신호만 존재)

**예시:**
- 스마트폰 마이크로 화재경보음 감지 + 화재감지기 경보 → V = 1.0
- 스마트폰 마이크로 화재경보음 감지 + 화재감지기 정상 → V = 0.5 (안전교육 영상 가능성)

### 4.5 신뢰도 점수 임계값

재난 신뢰도 점수에 따라 다음의 모드 전환 임계값을 설정한다.

| 재난 모드 | 신뢰도 점수 범위 |
|-----------|-----------------|
| 주의 모드 | 0.3 ≤ DCS < 0.5 |
| 확인 모드 | 0.5 ≤ DCS < 0.7 |
| 대피 모드 | 0.7 ≤ DCS < 0.9 |
| 구조 모드 | 0.9 ≤ DCS ≤ 1.0 + 미응답자 존재 |

## 5. 재난 모드 결정부

### 5.1 모드 결정 로직

**재난 모드 결정부**는 신뢰도 점수에 따라 다음의 4가지 모드 중 하나를 자동으로 결정한다.

#### 모드 1: 주의 모드 (Attention Mode)
**조건**: 0.3 ≤ DCS < 0.5

**동작**:
- 사용자에게 **경고 아이콘** 표시 (화면 상단 알림)
- **배경 모니터링 강화** (센서 샘플링 주기 증가)
- 추가 신호 수집 대기
- 관제센터에 주의 알림 전송 (우선순위: 낮음)

**목적**: 경미한 징후 감지 시 과도한 경보 방지, 사용자 피로도 감소

#### 모드 2: 확인 모드 (Confirmation Mode)
**조건**: 0.5 ≤ DCS < 0.7

**동작**:
- 사용자에게 **마이크로 설문** 출력 (전체 화면 팝업)
- 질문 예시:
  - "불꽃이 보이나요? (예/아니오)"
  - "연기가 나나요?"
  - "출구가 막혔나요?"
  - "부상자가 있나요?"
  - "도움이 필요하나요?"
- 사용자 응답을 신뢰도 점수에 반영 (응답 "예" → DCS +0.2)
- 응답 없을 시 30초 후 자동 대피 모드 전환

**목적**: 불확실한 상황에서 사용자 확인을 통해 오경보 방지 및 실제 위험 조기 확인

#### 모드 3: 대피 모드 (Evacuation Mode)
**조건**: 0.7 ≤ DCS < 0.9

**동작**:
- **개인별 대피 경로** 화면 전체에 표시
- 위험 구역 회피 경로 제공
- **대체 경로** 자동 생성 (주 경로 폐쇄 시)
- **진동 안내** (경로 방향 전환 시 진동 패턴)
- **음성 안내** (TTS: "지금 오른쪽으로 이동하세요")
- **시각 안내** (화살표, 색상 코드: 녹색→안전, 빨간색→위험)
- 관제센터에 대피 시작 알림 전송

**목적**: 실제 위험 발생 시 신속한 대피 안내

#### 모드 4: 구조 모드 (Rescue Mode)
**조건**: 0.9 ≤ DCS ≤ 1.0 **+** 미응답자 존재

**동작**:
- 미응답자, 무이동자, 취약계층, 부상 의심자를 **구조 대상**으로 분류
- 구조 대상의 **마지막 위치**, **주변 위험도**, **접근 경로**를 관제센터 및 구조대 단말에 실시간 전송
- **구조 우선순위** 자동 결정 (위험도 + 취약도)
- 구조대에게 **최적 접근 경로** 제공
- 구조 완료 시까지 **실시간 위치 추적**

**목적**: 미응답자 및 취약계층 우선 구조, 구조 효율 극대화

### 5.2 모드 전환 히스테리시스

모드 전환 시 **히스테리시스(Hysteresis)**를 적용하여 짧은 시간 내 반복 전환을 방지한다.

- 상향 전환 (주의→확인→대피→구조): 즉시 전환
- 하향 전환 (구조→대피→확인→주의): **일정 시간 유지 후** 전환 (예: 2분)

**예시:**
- DCS = 0.75 → 대피 모드 전환
- DCS = 0.65로 하락 → 즉시 확인 모드로 하향하지 않고, 2분간 대피 모드 유지
- 2분 후에도 DCS < 0.7 유지 → 확인 모드로 하향 전환

## 6. 대피 연동부

### 6.1 위험지도 생성부 연동

**대피 모드** 또는 **구조 모드**에서 **위험지도 생성부**가 자동으로 활성화된다.

#### 위험지도 생성 알고리즘
- 각 구역(x, y)의 위험도는 다음과 같이 산출된다:

**R(x, y, t) = max(DCS_Fire(x,y,t), DCS_Smoke(x,y,t), DCS_Congestion(x,y,t))**

- 위험도 색상 코드:
  - **녹색** (R < 0.3): 안전
  - **노란색** (0.3 ≤ R < 0.5): 주의
  - **주황색** (0.5 ≤ R < 0.7): 경고
  - **빨간색** (R ≥ 0.7): 위험

- 위험지도는 **실시간 갱신** (갱신 주기: 5초)

### 6.2 개인별 경로 추천부 연동

**대피 모드**에서 **개인별 경로 추천부**가 자동으로 활성화된다.

#### 경로 추천 알고리즘
- **A* 알고리즘 기반** 최단 안전 경로 탐색
- **비용 함수**:

**Cost(x, y) = Distance(x, y) + α·R(x, y, t) + β·Congestion(x, y, t)**

- **취약계층 우선 고려**:
  - 휠체어 사용자: 경사로, 엘리베이터 우선
  - 시각장애인: 직선 경로 우선
  - 고령자: 계단 최소화
  - 어린이: 보호자 동기화

- **대체 경로 자동 생성**: 주 경로가 폐쇄되거나 위험도가 상승하면 즉시 대체 경로 제공

### 6.3 관제센터 연동부 연동

**확인 모드** 이상에서 **관제센터 연동부**가 자동으로 활성화된다.

#### 관제센터 전송 정보
- 재난 발생 구역 (위치, 재난 유형, 신뢰도 점수)
- 사용자 분포 (층별, 구역별 인원 수)
- 미응답자 위치 (실시간 업데이트)
- 대피 진행 상황 (대피 완료율, 남은 인원)
- 위험지도 (실시간 갱신)

#### 관제센터 수동 명령
- 관제센터 운영자가 **전체 대피 지시**, **출구 폐쇄 알림**, **구조대 출동 요청** 등을 수동으로 발령 가능
- 수동 명령은 **최고 신뢰도**로 처리되어 즉시 시스템에 반영

### 6.4 구조대 연계부 연동

**구조 모드**에서 **구조대 연계부**가 자동으로 활성화된다.

#### 구조대 전송 정보
- **구조 대상 목록** (미응답자, 무이동자, 취약계층, 부상 의심자)
- **구조 우선순위** (위험도 + 취약도 기반 점수)
- **마지막 위치** (GPS 좌표, 층, 구역)
- **주변 위험도** (접근 경로상 화재·연기·혼잡도)
- **최적 접근 경로** (구조대 현재 위치 → 구조 대상까지)
- **실시간 위치 추적** (구조 완료 시까지)

#### 구조 우선순위 산정
**구조 우선순위 점수 (Rescue Priority Score, RPS)**는 다음과 같이 산출된다.

**RPS = w₁·R(x, y, t) + w₂·V + w₃·T_no_response**

여기서:
- **R(x, y, t)**: 구조 대상 위치의 위험도
- **V**: 취약계층 가중치 (일반: 0.5, 고령자: 0.8, 휠체어: 1.0)
- **T_no_response**: 미응답 지속 시간 (분 단위)
- **w₁, w₂, w₃**: 가중치 계수

RPS가 높을수록 우선 구조 대상이 된다.

## 7. 시스템 청구항 구성

본 발명의 시스템은 다음의 구성 요소를 포함한다.

### 다중 외부 자극 수집부
- 사용자 단말의 마이크, 가속도계, 자이로센서, 조도센서, WiFi/BLE 수신부
- 사용자 입력 인터페이스 (SOS 버튼, 마이크로 설문)
- 시설 설비 인터페이스 (화재감지기, 연기감지기, 스프링클러 등)
- 관제센터 인터페이스 (비상 명령 수신)

### 재난 이벤트 온톨로지 매핑부
- 외부 자극 신호를 재난 이벤트 온톨로지의 의미 노드로 매핑하는 연산 모듈
- 온톨로지 추론 엔진 (노드 간 관계 추론)

### 신뢰도 점수 산출부
- 신호 강도, 발생 빈도, 시간적 연속성, 공간적 근접성, 다수 단말 일치성, 교차검증, 신고 이력 신뢰도를 종합하여 재난 신뢰도 점수를 산출하는 연산 모듈
- 신호원별 가중치 적용 모듈

### 재난 모드 결정부
- 재난 신뢰도 점수에 따라 주의 모드, 확인 모드, 대피 모드, 구조 모드 중 하나를 결정하는 모듈
- 모드 전환 히스테리시스 제어 모듈

### 대피 연동부
- 위험지도 생성부: 실시간 위험도 맵 생성 및 갱신
- 개인별 경로 추천부: A* 알고리즘 기반 개인별 최적 대피 경로 산출
- 관제센터 연동부: 재난 상황 및 사용자 분포 정보 전송
- 구조대 연계부: 구조 대상 위치, 우선순위, 접근 경로 제공

### 통신부
- 사용자 단말, 시설 설비, 관제센터, 구조대 간 양방향 통신을 수행하는 모듈

## 8. 방법 청구항 구성

본 발명의 방법은 다음의 단계를 포함한다.

**단계 S100**: 복수의 외부 자극 신호를 수집하는 다중 외부 자극 수집 단계

**단계 S200**: 상기 외부 자극 신호를 재난 이벤트 온톨로지의 의미 노드로 매핑하는 온톨로지 매핑 단계

**단계 S300**: 신호 강도, 발생 빈도, 시간적 연속성, 공간적 근접성, 다수 단말 일치성, 교차검증, 신고 이력 신뢰도를 종합하여 재난 신뢰도 점수를 산출하는 신뢰도 점수 산출 단계

**단계 S400**: 상기 재난 신뢰도 점수에 따라 주의 모드, 확인 모드, 대피 모드, 구조 모드 중 하나를 결정하는 재난 모드 결정 단계

**단계 S500**: 상기 결정된 모드에 따라 위험지도 생성부, 개인별 경로 추천부, 관제센터 연동부, 구조대 연계부 중 적어도 하나를 활성화하는 대피 연동 단계

**단계 S600**: 매 시간 단계마다 상기 S100 내지 S500 단계를 반복 수행하여 재난 모드 및 대피 경로를 실시간으로 갱신하는 동적 갱신 단계
