# 발명의 상세한 설명

## 기술분야

본 발명은 WiFi 기반 실내 위치추적과 다중 인공지능 엔진을 이용한 실시간 화재 대피 경로 최적화 시스템 및 방법에 관한 것으로서, 보다 상세하게는 크루즈선, 고층 빌딩, 공항 등 대규모 밀폐 구조물에서 화재 발생 시 탑승객 또는 재실자의 실내 위치를 WiFi 신호로 실시간 파악하고, 예측 AI·행동 AI·의사결정 AI의 3중 엔진을 동시 가동하여 동적 위험도 맵을 생성하며, 취약 계층(고령자, 장애인, 어린이, 임산부, 부상자)에 대해 우선구조 디바이스를 통한 차별화된 대피 경로를 제공함과 동시에 **소방관의 최적 배치 위치를 AI로 추천하는 실시간 화재 대응 통합 플랫폼**에 관한 것이다.

## 배경기술

종래의 화재 대피 시스템은 고정된 대피 경로 안내판과 비상구 표시에 의존하여, 화재 확산 상황에 따른 동적 경로 변경이 불가능하였다. 또한, 실내에서의 정확한 위치 파악이 어려워 재실자 개개인에게 맞춤형 대피 경로를 제공하는 것이 사실상 불가능하였다.

기존의 WiFi 기반 실내 측위 기술은 일반적인 위치 서비스에 활용되었으나, 화재 대피 시나리오에 특화된 다중 위험 요소 통합 분석 및 경로 최적화와 결합된 사례는 없었다. 특히, 화재 시 연기 확산, 구조적 위험, 군집 밀집도, 대피 거리 등 복합 위험 요소를 동시에 고려하는 동적 리스크맵 기반의 경로 생성 기술은 존재하지 않았다.

나아가, 고령자·장애인·어린이·임산부·부상자 등 취약 계층에 대한 차별화된 우선 구조 메커니즘과, 해당 취약자와 보호자 간의 동기화된 대피 경로 제공 기술은 종래 기술에서 전혀 다루어지지 않았다.

이에 본 발명은 상기와 같은 종래 기술의 한계를 극복하고자 안출된 것이다.

## 발명의 내용

### 해결하려는 과제

본 발명의 목적은, 대규모 밀폐 구조물에서의 화재 발생 시 WiFi 기반 실내 위치추적 기술과 다중 AI 엔진을 결합하여 재실자 개개인에게 실시간으로 최적의 대피 경로를 제공하는 시스템 및 방법을 제공하는 데 있다.

본 발명의 다른 목적은, 취약 계층에 대해 우선구조 디바이스를 부여하고 보호자와 동기화된 대피 경로를 생성함으로써, 취약 계층의 생존율을 극대화하는 시스템 및 방법을 제공하는 데 있다.

본 발명의 또 다른 목적은, 평상시에는 보안 모니터링 모드로 운영되고 비상시에는 대피 관리 모드로 자동 전환되는 이중 모드 운영 플랫폼을 제공하는 데 있다.

### 과제의 해결 수단

상기의 목적을 달성하기 위하여, 본 발명에 따른 실시간 화재 대피 경로 최적화 시스템은, WiFi 비콘 및 센서를 통해 재실자의 위치를 추적하는 데이터 수집부(100)와, 화재 확산을 예측하는 예측 엔진(210), 군집 행동을 분석하는 행동 엔진(220), 경로를 최적화하는 의사결정 엔진(230)을 포함하는 AI 엔진부(200)와, 복합 위험 요소를 통합하여 동적 리스크맵을 생성하는 동적 리스크맵 생성부(300)와, 평상 모드(410)와 비상 모드(420)를 관리하는 플랫폼 모드 관리부(400)와, 대피 경로를 시각적으로 안내하는 시각화 및 안내부(500)를 포함한다.

### 발명의 효과

본 발명에 따르면, 다음과 같은 효과를 달성할 수 있다.

첫째, WiFi 기반 실내 위치추적을 룸키 또는 출입카드에 내장함으로써 2~3m 정밀도의 위치 파악이 가능하며, 별도의 앱 설치 없이도 전 재실자의 위치를 실시간으로 추적할 수 있다.

둘째, 3중 AI 엔진의 동시 가동을 통해 화재 확산 예측, 군집 행동 분석, 경로 최적화가 병렬적으로 수행되어, 급변하는 화재 상황에 실시간으로 대응할 수 있다.

셋째, 우선구조 디바이스를 통한 취약 계층 차별화 대피 및 보호자 동기화 경로 제공으로, 취약 계층의 생존율을 유의미하게 향상시킬 수 있다.

넷째, 동적 리스크맵 R(x,y,t)를 통해 시공간적으로 변화하는 복합 위험도를 정량화함으로써, 정적 대피 경로 대비 대피 효율을 대폭 개선할 수 있다.

다섯째, 이중 모드 운영을 통해 평상시에는 보안 모니터링 시스템으로 활용하고 비상시에는 대피 관리 시스템으로 즉시 전환할 수 있어, 시스템의 활용도와 경제성이 극대화된다.

## 1. 시스템 구성 (도면 1 참조)

본 발명에 따른 실시간 화재 대피 경로 최적화 시스템의 전체 구성을 도면 1을 참조하여 상세히 설명한다.

### 1.1 데이터 수집부 (100)

상기 데이터 수집부(100)는 구조물 내에 설치된 복수의 WiFi 비콘, 화재·연기 감지 센서, 온도·가스 센서, 및 재실자가 소지하는 위치추적 디바이스로부터 데이터를 수집하는 구성부이다.

상기 데이터 수집부(100)는 표준 디바이스(Standard Device)(110)와 우선구조 디바이스(Priority Rescue Device)(120)의 두 종류의 위치추적 디바이스를 포함한다.

#### 1.1.1 표준 디바이스 (Standard Device) (110)

상기 표준 디바이스(110)는 크루즈선의 룸키 또는 빌딩의 출입카드에 WiFi 송수신 모듈을 내장한 장치로서, 재실자의 실시간 위치를 2~3m 정밀도로 추적한다. 상기 표준 디바이스(110)는 WiFi 삼변측량(trilateration) 방식을 통해 최소 3개의 WiFi 액세스 포인트로부터 수신 신호 강도(RSSI)를 측정하여 위치를 산출한다.

상기 표준 디바이스(110)는 다음의 데이터를 포함하여 전송한다:
- 고유 식별자(Device ID)
- 현재 위치 좌표(x, y, deck/floor)
- 신호 강도 벡터(RSSI values)
- 타임스탬프

#### 1.1.2 우선구조 디바이스 (Priority Rescue Device) (120)

상기 우선구조 디바이스(120)는 취약 계층(고령자, 장애인, 어린이, 임산부, 부상자)에게 부여되는 차별화된 디바이스로서, 상기 표준 디바이스(110)의 모든 기능에 더하여 다음의 추가 기능을 포함한다:

- **우선구조 플래그(Priority Flag)**: 비상 시 해당 디바이스 소지자를 우선 구조 대상으로 자동 식별하는 플래그
- **취약 유형 코드(Vulnerability Type Code)**: 고령자(E), 장애인(D), 어린이(C), 임산부(P), 부상자(I)의 5가지 유형 코드
- **이동능력 계수(Mobility Factor, μ)**: 0.0~1.0 범위의 이동능력 정량화 값으로, 1.0은 정상 이동, 0.0은 이동 불가를 나타냄
- **보호자 연동 ID(Guardian Link ID)**: 해당 취약자의 보호자 디바이스와 쌍으로 연결하기 위한 식별자
- **긴급 호출 버튼**: 일방향 긴급 구조 요청 발신 기능

### 1.2 AI 엔진부 (200)

상기 AI 엔진부(200)는 수집된 데이터를 기반으로 화재 확산 예측, 군집 행동 분석, 경로 최적화를 수행하는 3개의 독립적 AI 엔진을 포함한다. 상기 3개의 엔진은 비상 모드 전환 시 동시에 병렬 가동되어 실시간 분석을 수행한다.

#### 1.2.1 예측 엔진 (Prediction Engine) (210)

상기 예측 엔진(210)은 화재 및 연기의 확산을 시공간적으로 예측하는 엔진으로서, 다음의 수리 모델을 활용한다:

- **이류-확산 방정식 (Advection-Diffusion Equation)**: 연기 농도의 시공간적 변화를 모델링
  - ∂C/∂t + u·∇C = D·∇²C + S
  - 여기서 C는 연기 농도, u는 기류 속도 벡터, D는 확산 계수, S는 발생원항

- **Beer-Lambert 법칙**: 연기에 의한 가시거리 감소를 정량화
  - V = (1/K) · ln(1/C_threshold)
  - 여기서 V는 가시거리, K는 소광계수, C_threshold는 인지 한계 농도

- **LSTM (Long Short-Term Memory)**: 과거 센서 데이터의 시계열 패턴을 학습하여 향후 화재 확산 경로를 예측

#### 1.2.2 행동 엔진 (Behavior Engine) (220)

상기 행동 엔진(220)은 재실자의 군집 행동을 분석하고 예측하는 엔진으로서, 다음의 수리 모델을 활용한다:

- **Social Force Model**: 개인 간 사회적 힘(반발력, 끌림력)을 모델링하여 군집 이동 패턴을 시뮬레이션
  - m_i · (dv_i/dt) = f_i^desire + Σ f_ij^social + Σ f_iW^wall
  - 여기서 f_i^desire는 목표 방향력, f_ij^social는 타인과의 상호작용력, f_iW^wall은 벽면 반발력

- **KDE (Kernel Density Estimation)**: 재실자 분포의 밀집도를 추정하여 병목 지점을 사전 식별
  - ρ(x) = (1/nh) · Σ K((x - x_i)/h)

- **LWR (Lighthill-Whitham-Richards) 모델**: 통로에서의 보행자 흐름을 교통류 이론으로 분석
  - ∂ρ/∂t + ∂(ρ·v(ρ))/∂x = 0

- **Navier-Stokes 유사 모델**: 대규모 군집 흐름을 유체역학적으로 분석

#### 1.2.3 의사결정 엔진 (Decision Engine) (230)

상기 의사결정 엔진(230)은 예측 엔진(210)과 행동 엔진(220)의 출력을 종합하여 각 재실자에게 최적의 대피 경로를 생성하는 엔진으로서, 다음의 알고리즘을 활용한다:

- **위험도 가중 A* 경로탐색 알고리즘**: 동적 리스크맵의 위험도를 비용함수에 통합한 변형 A* 알고리즘
  - f(n) = g(n) + h(n) + λ·R(x_n, y_n, t)
  - 여기서 g(n)은 시작점에서의 실제 비용, h(n)은 목표점까지의 추정 비용, R은 해당 위치·시점의 위험도, λ는 위험도 가중 계수

- **Monte Carlo 시뮬레이션**: 복수의 대피 시나리오를 확률적으로 시뮬레이션하여 최적 경로의 신뢰성을 검증

### 1.3 동적 리스크맵 생성부 (300)

상기 동적 리스크맵 생성부(300)는 예측 엔진(210)과 행동 엔진(220)의 출력을 통합하여, 구조물 내 모든 위치에 대해 시간에 따라 변화하는 위험도 값을 생성한다. 리스크맵은 다음의 수식으로 정의된다:

**R(x, y, t) = w₁·F(x,y,t) + w₂·S(x,y,t) + w₃·D(x,y,t) + w₄·C(x,y,t)**

여기서:
- **F(x,y,t)**: 화재 근접도 지수 (Fire Proximity Index), 가중치 w₁ = 0.35
- **S(x,y,t)**: 연기 농도 지수 (Smoke Density Index), 가중치 w₂ = 0.30
- **D(x,y,t)**: 구조적 위험 지수 (Structural Danger Index), 가중치 w₃ = 0.20
- **C(x,y,t)**: 군집 밀집도 지수 (Crowd Congestion Index), 가중치 w₄ = 0.15

각 지수는 0~1 범위로 정규화되며, 가중치의 합은 1.0이다. 상기 리스크맵은 미리 설정된 갱신 주기(바람직하게는 2~5초)마다 재계산된다.

### 1.4 플랫폼 모드 관리부 (400)

상기 플랫폼 모드 관리부(400)는 시스템의 운영 모드를 관리하며, 두 가지 모드를 포함한다.

#### 1.4.1 Normal Mode (평상 모드) (410)

상기 평상 모드(410)에서는 다음의 보안 및 운영 모니터링 기능이 수행된다:
- 구역별 재실자 수 실시간 집계
- 보안 구역 침입 탐지 (통제 구역, 선교, 엔진룸 등)
- 비인가 구역 접근 알림
- 재실자 동선 패턴 분석
- 비정상 밀집 경고

#### 1.4.2 Emergency Mode (비상 모드) (420)

화재 감지 센서로부터 화재 신호가 수신되면, 상기 플랫폼 모드 관리부(400)는 시스템을 비상 모드(420)로 자동 전환한다. 비상 모드(420)에서는 다음의 기능이 활성화된다:
- 3중 AI 엔진 동시 가동
- 동적 리스크맵 실시간 생성
- 우선구조 대상 자동 식별
- 개인별 맞춤형 대피 경로 생성 및 안내
- 보호자-취약자 동기화 경로 생성
- 대피 진행 상황 실시간 모니터링
- 구조대 대시보드 운영

### 1.5 시각화 및 안내부 (500)

상기 시각화 및 안내부(500)는 대피 경로 및 상황 정보를 재실자와 관리자에게 시각적으로 전달하는 구성부로서, 다음을 포함한다:
- 관리자용 통합 대시보드: 전체 구조물의 리스크맵, 재실자 위치, 대피 진행률 표시
- 구역별 안내 디스플레이: 각 구역에 설치된 디스플레이에 해당 구역의 대피 방향 표시
- 디바이스 알림: 표준 디바이스 및 우선구조 디바이스에 대피 방향 및 비상 메시지 전송
- 대피 완료 통계: 유형별·구역별 대피 완료 현황 및 소요 시간 통계

## 2. 처리 흐름 (도면 2 참조)

본 발명에 따른 실시간 화재 대피 경로 최적화 방법의 처리 흐름을 도면 2를 참조하여 단계별로 설명한다.

### S100: 데이터 수집 단계

시스템은 구조물 내에 설치된 WiFi 비콘, 화재·연기 감지 센서, 온도·가스 센서로부터 실시간 데이터를 수집한다. 동시에, 각 재실자가 소지한 표준 디바이스(110) 또는 우선구조 디바이스(120)로부터 위치 신호를 수신한다.

### S200: WiFi 위치 파악 단계

수집된 WiFi RSSI 신호를 기반으로 삼변측량 알고리즘을 적용하여, 각 디바이스의 실내 위치 좌표(x, y, deck/floor)를 2~3m 정밀도로 산출한다. 위치 산출 결과는 칼만 필터(Kalman Filter)를 적용하여 노이즈를 제거하고 궤적의 연속성을 보장한다.

### S300: 화재 감지 판단 단계 (분기)

화재 감지 센서의 신호를 분석하여 화재 발생 여부를 판단한다. 화재가 감지되지 않은 경우 단계 S310으로 진행하고, 화재가 감지된 경우 단계 S400으로 진행한다.

### S310: Normal Mode 유지 단계 (보안/운영)

화재가 감지되지 않은 상태에서, 시스템은 평상 모드(410)를 유지하며 다음의 보안·운영 모니터링을 수행한다:
- 구역별 재실자 수 집계 및 표시
- 보안 구역 침입 탐지: 통제 구역 경계에 가상 펜스를 설정하고, 비인가 디바이스의 진입을 실시간 탐지
- 비정상 밀집 패턴 감지: KDE를 적용하여 비정상적 밀집이 감지되면 관리자에게 알림
- 단계 S100으로 회귀하여 지속적 모니터링을 수행

### S400: Emergency Mode 전환 단계

화재 감지 시, 플랫폼 모드 관리부(400)는 시스템을 비상 모드(420)로 즉시 전환한다. 전환과 동시에 모든 디바이스에 비상 알림이 발송되고, 관리자 대시보드가 비상 모드 인터페이스로 변경된다.

### S410: 3 AI 엔진 동시 가동 단계

비상 모드 전환과 동시에 3개의 AI 엔진이 병렬로 가동된다:
- 예측 엔진(210): 이류-확산 방정식, Beer-Lambert 법칙, LSTM을 이용하여 화재 및 연기 확산을 예측
- 행동 엔진(220): Social Force Model, KDE, LWR 모델을 이용하여 군집 행동을 분석 및 예측
- 의사결정 엔진(230): A* 경로탐색, Monte Carlo 시뮬레이션을 이용하여 최적 경로를 생성

### S420: 동적 리스크맵 생성 단계

예측 엔진(210)과 행동 엔진(220)의 출력을 통합하여, 구조물 전체에 대한 동적 리스크맵 R(x,y,t)를 생성한다. 리스크맵은 미리 설정된 주기(2~5초)마다 갱신된다.

### S430: 우선구조 대상 식별 단계

우선구조 디바이스(120)를 소지한 재실자를 자동 식별하고, 각 취약자의 유형 코드와 이동능력 계수(μ)를 파악한다. 우선구조 점수(Priority Score)를 다음과 같이 산출한다:

**P_score = α · (1 - μ) + β · R(x_i, y_i, t) + γ · T_type**

여기서:
- μ: 이동능력 계수 (0.0~1.0)
- R(x_i, y_i, t): 현재 위치의 위험도
- T_type: 취약 유형별 가중치 (어린이 > 장애인 > 고령자 > 임산부 > 부상자 순)
- α, β, γ: 조정 계수

### S435: AI 출구 혼잡도 분석 단계

의사결정 엔진(230)은 각 출구에 현재 배정된 재실자 수를 실시간으로 카운트하여 출구별 혼잡도를 분석한다. 구체적으로, getExitCrowdCount(exit) 함수를 통해 각 출구에 이미 대피 경로가 배정된 재실자 수(N_assigned)를 산출하고, 혼잡도 페널티(CrowdPenalty = N_assigned × 40)를 출구 선택 스코어에 반영한다. 이를 통해 특정 출구에 재실자가 과도하게 집중되는 병목 현상을 사전에 방지하고, 복수의 출구에 재실자를 균형 있게 분산 배정한다.

### S437: 취약 계층 연기 회피 강화 단계

상기 S430 단계에서 식별된 우선구조 대상에 대해, 출구 선택 스코어 산출 시 화염 및 연기 페널티에 적용되는 안전 계수(α, smokeMultiplier)를 강화한다. 고령자(E), 휠체어 사용자(D), 어린이(C), 임산부(P), 부상자(I)로 분류되는 취약 계층에 대해서는 α = 2.0을 적용하고, 일반 성인에 대해서는 α = 1.0을 적용한다. 상기 안전 계수의 차별 적용에 의해, 취약 계층은 경로상 연기 농도가 높은 출구를 자동으로 기피하고, 다소 거리가 멀더라도 연기가 없는 안전한 출구를 선택하게 되어, 호흡기 취약자의 연기 노출 위험이 대폭 감소한다.

### S438: 개인화 출구 배정 단계

상기 S435 및 S437 단계의 출력을 종합하여, 각 재실자에 대해 개인화된 최적 출구를 배정한다. 개인화 출구 배정 함수 findNearestSafeExit(x, y, passenger)는 승객 객체(passenger)의 유형 정보에 따라 smokeMultiplier를 결정하고, 다음의 5단계 의사결정 프로세스를 수행한다: (1) 각 출구의 안전성 검사(화재 차단 여부), (2) 현재 위치에서 각 출구까지의 거리 산출, (3) 경로상 화염·연기 페널티에 안전 계수 α 적용, (4) 경로상 장애물 페널티 산출, (5) 출구별 혼잡도 페널티 산출. 최종 출구 선택 스코어는 Score(exit) = Distance + FirePenalty×α + SmokePenalty×α + CrowdPenalty에 의해 산출되며, 스코어가 최소인 출구가 해당 재실자의 최적 출구로 배정된다. 이에 의해, 동일 위치에 있는 일반 성인과 취약 계층에게 서로 다른 최적 출구가 배정되는 진정한 개인화 대피가 실현된다.

### S440: 개인별 대피 경로 생성 단계

의사결정 엔진(230)이 다음의 요소를 종합하여 각 재실자에 대해 개인화된 대피 경로를 생성한다:

**(a) 6가지 승객 유형 분류:**
| 유형 | 이동능력 계수(μ) 범위 | 경로 특성 |
|------|----------------------|-----------|
| 일반 성인 | 0.8~1.0 | 최단 시간 경로 |
| 고령자 | 0.4~0.7 | 계단 최소화, 완경사 우선 |
| 장애인(휠체어) | 0.1~0.3 | 엘리베이터/경사로 필수, 폭 1.2m 이상 통로 |
| 어린이 | 0.5~0.7 | 보호자 동행 경로, 안전 구역 경유 |
| 임산부 | 0.5~0.7 | 저층 이동 우선, 완경사 경로 |
| 부상자 | 0.1~0.5 | 구조대 합류 경로, 의료 지점 경유 |

**(b) 건강 인지 경로 생성:**
이동능력 계수(μ)를 A* 알고리즘의 비용함수에 통합하여 개인별 최적 경로를 생성한다:
- f(n) = g(n)/μ + h(n) + λ·R(x_n, y_n, t)
- μ 값이 낮을수록 이동 비용이 증가하여, 자동으로 장애물이 적고 이동이 용이한 경로가 선택됨

**(c) 보호자-취약자 동기화 경로:**
보호자 연동 ID를 통해 식별된 보호자-취약자 쌍에 대해, 양자의 현재 위치에서 합류 가능한 중간 지점을 산출한 후, 합류 지점에서 출구까지 동일한 대피 경로를 생성한다.

### S450: 실시간 경로 재계산 단계

대피 진행 중 동적 리스크맵이 갱신될 때마다, 의사결정 엔진(230)은 각 재실자의 대피 경로를 재계산한다. 경로 변경이 발생하면 해당 디바이스에 즉시 새 경로가 전송된다. 경로 재계산의 트리거 조건은 다음과 같다:
- 리스크맵 갱신에 의해 현재 경로의 위험도가 임계값을 초과한 경우
- 경로상 통로가 차단된 것으로 감지된 경우
- 군집 밀집도가 임계값을 초과하여 병목이 발생한 경우
- 새로운 출구가 개방되거나 기존 출구가 차단된 경우

### S460: 대피 완료 판정 단계

각 재실자의 디바이스가 미리 정의된 안전 구역(집결지, 구명정 탑승장 등)에 도달한 것이 감지되면, 해당 재실자의 대피 완료를 판정한다. 전체 재실자의 대피 완료 또는 잔류자 구조 완료 시 단계 S500으로 진행한다.

### S500: 통계 및 보고 단계

대피 완료 후 다음의 통계 및 보고를 생성한다:
- 유형별 대피 완료 인원 및 비율
- 평균 대피 소요 시간 (전체/유형별/구역별)
- 우선구조 디바이스 대피 성과 (우선 대피 달성률)
- 잔류자 현황 및 위치
- 대피 경로 효율 분석 (경로 변경 횟수, 병목 발생 지점 등)

DeviceData {

```
RiskCell {

PassengerProfile {

    evacuation_status: Enum    // WAITING | EVACUATING | ARRIVED | RESCUED
}

## 4. 실시예 1: 크루즈선 6,000명 화재 시나리오

이하, 본 발명의 구체적 실시예를 설명한다. 본 실시예는 총 탑승인원 6,000명(승객 4,000명, 승무원 2,000명)의 대형 크루즈선에서 Deck 5 엔진룸 부근에서 화재가 발생한 경우를 가정한다.

### 4.1 초기 상태

- 구조: 12개 Deck, 총 바닥면적 약 50,000㎡
- WiFi 비콘: 각 Deck당 약 100개, 총 약 1,200개 설치
- 디바이스 분포: 표준 디바이스(110) 5,400개, 우선구조 디바이스(120) 600개
- 우선구조 대상: 고령자 200명, 장애인 50명, 어린이 250명, 임산부 30명, 부상자 70명

### 4.2 화재 발생 및 모드 전환

시각 T=0에서 Deck 5 엔진룸 부근 화재 감지 센서가 작동하고, 시스템은 0.5초 이내에 비상 모드(420)로 전환된다.

### 4.3 AI 엔진 가동 및 리스크맵 생성

- 예측 엔진(210): T=1초에서 이류-확산 방정식을 적용하여 Deck 5로부터 상층으로의 연기 확산 경로를 예측. T+5분 시점에서 Deck 6~7의 중앙 복도 연기 도달 예측.
- 행동 엔진(220): Deck 5의 재실자 450명의 초기 이동 패턴을 Social Force Model로 분석. 중앙 복도 병목 예상 지점 3개소 식별.
- 리스크맵 생성부(300): T=2초에서 첫 번째 리스크맵 생성 완료. Deck 5 엔진룸 부근 R≥0.9, 인접 복도 R=0.6~0.8.

### 4.4 우선구조 대피 수행

- T=3초: 우선구조 디바이스(120) 소지자 600명의 우선구조 점수 산출 완료
- Deck 5에 위치한 우선구조 대상 35명에 대해 즉시 우선 대피 경로 생성
- 보호자-취약자 쌍 180쌍에 대해 합류 지점 산출 및 동기화 경로 생성
- 휠체어 사용 장애인 50명에 대해 엘리베이터 및 경사로 경유 경로 할당

### 4.5 대피 결과 (시뮬레이션)

- 전체 대피 완료: T+18분 (종래 시스템 대비 약 35% 단축)
- 우선구조 대상 대피 완료: T+12분 (일반 대피자 평균 대비 약 6분 조기 완료)
- 경로 재계산 발생: 평균 4.2회/인
- 병목 지점 동적 우회: 12개소에서 자동 경로 변경 수행

## 5. 실시예 2: 고층 빌딩 500명 화재 시나리오

본 실시예는 지상 30층, 지하 3층, 총 재실자 500명의 오피스 빌딩에서 15층 전기실에서 화재가 발생한 경우를 가정한다.

## 7. 핵심 알고리즘 의사코드

### 7.1 위험도 가중 A* 경로탐색 알고리즘

```
FUNCTION RiskWeightedAStar(start, goal, risk_map, mobility_factor):
    OPEN ← MinHeap()
    CLOSED ← Set()
    
    start.g = 0
    start.h = Heuristic(start, goal)
    start.f = start.g + start.h
    OPEN.push(start)
    
    WHILE OPEN is not empty:
        current ← OPEN.pop()   // 최소 f 값 노드
        
        IF current == goal:
            RETURN ReconstructPath(current)
        
        CLOSED.add(current)
        
        FOR EACH neighbor IN GetNeighbors(current):
            IF neighbor IN CLOSED:
                CONTINUE
            IF NOT neighbor.passable:
                CONTINUE
            
            // 이동 비용: 이동능력 계수로 보정
            move_cost = Distance(current, neighbor) / mobility_factor
            
            // 위험도 비용: 리스크맵에서 조회
            risk_cost = λ * risk_map.GetRisk(neighbor.x, neighbor.y, current_time)
            
            // 연기 가시거리 패널티
            IF risk_map.GetSmoke(neighbor.x, neighbor.y) > SMOKE_THRESHOLD:
                move_cost *= SMOKE_PENALTY_FACTOR
            
            tentative_g = current.g + move_cost + risk_cost
            
            IF tentative_g < neighbor.g:
                neighbor.parent = current
                neighbor.g = tentative_g
                neighbor.h = Heuristic(neighbor, goal)
                neighbor.f = neighbor.g + neighbor.h
                
                IF neighbor NOT IN OPEN:
                    OPEN.push(neighbor)
                ELSE:
                    OPEN.update(neighbor)
    
    RETURN NULL   // 경로 없음
```

### 7.2 우선구조 점수 산출 알고리즘

FUNCTION CalculatePriorityScore(device):
    IF device.type != PRIORITY:
        RETURN 0
    
    // 이동능력 역수 반영 (이동 어려울수록 높은 점수)
    mobility_score = α * (1.0 - device.mobility_factor)
    
    // 현재 위치 위험도 반영
    risk_score = β * risk_map.GetRisk(device.x, device.y, current_time)
    
    // 취약 유형별 가중치
    type_weights = {
        CHILD: 1.0,
        DISABLED: 0.9,
        ELDERLY: 0.8,
        PREGNANT: 0.7,
        INJURED: 0.6
    }
    type_score = γ * type_weights[device.vulnerability_type]
    
    // 대피 출구까지의 거리 반영
    distance_score = δ * NormalizedDistance(device.position, nearest_exit)
    
    RETURN mobility_score + risk_score + type_score + distance_score

FUNCTION PrioritizeRescue(all_priority_devices):
    scores = []
    FOR EACH device IN all_priority_devices:
        score = CalculatePriorityScore(device)
        scores.append((device, score))
    
    // 점수 내림차순 정렬
    scores.sort(descending=True)
    
    RETURN scores
```

### 7.3 보호자-취약자 동기화 경로 생성 알고리즘

```
FUNCTION GenerateSyncedRoute(guardian, vulnerable):
    // 1단계: 합류 지점 산출
    midpoint = FindOptimalMeetingPoint(
        guardian.position, 
        vulnerable.position,
        risk_map
    )
    
    // 2단계: 각자 합류 지점까지의 경로 생성
    guardian_to_meet = RiskWeightedAStar(
        guardian.position, midpoint, risk_map, guardian.mobility_factor
    )
    vulnerable_to_meet = RiskWeightedAStar(
        vulnerable.position, midpoint, risk_map, vulnerable.mobility_factor
    )
    
    // 3단계: 합류 후 출구까지 동일 경로 생성 (취약자 이동능력 기준)
    synced_mobility = MIN(guardian.mobility_factor, vulnerable.mobility_factor)
    meet_to_exit = RiskWeightedAStar(
        midpoint, nearest_safe_exit, risk_map, synced_mobility
    )
    
    // 4단계: 경로 동기화
    guardian_route = Concat(guardian_to_meet, meet_to_exit)
    vulnerable_route = Concat(vulnerable_to_meet, meet_to_exit)
    
    // 보호자 경로에 대기 시간 삽입 (취약자 합류 대기)
    guardian_wait = EstimateArrivalDifference(guardian_to_meet, vulnerable_to_meet)
    IF guardian_wait > 0:
        InsertWaitAtMeetingPoint(guardian_route, guardian_wait)
    
    RETURN (guardian_route, vulnerable_route)
```

## 7. 소방관 최적 배치 추천 시스템 (도면 6 참조)

### 7.1 소방관 배치 위치 결정 알고리즘

본 발명의 의사결정 엔진(230)은 동적 리스크맵에 기반하여 재실자의 대피 경로 산출과 동시에, **소방관의 최적 배치 위치를 AI로 추천하는 기능**을 포함한다.

상기 소방관 배치 위치 결정은 다음의 위치 점수 함수(Position Score Function)에 의해 산출된다:

```
Position Score = Upwind(40) + ExitAccess(30) 
                - PassengerBlock(5×N) + MultiFireCover(10) 
                - FFOverlap(20) + CorridorBonus(15)
```

여기서 각 항의 의미는 다음과 같다:

**1) Upwind(40점)**: 바람 방향 분석을 통해 화재 발원지의 상풍(상부 풍상) 방향에 접근하는 위치에 40점을 부여한다. 이는 소방관이 연기를 회피하면서 화재에 접근 가능하도록 함으로써, 호흡 장애 및 시야 차폐로 인한 진입 방해를 최소화한다.

**2) ExitAccess(30점)**: 건물의 대피 출구와 인접한 위치에 30점을 부여한다. 소방관의 초기 진입 거리 단축뿐만 아니라, 화재 진행에 따른 재배치 시 신속하게 위치를 변경하여 추가 화재 지점으로 이동 가능하도록 한다.

**3) PassengerBlock(5×N 감점)**: 해당 배치 위치의 8방향 근처에서 대피 중인 승객 수(N)를 계산하여, 5점×N만큼 점수를 감점한다. 이를 통해 소방관과 승객의 진행 경로 충돌을 최소화하여, 소방관의 진입 방해 및 승객의 대피 지연을 방지한다.

**4) MultiFireCover(10점 보너스)**: 하나의 배치 위치에서 인접한 복수의 화재 지점을 동시에 대응 가능한 경우, 10점의 보너스를 부여한다. 이는 제한된 소방관 인력으로 여러 화재를 동시 대응할 때의 효율성을 극대화한다.

**5) FFOverlap(20점 감점)**: 이미 배치된 다른 소방관과의 위치 중복을 방지하기 위해 20점을 감점한다. 이를 통해 소방관들이 분산 배치되어 화재 현장 전체를 효과적으로 커버하도록 한다.

**6) CorridorBonus(15점 보너스)**: 건물의 복도(Corridor)와 같이 승객과 소방관의 이동 공간이 분리되는 위치에 15점의 보너스를 부여한다. 복도 위치는 소방관의 직진 이동을 가능하게 하고 승객과의 간섭을 최소화한다.

### 7.2 소방관 전용 경로 탐색 알고리즘

일반 승객의 경로 탐색(findPath)과 달리, 본 발명은 소방관 전용의 특화된 경로 탐색 알고리즘(findPathFirefighter)을 제공한다:

```
FUNCTION findPathFirefighter(start, target, grid)
    // 소방관은 화재 위험을 회피하지 않고 직진 접근
    // fireDangerAt 비용을 무시하고 순수 최단 거리(A* 알고리즘) 추적
    
    openSet = MinHeap()
    openSet.add(start)
    cameFrom = {}
    gScore = {start: 0}
    fScore = {start: heuristic(start, target)}
    
    WHILE openSet is not empty:
        current = openSet.extractMin()
        
        IF current == target:
            RETURN reconstructPath(cameFrom, current)
        
        FOR neighbor IN getNeighbors(current, grid):
            // 화재 회피 비용을 무시하고 순수 거리만 사용
            tentative_gScore = gScore[current] + distance(current, neighbor)
            
            IF tentative_gScore < gScore.get(neighbor, INF):
                cameFrom[neighbor] = current
                gScore[neighbor] = tentative_gScore
                fScore[neighbor] = gScore[neighbor] + heuristic(neighbor, target)
                
                IF neighbor not IN openSet:
                    openSet.add(neighbor)
    
    RETURN null  // 경로 없음
END FUNCTION
```

상기 알고리즘의 핵심은, 일반 경로 탐색에서 사용되는 fireDangerAt(x,y) 비용을 **무시**함으로써, 소방관이 화재 방향으로 직진 진입할 수 있도록 한다. 이는 소방관의 화재 대응 특성상 화재를 회피하지 않는다는 현실적 특성을 반영한 것이다.

### 7.3 복수 화재 상황의 우선순위 산정

다중 화재가 동시 발생한 경우, 제한된 소방관 인력의 투입 순서를 결정하기 위해 다음의 **우선순위 점수(Priority Score, PS)** 함수를 사용한다:

```
Priority Score = PassengersInFire×100 
               + BlockedPassengers×30 
               + PassengersInSmoke×15 
               + ExitBlocked×40 
               + FireSize×2 
               - FFAssigned×80
```

여기서 각 항의 의미는 다음과 같다:

**1) PassengersInFire×100**: 화염에 직접 노출된 승객 수에 100의 높은 가중치를 부여한다. 즉시 생명 위협에 처한 인원이 가장 높은 우선순위를 갖는다.

**2) BlockedPassengers×30**: 대피 출구가 차단되어 탈출이 불가능한 승객 수에 30의 가중치를 부여한다. 출구 차단으로 인한 고착 상태는 시간이 경과할수록 위험도가 높아지므로 높은 우선도를 갖는다.

**3) PassengersInSmoke×15**: 연기에 노출된 승객 수에 15의 가중치를 부여한다. 연기는 화염보다 빨리 확산되므로 중기적 위험 요인이다.

**4) ExitBlocked×40**: 해당 화재 지점의 대피 출구가 완전히 차단된 정도(0~1)에 40의 가중치를 부여한다. 출구 차단은 승객의 탈출 경로를 원천 차단하므로 높은 위험도 지표이다.

**5) FireSize×2**: 화염의 확산 크기(면적) 또는 강도에 2의 가중치를 부여한다. 화염 크기는 장기적 화재 진행의 지표이다.

**6) FFAssigned×80 (감점)**: 이미 배치된 소방관 수에 80의 높은 감점을 부여한다. 이미 소방관이 투입된 화재 지점에 중복 투입을 방지하여, 제한된 인력을 여러 지점에 분산 배치하도록 한다.

### 7.4 소방관 배치 위치의 실시간 갱신

본 발명의 시스템은 매 시간 단계(time step)마다 화재 상황의 변화에 따라 소방관의 배치 위치를 실시간으로 재산정한다:

1. **동적 위험도 맵 갱신**: 예측 AI 엔진이 다음 시간 단계의 화염(F), 연기(S) 분포를 예측
2. **새로운 화재 지점 식별**: 기존 화재 지점의 확산 및 새로운 화재 발생 감지
3. **각 화재 지점별 우선순위 재산정**: 위의 PS 함수에 따른 우선순위 점수 갱신
4. **각 화재별 최적 배치 위치 재산정**: 위치 점수 함수에 따른 최적 배치 위치 재계산
5. **소방관에게 신규 배치 명령 전달**: 기존 배치 위치 대비 변동사항을 현장 지휘관에게 즉시 전달

이러한 동적 갱신을 통해, 화재 확산에 따른 상황 변화에 신속하게 대응하며, 소방관의 배치 효율성을 지속적으로 최적화한다.

### 7.5 시각화 및 현장 지휘 인터페이스

본 발명은 AI가 추천하는 소방관 배치 위치를 다음과 같이 시각화하여 현장 지휘관의 신속한 의사결정을 지원한다:

**1) 보라색 펄스 십자 마커(Purple Pulsing Cross Mark)**: 시뮬레이션 캔버스 상의 추천 위치를 명확하게 표시. 점멸(Pulsing) 효과로 시간 경과에 따른 위치 변경을 시각적으로 강조하여, 지휘관이 실시간 상황 변화를 직관적으로 파악 가능.

**2) 8방향 접근 분석 시각화**: 추천 위치에서 북(N), 북동(NE), 동(E), 남동(SE), 남(S), 남서(SW), 서(W), 북서(NW)의 8개 방향 각각에 대해:
   - 접근 가능 여부 (차단/통행 가능)
   - 위험도 수준 (높음/중간/낮음)을 색상 그래디언트로 표시
   - 예상 진입 시간
   
**3) AI 판단 이유 텍스트**: 캔버스 하단의 텍스트 패널에 AI의 의사결정 과정을 실시간으로 표시:
   - "상풍 접근 ✓ (Upwind: +40점)"
   - "출구 근접 ✓ (ExitAccess: +30점)"
   - "승객 비간섭 (PassengerBlock: 감점 미적용)"
   - "복수 화재 커버 ✓ (MultiFireCover: +10점 보너스)"
   - "기존 소방관 중복 없음 (FFOverlap: 감점 미적용)"
   - "복도 위치 우선 ✓ (CorridorBonus: +15점)"
   - "**최종 위치 점수: 125점**"

이러한 투명한 의사결정 표시를 통해, 현장 지휘관은 AI 추천의 근거를 신뢰하고 신속히 실행할 수 있다.
