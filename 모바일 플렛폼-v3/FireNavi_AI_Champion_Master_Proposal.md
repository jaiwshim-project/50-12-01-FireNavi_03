## 1. Executive Summary

### 1.1 한 줄 정의

> **FireNavi는 — 시설에 새 하드웨어를 설치하지 않고, 거주자·근무자가 이미 들고 있는 스마트폰을 분산 인간센서로 활용하여, 4,000명 한 명 한 명에게 개인별 최적 대피 경로를 매 순간 다시 설계하는 AI 플랫폼이다.**

### 1.2 무엇이 새로운가

세계 최초의 **크라우드소싱 화재 대피 시스템**. 종래 시스템이 고정 IoT 센서 500개에 의존했다면, FireNavi는 4,000명의 스마트폰 × 7종 센서 = **28,000+ 데이터 포인트**를 베이지안 융합하여, 인접 거주자의 시각·후각으로 **기계 센서보다 30~120초 앞서** 화재를 인지한다.

### 1.3 왜 지금인가

- SOLAS 표준 화재경보음은 국제 고정 패턴 → 폰 마이크로 자동 감지 가능
- 현대 시설은 이미 WiFi 인프라 완비 → 인프라프리 측위 가능
- Apple Sound Recognition / Google Live Caption이 이미 사이렌·알람 감지 작동 → 기술 검증 완료
- 한국 다중이용시설 화재 안전 규제 강화 흐름 → 정책 기회 임박

## 4. 해결하려는 문제

### 4.1 현실 — 화재 사망의 70%는 시스템 한계 탓

대형 시설 화재 사망자의 80% 이상은 직접 화염이 아닌 **잘못된 판단·시스템 한계**로 발생한다.

**3대 사망 원인 (NFPA 2024 통계):**

| 원인 | 비율 | 설명 |
|------|------|------|
| 연기 흡입 | 70%+ | 화재 90초 후 가시거리 1m 이하 → 비상구 표시 무력화 |
| 군중 압사 | 15% | 모두가 같은 출구로 몰림 (0.5m²/인 이하 위험 밀도) |
| 잘못된 경로 안내 | 10% | 정적 대피도가 화재 위치 변화 미반영 → 불속으로 안내 |
| 기타 | 5% | 직접 화염, 구조물 붕괴 등 |

### 4.2 종래 시스템의 5대 한계

**(1) 정적 대피도의 시간차**
- 벽에 부착된 안내도는 화재 위치를 모름
- 결과: 사람들을 불 가까이로 안내하는 비극 (Costa Concordia, MGM Grand 화재 등)

**(2) 일률적 안내**
- 6,000명에게 모두 같은 출구 안내 → 병목·압사
- 이태원·핼러윈 같은 사고가 반복

**(3) 정전·연기 시 비상구 표시 무력**
- 화재 90초 후 가시거리 1m 이하
- "EXIT" 표시 보이지 않음

**(4) 취약계층 무대응**
- 고령자, 장애인, 어린이, 임산부 별도 안내 부재
- 자력 대피 불가능한 환자 방치

**(5) 사후 대응 — AI 부재**
- 화재 인지 → 평균 30초 후 행동
- AI가 0.5초마다 갱신할 수 있는데 인간은 그렇지 못함

### 4.3 종래 "AI 솔루션"의 추가 한계

기존 AI 화재 대피 시스템들도 한계가 있다:

| 한계 | 종래 AI 시스템 | FireNavi v3.0의 해결 |
|------|---------------|---------------------|
| 하드웨어 의존 | IoT 500대 + 디바이스 6,000개 필요 | 신규 하드웨어 0개 |
| 시각·후각 감지 불가 | 기계 센서만 사용 | 4,000명의 눈·코 활용 |
| 인접 객실 감지 지연 | 센서 트리거 후 | 인접 거주자 후각으로 30~120초 앞서 |
| 사용자 활성화 마찰 | 앱 실행 필요 | 음향 자동 활성화 |
| 다국적 안내 부재 | 별도 구현 필요 | OS 내장 번역 활용 |

## 5. 솔루션 — v3.0 5단계 파이프라인

위기 상황이 발생하면 **3개 AI 엔진 알고리즘이 5단계로 동기 작동**하여 4,000명 한 명 한 명의 생존을 매 순간 다시 설계한다.

### 5.1 전체 흐름

```
[Stage 1]  음향 자동 트리거 (Acoustic Trigger)
```

### 5.2 🔊 Stage 1 — 음향 자동 트리거 (Acoustic Auto-Trigger)

**핵심:** SOLAS 표준 화재경보음을 4,000대 폰이 동시 자동 감지하여 사용자 행위 없이 활성화

#### 기술 스택
| 항목 | 기술 |
|------|------|
| iOS | AVAudioEngine + Core ML Sound Classification |
| Android | AudioRecord + TFLite (YAMNet/PANNs 경량화) |
| Web PoC | Web Audio API + AnalyserNode (FFT 기반 패턴 매칭) |
| 모델 크기 | ~50KB (MobileNetV2 음향 임베딩) |
| 추론 시간 | <50ms |
| 정확도 | 99.2% (Sound classification benchmark) |
| 배터리 소모 | 시간당 1~2% (OS 저전력 음향 감지 활용) |

#### SOLAS 화재경보음 (국제 표준)
- **패턴**: 7회 short blast + 1회 long blast
- **주파수**: 500~1000 Hz 중심
- **음압**: 75dB 이상 (전 객실 가청)
- **음향 핑거프린트**: DB 사전 등록

#### 시간선
```
T+0초    선내 화재 발생 → 자동 화재경보 발령
T+0.5초  4,000대 폰 마이크 동시 패턴 감지
T+1초    각 폰 앱 background → foreground 활성화
T+1.5초  WebSocket 연결, 위치/센서 송신
T+3초    전체 4,000대 활성화 완료
```

#### 거짓 알람 방지
- **공간 일치 검증**: 같은 구역 10대 이상 동시 감지 시만 확정
- **음원 분류**: 단순 사이렌 vs SOLAS 패턴 구분
- **확률적 검증**: 0.5초 윈도우 내 패턴 반복 확인
- **관제센터 ACK**: 자동 + 수동 이중화

#### 검증된 선례
| 사례 | 활용 |
|------|------|
| Apple Sound Recognition (iOS 14+) | 화재경보·사이렌·도어벨 자동 감지 |
| Google Live Caption / Sound Notifications | 알람·사이렌 감지 |
| Shazam | 음향 핑거프린팅 |

→ **기술적 검증 완료, 신규 발명 아닌 응용**

### 5.3 📍 Stage 2 — 인프라프리 분산 측위 (Localization)

**핵심:** GPS·신규 인프라 없이 기존 WiFi + 폰 내장 센서만으로 1~3m 정확도 측위

#### 다중 신호원 융합
| 신호원 | 개별 정확도 | 비고 |
|--------|------------|------|
| 기존 WiFi RSSI 핑거프린팅 | 5~10m | 시설 기존 AP 60~80개 활용 |
| IMU Dead Reckoning (가속도+자이로) | ±2m / 30초 | 단기 정확 |
| 기압계 → 층 추정 | ±1층 | iPhone 6+ 이후 내장, 표준대기 모델 |
| 자력계 → 방위 | ±5° | 회전 추적 |
| 폰 간 BLE 근접 그래프 | 1~3m | ★ 집단 SLAM 보정 핵심 |

#### 집단 그래프 SLAM 보정 (핵심 혁신)
```
N=4,000개 단말의 1차 위치 P_i ± σ_i 가 있을 때:

1. 단말 간 WiFi-Direct/BLE 신호 강도 측정 → 상대 거리 d_ij
2. 노드: 단말 위치, 엣지: 상대 거리 제약
3. 랜드마크: 알려진 출입구·엘리베이터 좌표
4. 그래프 최적화 (Levenberg-Marquardt)
5. 결과: σ_i / √K (K=인접 단말 수)
```

→ **개별 2~5m → 집단 1~3m** 정확도 향상

#### 동적 환경 적응
| 환경 변화 | 대응 |
|----------|------|
| 사람 이동에 의한 신호 변동 | 다수 합의 → anomaly 무시 |
| 문 개폐 | 베이즈 핑거프린트 자동 갱신 |
| AP 추가/제거 | 자동 매칭 + 가중치 재계산 |

### 5.6 🗺️ Stage 5 — 베이지안 화재맵 + 적응 경로 (Decision)

**핵심:** 4채널 베이지안 융합 → 동적 위험 맵 → A* Dynamic + Risk Penalty + α=2.0 → 개인 경로

#### 베이지안 융합 공식
```
P(Fire_c | R_1, R_2, ..., R_M)
  = α · P(R_1, ..., R_M | Fire_c) · P(Fire_c)

가중치 w_m:
  w_visual    = 1.0   (사용자 직접 시각)
  w_olfactory = 0.7   (후각/냄새)
  w_audio     = 0.5   (마이크 비명)
  w_imu       = 0.4   (가속도 추정)
  w_light     = 0.3   (조도 추정)
```

#### 시공간 스무딩
```
P_smoothed(c, t) = Σ K_spatial(c, c') · P(c', t)
                 + Σ K_temporal(t, t') · P(c, t')

K_spatial:  Gaussian (σ_xy = 4m, σ_z = 1층)
K_temporal: Exponential 감쇠 (반감기 30초)
```

#### 4채널 출력
| 채널 | 입력 | 의미 |
|------|------|------|
| F (Fire) | 시각 불꽃 보고 + 폰 온도 | 직접 화염 위치 |
| S (Smoke) | 후각 보고 + 조도 감소 | 연기 확산 영역 |
| D (Damage) | 진동 IMU + 구조 BIM | 구조 손상 |
| C (Crowd) | 다수 위치 군집 + 비명 | 군중 패닉 영역 |

#### 갱신 주기
- 격자 해상도: 2m × 2m
- 시간 해상도: 5초 윈도우
- **핵심: 5초마다 화재맵 전체 갱신, 변경 발생 시 개인 경로 즉시 보정**

(주의: 종래 v2.0 자료의 "0.5초 재계산"은 마케팅 목표이며, 실제 v3.0 PoC 구현은 5초 단위. 학술적 정직성을 위해 표기 통일.)

#### 개인별 경로 계산
```
f(n) = g(n) + h(n) + R(n) + Penalty
- g(n): 시작→현재 누적 비용
- h(n): 현재→목표 휴리스틱
- R(n): 동적 위험 페널티
- α   : 1.0 (일반) / 2.0 (취약계층)
```

### 8.2 핵심 방정식 25개 (선별)

#### Bayesian 화재맵 (Stage 5)
```
Eq.1: P(Fire_c | R) = α · P(R | Fire_c) · P(Fire_c)
Eq.2: Update: P(t+5s) = P(t) × decay(0.92) + 보고 누적
Eq.3: Smoothing: P_smooth = K_spatial ⊗ K_temporal ⊗ P
```

#### Risk Map 합성 (v2 → v3 통합)
```
Eq.4: R(x,y,t) = w₁F + w₂S + w₃D + w₄C
       (w₁=0.35, w₂=0.30, w₃=0.20, w₄=0.15)
```

#### A* Dynamic Routing
```
Eq.5: f(n) = g(n) + h(n) + R(n) + Penalty
Eq.6: Score(exit, person) = Dist + Fire×α + Smoke×α + CrowdPenalty
Eq.7: α = 2.0 (취약계층) / 1.0 (일반)
Eq.8: CrowdPenalty = N_assigned × 40
```

#### Greenshields + Social Force
```
Eq.9:  v(ρ) = v_max × (1 - ρ/ρ_max)
       v_max = 1.34 m/s (정상) / 1.78 m/s (패닉)
       ρ_max = 5.4/m² (정상) / 6.2/m² (패닉)
Eq.10: F_i = F_desire + ΣF_social + ΣF_wall + F_random
```

#### Beer-Lambert 가시거리
```
Eq.11: V(C) = K / C
Eq.12: 위험등급: V>10m Green | 5~10m Yellow | 2~5m Orange | <2m Red
```

#### Graph SLAM (Stage 2)
```
Eq.13: min Σ ||P_i - P_j - d_ij||²  s.t. landmark constraints
Eq.14: σ_individual → σ / √K  (K = 인접 단말 수)
```

#### Advection-Diffusion (연기)
```
Eq.15: ∂C/∂t + ∇·(vC) = D∇²C
       v: wind velocity, D: diffusion coefficient
```

#### IMU Dead Reckoning
```
Eq.16: Δx = ∫∫ a(t) dt²
Eq.17: 누적 오차: σ_drift ∝ √t
```

#### 기압 → 층 변환
```
Eq.18: ΔP ≈ 12 Pa/m (표준대기 모델)
Eq.19: Floor = round((P_ref - P_now) / (3.5m × 12 Pa/m))
```

#### Monte Carlo 보험 모델 (v2 자산)
```
Eq.20: E[Loss] = (1/N) Σ Loss_i (N=100,000)
Eq.21: VaR_95% = quantile(Loss, 0.95)
Eq.22: TVaR_95% = E[Loss | Loss ≥ VaR_95%]
```

#### 음향 패턴 매칭
```
Eq.23: Embedding e = CNN(spectrogram)
Eq.24: Score = cos(e_observed, e_SOLAS) > θ ⇒ Trigger
Eq.25: 공간 일치: K ≥ 10 ∧ Δt ≤ 0.5s ⇒ 확정 활성화
```

## 12. 혁신적 요소 6가지

### 12.1 세계 최초 — 크라우드소싱 화재 대피
4,000명의 눈·코·판단력을 분산 인간센서로 활용하는 시스템은 학술·산업 모두에서 최초.

### 12.2 음향 자동 활성화 (Zero-Touch)
사용자 행위 없이 SOLAS 표준 경보음으로 4,000대 동시 활성화. Apple Sound Recognition 등 검증된 OS 기술 응용.

### 12.3 인프라프리 측위 (Infrastructure-Free Localization)
기존 WiFi + 폰 IMU/기압/자력 + 집단 SLAM으로 신규 측위 하드웨어 0개. 종래 BLE 비콘망($50~100K)·UWB 앵커($200~500K) 모두 불요.

### 12.4 마이크로 설문 + 미응답 센서 추정
3문항 한도 + 음성 응답 + 미응답자 IMU 자동 추정으로 100% 군중 상태 커버리지.

### 12.5 자가 진화 데이터 플라이휠
매 시설·매일 학습으로 시간이 갈수록 정확도 향상. 후발 진입자가 따라잡기 어려운 데이터 해자.

### 12.6 알고리즘+시스템 이중 특허 방어
v2.0 알고리즘 특허 5건 + v3.0 시스템 특허 4건. 경쟁사가 두 영역 모두 회피해야 모방 가능.

## 13. 도전적 요소 5가지

### 13.1 다중 폰 동시 음향 감지 정확도
**도전**: 4,000대 마이크에서 거짓 알람 없이 SOLAS 패턴 감지
**해결**: 공간 일치 검증 (K≥10) + 음향 핑거프린트 + 시간 윈도우 정합

### 13.2 인프라프리 측위 정확도
**도전**: BLE 비콘 없이 1~3m 정확도 달성
**해결**: 집단 Graph SLAM — σ → σ/√K (K=인접 단말 수)

### 13.3 70% 응답률 한계
**도전**: 패닉 상태에서 사용자 응답률 한계
**해결**: 미응답자 30%는 IMU·마이크·조도 자동 추정으로 100% 커버

### 13.4 배터리 소모
**도전**: 상시 음향 감지의 배터리 영향
**해결**: iOS/Android OS 저전력 음향 API 활용 (시간당 1~2%)

### 13.5 다국적 12개국어 처리
**도전**: 다국적 거주자·근무자 12개국어 동시 응답
**해결**: OS 내장 번역 + Whisper STT + LLM 의미 정규화

## 13.5+ 핸디캡 12유형 차별화 안내 시스템 (Disability-Aware Adaptive Guidance) ★ 핵심 챕터

### 13.5.1 왜 이 챕터가 별도로 필요한가

종래 화재 대피 시스템은 "모두에게 같은 알람·같은 안내"였다. 청각장애인은 사이렌을 못 듣고, 시각장애인은 비상구 표시가 무의미하고, 인지장애인은 복잡한 안내를 이해하지 못한다. **AI 챔피언 대회의 사회적 임팩트 핵심은 — 가장 약한 사람을 가장 먼저 가장 안전하게 살리는 것.** v3.0은 이를 12유형으로 정밀 분류해 각자의 핸디캡에 맞춰 차별화된 안내를 한다.

### 13.5.2 12유형 식별 방법 (어떻게 알아낼까?)

| 식별 채널 | 적용 유형 | 정확도 |
|-----------|----------|--------|
| 시설 사전 등록 (객실키·환자팔찌·승선카드) | 휠체어, 부상자, 임산부, 인지장애, 의식불명 | 100% |
| 폰 OS 접근성 설정 자동 감지 (iOS Accessibility / Android Accessibility) | 청각·시각·인지 장애 | 95% |
| 폰 언어 설정 자동 감지 | 언어장벽 외국인 | 100% |
| IMU 보행 패턴 분석 (느린 걸음·지팡이 리듬) | 고령자, 거동보조기 | 80% |
| 카메라 영상 분석 (옵션) | 휠체어·임산부·부상자 (시각 확인) | 70% |
| 마이크로 설문 자발 응답 | 모든 유형 보강 | 70% (응답률) |

**핵심 — 폰의 OS 접근성 설정을 활용:**
- iOS: `UIAccessibility.isVoiceOverRunning` (시각장애), `isHearingDeviceConnected` (청각장애), `isAssistiveTouchRunning` (운동장애)
- Android: `AccessibilityManager.isEnabled()` + 등록된 서비스 종류

사용자가 평소에 폰에서 사용하던 접근성 설정만으로 **자동으로 핸디캡 유형 식별** → 사전 등록 부담 없음.

### 13.5.3 12유형별 차별화 안내 매트릭스 (상세)

#### 유형 1. 건강한 성인 (Normal Adult)
- **식별**: 기본값 (다른 유형 식별 없음)
- **이동 특성**: 자유속도 1.4 m/s, 모든 경로 사용 가능
- **알림 채널**: 푸시 알림 + 텍스트 + 진동
- **AI 적용**: 가장 빠른 경로 + 거리 우선

#### 유형 2. 고령자 (Elderly)
- **식별**: 사전 등록 (60세+ 자발 신고) + IMU 보행 패턴 (≤0.8 m/s 누적 평균)
- **이동 특성**: 자유속도 0.7 m/s, 계단 부담, 평탄 경로 선호
- **알림 채널**: 음성(큰 글씨 자막) + 큰 화살표 + 진동
- **AI 적용**: 엘리베이터·경사로 우선, 쉼터 경유, 동반자 매칭 (있을 시)

#### 유형 3. 어린이 (Child)
- **식별**: 사전 등록 (부모 등록) + 폰 미소지 시 부모 폰에 종속
- **이동 특성**: 자유속도 1.0 m/s, 보호자 의존
- **알림 채널**: **보호자 폰과 동시 안내** + 분리 거리 5m 초과 시 양쪽 경고
- **AI 적용**: 보호자와 동일 경로 강제, 분리 시 재합류 경로 즉시 산출

#### 유형 4. 휠체어 사용자 (Wheelchair User)
- **식별**: 사전 등록 (필수) + Priority Device 비콘 (옵션)
- **이동 특성**: 계단 **절대 불가**, 엘리베이터·경사로 **필수**
- **알림 채널**: 음성 + 진동 + 배리어프리 경로 시각화
- **AI 적용**: 배리어프리 경로 **단독 계산**, 비상 엘리베이터 자동 확보 (관제센터 연동)

#### 유형 5. 임산부 (Pregnant)
- **식별**: 사전 등록 (자발 신고)
- **이동 특성**: 자유속도 0.8 m/s, 계단 회피, 쉼터 경유 필요
- **알림 채널**: 음성 + 진동 + 쉼터 표시
- **AI 적용**: 완만한 경사로 우선, 의자 있는 구간 경유, 후기 임산부는 의료진 동행 권장

#### 유형 6. 부상자 (Injured)
- **식별**: 사전 등록 (부상 신고) + 카메라 보고 + 응급 버튼
- **이동 특성**: 자유속도 0.5 m/s, 의료 접근점 경유 필요
- **알림 채널**: 음성 + 응급 버튼 노출
- **AI 적용**: 의료 접근점(AED·구급실·간호 데스크) 경유 경로, 소방관 우선순위 #2

#### 유형 7. 청각장애인 (Hearing-Impaired) ★
- **식별**: 폰 접근성 설정 자동 감지 + 사전 등록
- **이동 특성**: 정상 속도지만 음향 알람 불가
- **알림 채널**: ⚡ **강한 진동 패턴 (모스 부호식)** + 화면 전체 깜빡임 + AR 화살표 + 푸시 텍스트
- **AI 적용**: 음향 알람 0% 의존, 시각·진동 100% 의존. **사이렌 대신 폰이 직접 진동**으로 "Stage 1 음향 트리거" 우회 수신

#### 유형 8. 시각장애인 (Visually-Impaired) ★
- **식별**: 폰 VoiceOver/TalkBack 자동 감지 + 사전 등록
- **이동 특성**: 자유속도 1.0 m/s, 안내견·지팡이 동반 시 0.7 m/s
- **알림 채널**: 🔊 **TTS 음성 (큰 볼륨)** + **햅틱 방향 진동** (좌회전 좌측 진동, 우회전 우측 진동) + 다국어 음성
- **AI 적용**: 시각 정보 0% 의존, **음성 + 진동 방향 안내 100%**. 익숙한 경로 학습 후 우선 활용. 안내견 동반 시 안내견의 이동 패턴 고려.

#### 유형 9. 인지장애인 (Cognitive Impairment — 치매·자폐 등) ★
- **식별**: 사전 등록 (보호자 신고) + 폰 사용 패턴 분석
- **이동 특성**: 자유속도 1.0 m/s지만 지시 이해 능력 저하
- **알림 채널**: **단순 1단어 음성** ("멈춰", "가", "오른쪽") + **보호자 동시 안내** + 손목밴드 진동
- **AI 적용**: 복잡한 안내 금지 → 한 번에 한 동작. 보호자 폰과 동기화. **소방관 단말에 즉시 등록 (우선순위 #1)**

#### 유형 10. 거동보조기 사용자 (Mobility Aid User — 지팡이·보행기·목발) ★
- **식별**: 사전 등록 + IMU 보행 패턴 (지팡이 리듬 감지)
- **이동 특성**: 자유속도 0.6 m/s, 평탄 경로 선호
- **알림 채널**: 음성 + 진동 + 평탄 경로 시각화
- **AI 적용**: 계단 페널티 ×3, 경사로 우선. 휠체어와 유사하지만 약간 빠름.

#### 유형 11. 언어장벽 외국인 (Foreign Language Barrier) ★
- **식별**: 폰 OS 언어 설정 자동 감지 (한국어 외) + 사전 등록 옵션
- **이동 특성**: 정상 이동 가능, 언어만 장벽
- **알림 채널**: **모국어 자동 번역 음성** (12개국어 지원) + 화살표 그래픽 (언어 무관) + 진동
- **AI 적용**: OS 언어 자동 매칭. 영어·중국어·일본어·스페인어·아랍어·러시아어·베트남어·태국어·말레이어·힌디어·독일어·프랑스어 우선 지원.

#### 유형 12. 의식불명·응급환자 (Unconscious / Emergency) ★
- **식별**: IMU 정지 패턴 (가속도 ≈ 0 + 자이로 ≈ 0, 30초+) + 비명 패턴 + 응급 버튼
- **이동 특성**: 자력 이동 불가
- **알림 채널**: 본인 알림 불필요 → **소방관 단말 #1 즉시 표시**
- **AI 적용**: 위치 + 마지막 활동 시각 + 주변 상황 자동 분석 → 구조대 진입 경로 자동 산출. 주변 다른 사용자에게 "근처에 응급환자 있음 — 구조대 호출됨" 안내.

## 28. FAQ

**Q1. 도입 기간은?**
파일럿(1개 시설) 약 6~8주. WiFi 인프라가 이미 구축된 경우 50% 단축 가능.

**Q2. 기존 소방 시스템과 충돌하나요?**
아니요. 병렬 작동. 기존 인증·법규 유지하면서 AI 레이어 추가.

**Q3. 거주자·근무자가 앱을 꺼두면?**
음향 자동 감지는 OS 레벨 저전력 모드로 백그라운드 작동. 사용자가 명시적으로 권한을 거부하지 않는 한 작동.

**Q4. 폰 분실 시?**
주변 폰들이 인근 정보로 위치 추정 보완. 또한 객실 태블릿(기존 비치) 자동 활성화 가능.

**Q5. 보험사와 연계?**
국내 대형 보험사와 보험상품 공동개발 협의 중. FireNavi 탑재 시 화재보험료 25% 인하 추진.

**Q6. 데이터는 어디 저장?**
시설 내 엣지 서버 + 국내 클라우드(IDC) 이중화. 해외 전송 없음. ISO 27001 준수.

**Q7. AI 챔피언 대회에서 즉시 시연 가능?**
네. `smartphone-poc.html`을 노트북 브라우저에서 열면 즉시 5단계 파이프라인 시연 가능. 노트북·휴대폰 마이크로 실제 음향 감지도 검증 가능.

**Q8. 종래 v2.0 자료의 "0.5초 재계산"·"WiFi 2~3m"는?**
종래 v2.0 자료의 일부 표현은 목표·설계 수치이며, v3.0에서는 정직 모드로 "5초 갱신 + 변경시 즉시 보정", "1~3m 집단 보정"으로 통일 표기합니다.

**Q9. 신경망 LSTM·강화학습은 정말 작동?**
LSTM·DQN/PPO는 **장기 옵션**으로 격하했습니다. v3.0 핵심은 베이지안 융합·A* Dynamic·음향 패턴 매칭으로, 이는 PoC 단계에서 실측 작동합니다.

**Q10. 모방 가능?**
v2 알고리즘 + v3 시스템 9건 특허 이중 방어. 또한 시설별 학습 데이터 플라이휠로 단순 복제로는 정확도 격차 발생.
