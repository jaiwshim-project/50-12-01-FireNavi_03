## 1. Google (Alphabet Inc.)

### 1-1. 주요 특허

#### US 10,354,529 B2 (2019)
**"Audio event detection for alarm sounds"**

- **핵심 내용**: 스마트홈 장치가 화재경보음·유리 파손음을 감지하여 사용자에게 푸시 알림 전송
- **기술 구조**: 고정 센서 (Google Nest) → 클라우드 서버 → 스마트폰 알림
- **활용 분야**: 홈 보안

**FireNavi와의 차이**:
| 항목 | Google | FireNavi |
|------|--------|----------|
| 감지 장치 | 고정 센서 (Nest) | **스마트폰 마이크 (로컬)** |
| 처리 방식 | 클라우드 서버 | **로컬 + 엣지** |
| 후속 조치 | 푸시 알림만 | **대피 모드 자동 활성화** |
| 온톨로지 | 없음 | **음향 이벤트 노드 매핑** |
| 네트워크 의존 | 필수 | **독립 작동 가능** |

**회피 전략**: 스마트폰 로컬 감지 + 온톨로지 매핑 강조

#### US 10,098,019 B2 (2018)
**"Indoor positioning using WiFi and inertial sensors"**

- **핵심 내용**: WiFi RSSI + IMU를 이용한 실내 위치 추정
- **출력 형식**: 좌표 (x, y, floor)
- **활용 분야**: Google Maps 실내 내비게이션

**FireNavi와의 차이**:
| 항목 | Google | FireNavi |
|------|--------|----------|
| 출력 | 좌표만 | **공간 온톨로지 노드** |
| 의미 | 없음 | **층·복도·계단·출구·피난구역** |
| 목적 | 일반 길찾기 | **재난 대피 의사결정** |
| 경로 연동 | 최단 거리 | **위험도 기반 경로 제외** |

**회피 전략**: 좌표를 "대피 의미 공간"으로 변환하는 온톨로지 매핑 강조

- FireNavi는 온톨로지 지식그래프 기반
- **청구항**: "재난대피 온톨로지 지식그래프를 이용한..."

### 2차 방어선: 통합 수준
- 경쟁사는 개별 기능 독립 작동
- FireNavi는 음향·측위·센서·AI를 온톨로지로 통합
- **청구항**: "사용자 온톨로지, 위험 온톨로지, 공간 온톨로지를 통합하여..."

### 3차 방어선: 설명 가능성
- 경쟁사는 블랙박스 출력
- FireNavi는 추천 사유 자연어 생성
- **청구항**: "추천 경로와 추천 사유를 온톨로지 관계 기반으로 생성하는..."

## 특허심사관 예상 질문 & 답변

**Q1**: "Google Nest도 화재경보음을 감지하는데, 이 특허와 어떻게 다른가?"  
**A1**: Google은 고정 센서로 감지하여 알림만 전송하지만, FireNavi는 **스마트폰 마이크로 로컬 감지**하고 **온톨로지 노드로 매핑**하여 **대피 모드를 자동 활성화**합니다. 네트워크 장애 시에도 독립 작동 가능합니다.

**Q2**: "Apple도 WiFi로 실내 위치를 추정하는데?"  
**A2**: Apple은 좌표만 제공하지만, FireNavi는 좌표를 **공간 온톨로지 노드("4층 동쪽 복도")**로 변환하고 **계단·출구 관계를 추론**하여 **재난 대피 의사결정**에 활용합니다.

**Q3**: "IBM도 크라우드소싱으로 재난 정보를 수집하는데?"  
**A3**: IBM은 텍스트만 수집하지만, FireNavi는 **센서 데이터 + 자연어 보고를 온톨로지로 통합**하고 **베이지안 융합으로 신뢰도를 평가**하며 **4채널 독립 화재맵**을 생성합니다.

**Q4**: "Panasonic도 장애인용 대피 시스템이 있는데?"  
**A4**: Panasonic은 수동 프로필 설정이지만, FireNavi는 **취약계층 온톨로지 기반 안전 마진 α를 자동 산출**하고 **보호자 동기화 경로**를 자동 생성하며 **구조 우선순위**를 구조대에 실시간 전송합니다.

## 최종 결론

### 경쟁사 대비 FireNavi의 3대 차별점

1. **온톨로지 기반 의미 체계**  
   → 경쟁사는 데이터 처리, FireNavi는 의미 이해

2. **통합 수준**  
   → 경쟁사는 개별 기능, FireNavi는 지식그래프 통합

3. **설명 가능성**  
   → 경쟁사는 블랙박스, FireNavi는 추천 사유 생성

### 특허 등록 가능성

✅ **신규성 충족**: 온톨로지 기반 접근은 경쟁사 특허에 없음  
✅ **진보성 충족**: 단순 조합이 아닌 패러다임 전환  
✅ **산업성 충족**: BTS 콘서트 6만 관객 실시간 개인별 안내 가능
