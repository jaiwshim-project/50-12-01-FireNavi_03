# 13. 도면

본 발명의 특허출원에 필요한 도면 12개의 구조와 설명문입니다.

---

## 도 1. 전체 시스템 구성도

### 목적
본 발명의 전체 시스템 구성요소와 그 관계를 나타내는 블록 다이어그램

### 도면 설명문

도 1은 본 발명에 따른 스마트폰 센서, 온톨로지 지식그래프 및 인공지능 경로 엔진을 이용한 개인별 재난 대피 경로 제공 시스템의 전체 구성도를 나타낸다.

본 발명의 시스템은 엣지 레이어(100)와 서버 레이어(200)로 구분된다.

엣지 레이어(100)는 사용자 단말(140)에서 실행되며, 외부 자극 수집부(110), 로컬 전처리부(120), 캐싱부(130)를 포함한다. 사용자 단말(140)은 센서 모듈(141)과 출력부(142)를 포함한다.

서버 레이어(200)는 온톨로지 관리부(210), 신뢰도 점수 산출부(220), 위험지도 생성부(230), 경로 추천부(240), 역할 관리부(250), 그룹 관리부(260), 관제센터 연동부(270), 구조대 연계부(280), API 연동부(290)를 포함한다.

엣지 레이어(100)와 서버 레이어(200)는 네트워크(300)를 통해 연결된다.

## 도 2. 다중 외부 자극 수집 및 신뢰도 점수 산출 흐름도

### 주요 부호 설명

- S140: 모드 결정 단계

### 도면 설명문

도 2는 본 발명에 따른 다중 외부 자극 수집부터 재난 모드 결정까지의 전체 흐름을 나타낸 플로우차트이다.

먼저 사용자 단말의 센서로부터 12종의 외부 자극을 수집한다(S110). 수집된 외부 자극은 화재경보음, 비상 음성 키워드, 비명, 폭발음, 급진동, 낙상, 조도 급감, WiFi/BLE 이상, 사용자 SOS 신고, 미응답, 선박 설비 신호, 관제센터 비상 푸시 중 적어도 하나를 포함한다.

다음으로 수집된 외부 자극을 재난 이벤트 온톨로지의 의미 노드로 매핑한다(S120). 의미 노드는 화재, 연기, 혼잡, 출구 폐쇄, 정전 등을 포함한다.

매핑된 의미 노드를 이용하여 신뢰도 점수를 산출한다(S130). 신뢰도 점수는 신호 강도, 동일 구역 발생 빈도, 시간적 연속성, 공간적 근접성, 다수 단말 일치성, 설비 신호 교차 검증을 종합하여 산출된다.

신뢰도 점수에 따라 주의 모드, 확인 모드, 대피 모드, 구조 모드 중 하나를 결정한다(S140).

온톨로지 지식그래프(210)는 사용자 온톨로지(211), 공간 온톨로지(212), 위험 온톨로지(213), 센서 온톨로지(214), 경로 온톨로지(215), 규정 온톨로지(216)를 포함한다.

사용자 온톨로지(211)는 일반 사용자, 고령자, 어린이, 휠체어 사용자, 시각장애인 등 사용자 유형과 그 특성을 포함한다.

공간 온톨로지(212)는 객실, 복도, 비상구, 계단, 피난구역 등 공간 노드와 그 연결 관계를 포함한다.

위험 온톨로지(213)는 화재, 연기, 혼잡, 출구 폐쇄 등 위험 유형과 그 확산 관계를 포함한다.

센서 온톨로지(214)는 화재감지기, 연기감지기, 스마트폰 센서, 방화문 센서 등 센서 유형과 그 감지 대상을 포함한다.

경로 온톨로지(215)는 주경로, 대체경로, 우회경로, 구조경로 등 경로 유형과 그 연결 관계를 포함한다.

규정 온톨로지(216)는 계단 사용 규정, 연기 회피 규정, 구조 우선순위 규정, 보호자 동행 규정 등을 포함한다.

각 온톨로지는 located at, affected by, detected by, avoided by, guides, complies with 등의 관계로 연결된다.

## 도 4. 위험지도 생성 및 동적 갱신 흐름도

### 목적
다중 신호 융합을 통한 실시간 위험지도 생성 과정

### 도면 구조

```
[입력 신호원]
    ↓
┌───────────────┬───────────────┬───────────────┐
│ 스마트폰 센서 │ 사용자 보고   │ 설비 신호     │
│ (S210)       │ (S220)       │ (S230)       │
└───────┬───────┴───────┬───────┴───────┬───────┘
        ↓               ↓               ↓
    ┌─────────────────────────────────────┐
    │  입력원별 신뢰도 가중치 적용 (S240)  │
    │  • 설비 신호: 0.9                  │
    │  • 사용자 보고: 0.7                │
    │  • 스마트폰 센서: 0.6              │
    └─────────────────────────────────────┘
        ↓
    ┌─────────────────────────────────────┐
    │  시간-공간 기반 융합 (S250)         │
    │  • 동일 구역 내 신호 집계           │
    │  • 시간 윈도우 내 신호 통합         │
    │  • 확산 패턴 예측                  │
    └─────────────────────────────────────┘
        ↓
    ┌─────────────────────────────────────┐
    │  동적 위험지도 생성 (S260)          │
    │  위험도 레벨 (0~10):               │
    │  • 0~2: 안전                       │
    │  • 3~5: 주의                       │
    │  • 6~8: 위험                       │
    │  • 9~10: 매우 위험                 │
    └─────────────────────────────────────┘
        ↓
    ┌─────────────────────────────────────┐
    │  위험지도 갱신 주기 (S270)          │
    │  • 주의 모드: 10초                 │
    │  • 확인 모드: 5초                  │
    │  • 대피 모드: 2초                  │
    │  • 구조 모드: 1초                  │
    └─────────────────────────────────────┘
        ↓
    [경로 추천부로 전달]
```

### 주요 부호 설명

- S210: 스마트폰 센서 신호 수집
- S220: 사용자 보고 수집
- S230: 설비 신호 수집
- S240: 입력원별 신뢰도 가중치 적용
- S250: 시간-공간 기반 융합
- S260: 동적 위험지도 생성
- S270: 위험지도 갱신 주기 설정

### 도면 설명문

도 4는 본 발명에 따른 위험지도 생성 및 동적 갱신 흐름을 나타낸다.

먼저 스마트폰 센서 신호(S210), 사용자 보고(S220), 설비 신호(S230)를 수집한다.

수집된 신호에 입력원별 신뢰도 가중치를 적용한다(S240). 설비 신호는 0.9, 사용자 보고는 0.7, 스마트폰 센서는 0.6의 가중치를 적용한다.

가중치가 적용된 신호를 시간-공간 기반으로 융합한다(S250). 동일 구역 내 신호를 집계하고, 시간 윈도우 내 신호를 통합하며, 확산 패턴을 예측한다.

융합된 신호를 기반으로 동적 위험지도를 생성한다(S260). 위험도 레벨은 0~10의 값으로 표현되며, 0~2는 안전, 3~5는 주의, 6~8은 위험, 9~10은 매우 위험으로 분류된다.

위험지도는 재난 모드에 따라 다른 주기로 갱신된다(S270). 주의 모드는 10초, 확인 모드는 5초, 대피 모드는 2초, 구조 모드는 1초 주기로 갱신된다.

## 도 5. 개인별 경로 산출 알고리즘 상세도

### 목적
사용자 상태, 위험지도, 공간 구조를 반영한 경로 비용 함수 및 A* 알고리즘 적용 과정

### 도면 구조

```
[입력 데이터]
    ↓
┌──────────────────────────────────────────────┐
│  경로 비용 함수 정의 (S310)                   │
│                                              │
│  Cost(u,v) = BaseDistance(u,v) × W_factors  │
│                                              │
│  W_factors = W_risk × W_congestion ×        │
│              W_constraint × W_margin        │
│                                              │
```

센서 데이터 수집부(111)는 마이크, 가속도계, 조도센서, WiFi/BLE 신호를 수집한다.

로컬 전처리부(112)는 음성 키워드 감지, 낙상 패턴 인식, WiFi 신호 기반 위치 추정을 로컬에서 전처리한다.

캐싱부(113)는 공간 온톨로지 일부, 대피 경로 최근 버전, 위험지도 스냅샷을 캐싱한다.

오프라인 대피 경로 표시부(114)는 네트워크가 단절된 경우 캐시된 최근 경로를 표시하고 "오프라인 모드" 경고 메시지를 출력한다.

서버 레이어(200)는 다중 단말 신호 융합부(221), 신뢰도 점수 산출부(222), 위험지도 생성부(223), 개인별 경로 산출부(224), 관제센터 연동부(225)를 포함한다.

엣지 레이어와 서버 레이어는 네트워크(300)를 통해 연결된다.

## 도 9. 대피 그룹 관리 흐름도

### 목적
가족, 보호자-피보호자 그룹 편성 및 그룹 내 최대 취약도 기준 경로 조정 과정

### 주요 부호 설명

- S410: 그룹 편성 조건 확인
- S420: 대피 그룹 생성
- S430: 그룹 내 최대 취약도 추출
- S440: 그룹 전체 경로 비용 함수 조정
- S450: 그룹 응집성 모니터링
- S460: 그룹 해산 조건

### 도면 설명문

도 9는 본 발명에 따른 대피 그룹 관리 흐름을 나타낸다.

먼저 그룹 편성 조건을 확인한다(S410). 동일 객실 체크인, 보호자-피보호자 관계, 교직원-학생 관계, 승무원 수동 편성 중 하나에 해당하면 그룹 편성 대상이 된다.

대피 그룹을 생성한다(S420). Group ID를 발급하고, 그룹 멤버 목록을 생성하며, 그룹장을 지정한다.

그룹 내 최대 취약도를 추출한다(S430). 그룹 내에 휠체어 사용자가 있으면 그룹 전체가 계단을 사용할 수 없고, 호흡기 환자가 있으면 그룹 연기 가중치를 3.0으로 설정하며, 어린이가 있으면 그룹 이동 속도를 최소값으로 설정한다.

그룹 전체 경로 비용 함수를 조정한다(S440). 그룹 경로 비용은 기본 비용에 그룹 멤버 중 최대 가중치를 곱하여 산출되며, 모든 그룹 멤버가 동일한 경로를 할당받는다.

그룹 응집성을 모니터링한다(S450). 그룹 멤버 간 거리가 20m를 초과하면 경고 메시지를 발송하고 대체경로를 재계산한다.

그룹 해산 조건을 확인한다(S460). 모든 멤버가 안전구역에 도착하거나, 그룹장이 수동으로 해산하거나, 승무원이 강제로 해산하면 그룹이 해산된다.

### 도면 설명문

도 13은 본 발명에 따른 재난 발생 시 사용자 상태를 실시간으로 수집하는 대화형 마이크로 설문 흐름도를 나타낸다.

1단계(S131)에서 재난 모드 활성화가 감지되면, 외부 자극 수집부(110)가 신호를 전달한다.

2단계(S132)에서 온톨로지 관리부(210)가 사용자 상태 온톨로지를 조회한다. 대화형 마이크로 설문부(500)는 이 정보를 기반으로 질문을 생성한다.

3단계(S133)에서 질문 생성 엔진(510)과 응답 방식 결정부(520)가 사용자의 이동능력, 감각 제약, 건강상태를 분석하여 질문 내용, 질문 개수(3문항 이하), 응답 방식을 자동으로 결정한다. 예를 들어 시각장애인에게는 음성 질문을, 청각장애인에게는 진동 알림과 화면 질문을 제공한다.

4단계(S134)에서 결정된 응답 방식(터치/음성/화면/진동)으로 설문을 사용자 단말에 전송한다.

5단계(S135)에서 응답 수집부(530)가 사용자의 응답을 수집한다. 응답 방식은 터치 입력, 음성 인식, 진동 패턴, 비명 감지 중 적어도 하나를 포함한다.

6단계(S136)에서 응답 수신 여부를 판단한다. 응답이 없으면 7단계(S137)로 진행하여 대체 응답 방식으로 재시도한다. 예를 들어 음성 응답이 없으면 터치 응답으로 전환한다. 재시도는 4단계(S134)로 루프백한다.

응답이 수신되면 8단계(S138)로 진행하여, 상태 업데이트부(540)가 수집된 데이터를 사용자 상태 온톨로지에 반영한다. 예를 들어 "부상 있음", "이동 곤란", "호흡 곤란" 등의 상태가 업데이트된다.

9단계(S139)에서 업데이트된 사용자 상태 정보를 경로 추천부(240)로 전달한다. 경로 추천부는 이 정보를 기반으로 개인별 대피 경로를 재계산한다.

본 발명의 대화형 마이크로 설문은 3문항 이하의 간결한 질문으로 재난 상황에서도 신속한 응답을 유도하며, 사용자 제약에 따라 응답 방식을 자동 조정하여 모든 사용자가 응답할 수 있도록 한다.
