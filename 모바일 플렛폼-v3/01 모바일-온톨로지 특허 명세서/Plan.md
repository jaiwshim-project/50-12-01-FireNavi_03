## §1. 입력 자료 요약

### 1-1. 기준 서비스
**FireNavi v3.0** — 스마트폰 기반 재난대피 통합 플랫폼

**주요 기능**:
- 스마트폰을 재난 감지 센서로 활용 (음향, 진동, 조도, 네트워크, 사용자 신고)
- 온톨로지 지식그래프 기반 위험지도 생성
- 개인별 맞춤형 대피 경로 AI
- 취약계층 안전 마진 자동 적용
- 관제센터 및 구조대 연계

**적용 시설**: WiFi 인프라를 보유한 대형 복합시설
- 크루즈선, 초고층 빌딩(50층 이상), 대형 공연장(5,000석 이상), 경기장, 전시장, 복합 지하철역(환승역), 복합 쇼핑몰, 호텔, 병원, 학교, 공항

### 1-2. 기존 초안
**p1~p8 디렉토리 구조**:
- p1-tech: 기술 분석, 선행조사, 차별성
- p2-competitor: 경쟁기술 분석
- p3-claims: 청구항 설계, 사업성 평가
- p4-spec-draft: 명세서 초안, 요약서, 발명의 명칭
- p5-spec-complete: 명세서 주요 섹션
- p6-embodiment: 실시예, 도면, 검증
- p7-final: 최종 검수
- p8-drawings: 도면 SVG 8개

### 1-3. 참고특허
**선행조사 보고서** (p1-tech/prior-art-report.md):
- IoT 센서 기반 대피 경로 안내
- BLE 비콘 기반 실내 위치 추정
- 스마트폰 음성 안내 기반 화재 대피
- BIM·온톨로지 기반 실내 화재 대피 모델
- 접근 가능한 대피 경로를 위한 사용자 프로파일 온톨로지
- 스마트폰 IMU·WiFi 기반 실내 측위
- 군중 상태 및 위험지도 생성 관련 연구

**1차 판정**: 개별 요소는 선행기술이 존재하나, FireNavi의 핵심인 **"다중 외부 자극 트리거 + 스마트폰 분산 인간센서 + 온톨로지 의미 정규화 + 개인별 경로 AI + 취약계층 안전 마진 + 관제·구조 연계"를 하나의 플랫폼으로 결합한 구조**는 차별화 가능성이 있다.

## §2. 기준 서비스 분해

### 2-1. 서비스 기술 요약

**FireNavi 파이프라인** (입력 → 처리 → 출력):

```
[입력] 다중 외부 자극 수집
  ↓
[정규화] 재난 온톨로지 노드 변환
  ↓
[위험지도] 공간·시간 기반 동적 화재맵 생성
  ↓
[사용자 상태] 온톨로지 기반 개인 제약 추출
  ↓
[경로 AI] 개인별 적응 대피 경로 산출
  ↓
[출력] 사용자·관제·구조대 안내
```

### 2-2. 사용된 기술 요소 분석 (5개 핵심)

| # | 기술 요소 | 동작·역할 | 사용 단계 | 기술적 난점 |
|---|---|---|---|---|
| 1 | 다중 외부 자극 기반 재난 트리거 엔진 | 화재경보음, 비상 음성 키워드, 비명·폭발음, 스마트폰 급진동·낙상 패턴, 조도 급감, WiFi/BLE 이상, 사용자 SOS, 선박 설비 신호, 관제센터 API 신호 등을 통합하여 재난 모드를 자동 활성화 | 입력 | 오작동 방지, 신호 교차검증, 신뢰도 점수 산출 |
| 2 | 센서·인간보고 온톨로지 정규화 기반 실시간 화재맵 | 스마트폰 센서와 사용자 보고를 화재, 연기, 혼잡, 출구폐쇄, 구조손상 등 재난 온톨로지 노드로 변환하여 시간·공간 기반 위험지도를 생성 | 정규화 → 위험지도 | 이질적 입력의 의미 통합, 신뢰도 가중치 설계 |
| 3 | 사용자·위험·공간 온톨로지 기반 개인별 적응 대피 경로 AI | 사용자 상태, 이동능력, 취약도, 현재 위치, 위험지도, 공간 연결성, 출구 혼잡도, 미래 위험 예측을 종합하여 개인별 경로를 산출 | 경로 AI | 실시간 재계산, 대체경로 자동 전환, 설명 가능성 |
| 4 | 취약계층 제약 온톨로지 기반 안전 마진 자동 적용 | 고령자, 어린이, 휠체어 사용자, 임산부, 호흡기 환자, 시각·청각장애인의 제약을 온톨로지로 정의하고, 경로 비용 함수에 안전 마진 계수를 자동 적용 | 경로 AI | 제약 우선순위, 그룹 내 최대 취약도 적용 |
| 5 | 스마트폰·온톨로지·AI 기반 재난대피 통합 플랫폼 | 스마트폰 앱, 엣지 서버, 온톨로지 지식그래프, AI 엔진, 관제센터, 구조대 단말을 통합하여 감지→판단→안내→관제→구조를 수행 | 전체 | 엣지-서버 분리, 네트워크 단절 대응, 역할별 권한 관리 |

### 2-3. 추가 발굴 제안

기존 서비스를 바탕으로 다음 요소를 추가 발굴 가능:
- **대피 그룹 관리** (가족, 보호자-피보호자 관계 기반 그룹 경로 조정)
- **엣지-서버 분리 아키텍처** (네트워크 단절 시 캐시 기반 최소 안내)
- **역할별 권한 관리** (일반 사용자 / 보호자 / 승무원 / 관제센터 / 구조대)
- **시설 유형별 특수성 대응** (초고층 빌딩, 대형 공연장, 복합 지하철역, 크루즈선)
- **대화형 마이크로 설문** (재난 시 사용자 상태 실시간 수집)

## §3. 발명 포인트 발굴 (넓게 펼치기)

### 군(群) 분류 — 파이프라인형 발명

FireNavi는 **입력 → 처리 → 출력** 흐름의 파이프라인형 발명이므로 **단계별로 군을 나눈다**.

### 군1: 입력 (다중 외부 자극 수집)
| 후보 | 출원 가치 | 4축 평가 (임팩트/상용/차별/발굴) |
|---|---|---|
| 12종 외부 자극 트리거 | 스마트폰을 재난 감지 센서로 전환 — 신규 하드웨어 불요 | ★★★★ / ★★★★★ / ★★★★ / ★★★★★ |
| 신뢰도 점수 기반 오작동 방지 | 다수 단말 교차검증, 입력원별 가중치 | ★★★ / ★★★★ / ★★★ / ★★★★ |

| 후보 | 출원 가치 | 4축 평가 |
|---|---|---|

| 공간 온톨로지 매핑 | WiFi/IMU/BLE → 층/복도/계단/피난구역 노드 | ★★★ / ★★★★ / ★★★ / ★★★★ |

| 후보 | 출원 가치 | 4축 평가 |

### 결합형 상위 컨셉 (독립항의 씨앗)

**컨셉 A: 통합 플랫폼 1개 독립항** (채택됨)
- 군1(입력) + 군2(정규화) + 군3(위험지도) + 군4(사용자 상태) + 군5(경로 AI) + 군6(출력)
- **조합 근거**: 전 단계를 "온톨로지"라는 기술적 끈으로 관통하여 단순 결합이 아닌 유기적 발명으로 구성
- 종속항에서 12종 트리거, 안전 마진, 이원 경로, 마이크로 설문, 그룹 관리 등을 보호

**컨셉 B: 복수 독립항** (기각됨 — 단일성 위험)
- 독립항 1: 입력+정규화+위험지도
- 독립항 2: 사용자 상태+경로 AI
- 독립항 3: 관제·구조 연계
- **기각 이유**: 공유하는 특별한 기술적 특징(STF)이 "온톨로지"뿐인데, 온톨로지는 선행기술이 많아 STF로 약함 → 단일성 거절 리스크

### 방향 합의
**✅ 선택: 전 과정을 하나로 꿴 상위 컨셉 (통합 플랫폼 독립항 1개)**

**근거**:
- 개별 단계는 선행기술이 많아 각각을 독립항으로 세우면 신규성·진보성 약함

- 자산가치 목적이므로 복수 독립항의 단일성 리스크보다 **단일 독립항으로 등록확실성** 우선

### ★ 핵심 경고 확인
전처리→생성→품질→대량→다운스트림을 "순서대로 한다"는 것만으로는 **단계의 단순 결합(공지기술 조합)**으로 진보성 거절을 맞기 쉽다.

**해법**: 전 단계를 관통하는 **기술적 끈(thread) 1개**가 있어야 단순 나열이 아닌 **하나의 유기적 발명**이 된다. → 다음 Phase 5에서 "온톨로지 지식그래프"를 관통 축으로 확정.

## §5. 관통 축(기술적 끈) 비교·확정

### 5-1. 축 후보 비교

**후보 축 3개**:

#### 축 A: **온톨로지 지식그래프로 꿰기** (채택됨)
**정의**: 재난 이벤트, 공간, 사용자 상태, 위험, 규정을 의미 노드와 관계로 표현하는 온톨로지 지식그래프가 전 단계에 전파되어 각 단계를 구동·제약한다.

**각 단계에서 어떻게 작동하나**:
1. **입력**: 음향·진동·조도 등 센서값을 재난 온톨로지 노드(화재/연기/혼잡)로 정규화
2. **위험지도**: 정규화된 의미 노드 + 공간 온톨로지를 결합하여 동적 화재맵 생성
3. **사용자 상태**: 사용자 상태 온톨로지(이동능력/감각 제약/건강)를 추출
4. **경로 AI**: 위험지도 + 사용자 상태 온톨로지 + 공간 온톨로지를 종합하여 경로 비용 함수 계산
5. **출력**: 추론 근거를 온톨로지 관계로 설명 (예: "휠체어 사용자이므로 계단 제외")

**강점**:
- 전 단계가 온톨로지를 공유 → 일관성·재사용성
- 의미 기반 추론 → 설명 가능성
- 시설별 특수성을 온톨로지로 정의 → 확장성

**약점**:
- "온톨로지" 자체는 공지기술 (BIM·온톨로지 기반 대피 선행 있음)
- 차별성은 "어떤 온톨로지를 어떻게 쓰느냐"에 달림

**평가**:
- 진보성(단순결합 탈피력): ★★★★ (온톨로지로 전 단계 일관 구동 → 유기적 발명)
- 상용가치: ★★★★★ (시설별 확장, 설명 가능성)
- 발명 정합(FireNavi): ★★★★★ (서비스 핵심 그대로)
- 명세서화 난이도: ★★★ (온톨로지 노드·관계 상세 정의 필요)

#### 축 B: **신뢰도 점수로 꿰기**
**정의**: 입력 단계에서 추출한 신뢰도 점수가 전 단계의 생성·검증에 공통 적용된다.

**각 단계에서 어떻게 작동하나**:
1. **입력**: 입력원별 신뢰도 가중치 산출 (센서 vs 인간보고)
2. **위험지도**: 신뢰도 가중치로 화재맵 생성
3. **경로 AI**: 신뢰도 낮은 위험은 경로 비용에 낮게 반영

**강점**: 오작동 방지, 정합성

**약점**:
- 신뢰도 점수는 **입력 단계의 부가 요소**일 뿐, 전 단계를 관통하는 핵심 축으로 보기 어려움
- 선행기술에서도 센서 융합 시 가중치 사용은 흔함

**평가**:
- 진보성: ★★ (단독으로는 약함)
- 상용가치: ★★★
- 발명 정합: ★★★
- 명세서화 난이도: ★★★★

**판정**: **종속항 보강 요소로 흡수** (청구항 4)

#### 축 C: **피드백 루프로 꿰기**
**정의**: 후단계의 신호가 전단계 파라미터를 보정하는 폐루프가 파이프라인을 관통한다.

**각 단계에서 어떻게 작동하나**:
1. **경로 AI**: 사용자가 추천 경로를 따르지 않음 감지
2. **위험지도**: 위험지도 갱신 트리거
3. **경로 AI**: 경로 재계산

**강점**: 무인·자동보정

**약점**:
- FireNavi는 재난 대피 시스템이라 **피드백 루프보다 실시간 대응**이 핵심
- 피드백 루프는 **대체경로 자동 전환**으로 이미 구현 (축이 아니라 기능)

**평가**:

- 상용가치: ★★★
- 발명 정합: ★★
- 명세서화 난이도: ★★★

**판정**: **종속항 보강 요소로 흡수** (청구항 7)

## §6. 발명 컨셉문 + 독립항 골격

### 6-1. 발명 컨셉문

**FireNavi는 스마트폰 센서·인간보고·설비 신호를 재난 이벤트 온톨로지로 정규화하고, 공간·사용자 상태 온톨로지와 결합하여 동적 위험지도를 생성한 후, 개인별 제약과 취약계층 안전 마진을 반영한 대피 경로를 AI로 산출하여 사용자·관제센터·구조대에 제공하는 재난대피 통합 플랫폼이다.**

### 6-2. 독립항 골격 (구성요소 단위)

**방법 독립항 골격** (시스템 독립항으로 전환됨 — 6-3 참조):

① **입력부**: 복수의 모바일 단말로부터 음향, 진동, 조도, 위치, 네트워크 상태, 사용자 신고 및 미응답 상태 중 적어도 하나의 외부 자극 데이터를 수집

② **정규화부**: 수집된 데이터를 재난 이벤트 온톨로지의 의미 노드로 정규화

③ **위험지도 생성부**: 정규화된 의미 노드와 시설 공간 온톨로지 및 사용자 상태 온톨로지를 결합하여 동적 위험지도를 생성

④ **경로 추천부**: 상기 위험지도와 사용자별 제약조건을 반영하여 개인별 대피 경로를 산출

⑤ **출력부**: 산출된 경로와 추천 사유를 사용자 단말, 관제센터 및 구조대 단말 중 적어도 하나에 제공

### 6-3. 독립항 범위 결정

**질문**: 독립항에 어디까지 넣을까?

**옵션 A**: ①~⑤ 전체 (채택됨)
- 코어가 단단하고 회피가 어려움
- 자산가치 목적에 적합

**옵션 B**: ①~④만 (출력 제외)
- 출력은 당연한 결과 → 독립항에서 빼고 종속으로
- **기각 이유**: 출력부에 "추천 사유 설명"과 "역할별 차등 출력"이 포함되어 차별성 요소 — 독립항에 유지

**✅ 확정**: ①~⑤ 전체를 독립항 코어로

**카테고리 결정** (Phase 9에서 확장):
- 핵심 독립항은 **시스템 독립항**으로 (방법 독립항은 시스템의 동작 방법으로 흡수 가능)
- Phase 9에서 **방법·시스템·컴퓨터프로그램** 카테고리 확장 검토

### 8-2. 시장 진입 유형 판별

**진입 전략형** — 기존 시장(재난 대피 시스템)에 경쟁자·선행기술이 있고, 그것을 회피·차별화하며 진입하는 형

**근거**:
- 기존: IoT 센서 기반 화재감지기, BLE 비콘 기반 대피 안내 → 신규 하드웨어 설치 비용 高
- FireNavi: 스마트폰 우선 → 신규 하드웨어 불요 → 진입장벽 낮춤
- 기존: 정적 대피 안내 → FireNavi: 개인별 맞춤 + 취약계층 보호 → 차별화

**차별 한정이 특히 중요** → 청구항에 "온톨로지 정규화 + 취약계층 안전 마진" 명시

### 8-3. 평가 → 액션

**✅ 가치 충분 + 기술 탄탄 → 다음 단계(청구항 작성)로**

**근거**:
- 시장 규모: 크다 (글로벌 재난안전 시장 연평균 7% 성장, 고령화 사회)
- 성장성: 모든 기술 요소 성장 중
- 차별성: 신규 하드웨어 불요, 취약계층 보호, 온톨로지 기반 설명 가능성
- 수익모델: SaaS 구독, 파일럿 계약, 관제센터 연동, 보험사 리스크 저감

**보강 불필요** — 기술 요소 충분히 강함

#### 독립항 1 (시스템)
스마트폰 기반 재난대피 통합 플랫폼에 있어서,

- 복수의 모바일 단말로부터 음향, 진동, 조도, 위치, 네트워크 상태, 사용자 신고 및 미응답 상태 중 적어도 하나의 외부 자극 데이터를 수집하는 **입력부**;
- 수집된 데이터를 재난 이벤트 온톨로지의 의미 노드로 정규화하는 **정규화부**;
- 정규화된 의미 노드와 시설 공간 온톨로지 및 사용자 상태 온톨로지를 결합하여 동적 위험지도를 생성하는 **위험지도 생성부**;

- 산출된 경로와 추천 사유를 사용자 단말, 관제센터 및 구조대 단말 중 적어도 하나에 제공하는 **출력부**를 포함하는 것을 특징으로 하는

**스마트폰·온톨로지·AI 기반 재난대피 통합 플랫폼.**

## §11. 요약(Abstract) 작성

### 11-1. 작성 방침 — 여기서는 "비교적 자세히"

**분량**: 5문단 (평균 기준)

**충실히 담을 것**:
- 청구항 내용 (독립항 핵심 구성 + 주요 종속항)
- 발명의 명칭 정합
- 과제 → 해결수단(관통 축) → 효과

**대표도 후보**: 도 1 (전체 시스템 구성도)

### 11-2. 요약 초안 (5문단)

**문단 1 (발명 개요 + 과제)**:
본 발명은 다중이용시설 또는 선박 내 재난 상황에서 스마트폰을 재난 감지 센서 및 개인별 대피 안내 장치로 활용하는 스마트폰·온톨로지·AI 기반 재난대피 통합 플랫폼에 관한 것이다.

**문단 2 (입력 + 정규화)**:
본 발명은 화재경보음, 비상 음성 키워드, 비명, 폭발음, 스마트폰의 급진동·낙상 패턴, 조도 급감, WiFi/BLE 신호 이상, 사용자 신고, 미응답·무이동 상태, 선박 또는 시설 설비 신호 및 관제센터 API 신호를 포함하는 복수의 외부 자극을 수집한다. 수집된 데이터는 재난 이벤트 온톨로지의 화재, 연기, 혼잡, 출구폐쇄, 구조손상, 정전 및 시야저하 노드 등으로 정규화된다.

**문단 3 (위험지도 + 사용자 상태)**:
정규화된 의미 노드는 공간 온톨로지 및 사용자 상태 온톨로지와 결합되어 동적 위험지도를 생성하고, 개인별 이동능력, 감각 제약, 건강상태, 보호자 관계 및 취약계층 안전 마진을 반영한 대피 경로를 산출한다.

**문단 4 (경로 AI + 출력)**:
또한 본 발명은 주경로와 대체경로를 동시에 생성하고, 위험 변화나 미래 위험 예측에 따라 자동 전환하며, 추천 경로의 이유를 사용자, 관제센터 및 구조대에 설명한다.

**문단 5 (효과)**:
이에 따라 신규 하드웨어 설치 부담을 줄이면서도 개인별 맞춤 대피, 취약계층 우선 보호, 실시간 관제 및 구조대 연계를 가능하게 한다.

### 11-3. 청구항·명칭 정합 확인

**명칭 요소 vs 요약**:
- ✅ 스마트폰 센서 → 문단 2
- ✅ 온톨로지 지식그래프 → 문단 2~3
- ✅ 인공지능 경로 엔진 → 문단 3~4

- ✅ 경로 추천부 → 문단 3~4

**D2**: 스마트폰 기반 화재 감지 및 음성 안내 시스템 (선행특허)
- 스마트폰 음향 분석으로 화재 감지
- **차이점**: 온톨로지 정규화 없음, 개인별 경로 AI 없음

**D3**: IoT 센서 기반 대피 경로 안내 시스템 (선행특허)
- 화재감지기, 연기감지기 신호로 대피 경로 안내
- **차이점**: 스마트폰 우선 아님, 온톨로지 없음

### 신규성(제29조①) 점검

**청구항 1 결합구성이 단일 인용발명에 그대로 있는가?**

**판정**: ✅ **신규성 인정 가능**

**근거**:
- D1은 온톨로지는 있으나 **스마트폰 다중 외부 자극 트리거**가 없음
- D2는 스마트폰 화재 감지는 있으나 **온톨로지 정규화 + 개인별 경로 AI**가 없음
- D3은 대피 경로 안내는 있으나 **스마트폰 + 온톨로지**가 없음
- **결론**: 단일 인용발명에 청구항 1의 결합구성이 그대로 없음 → 신규성 OK

### 진보성(제29조②) 점검

**심사관의 전형적 주공격**:
"각 구성요소·단계가 개별적으로 공지이거나 인용발명에서 시사되므로, 그 결합은 통상의 기술자에게 자명하다"

**예상 공격 시나리오**:
1. D1(온톨로지 대피)에 D2(스마트폰 화재 감지)를 결합하면 청구항 1이 자명하다
2. 각 단계(입력→정규화→위험지도→경로)는 개별적으로 공지 → 단순 결합

**반박 논리 (관통 축 기반)**:

**✅ 본 발명은 단계의 단순 결합이 아니라, "온톨로지 지식그래프"라는 하나의 끈이 전 단계를 일관되게 구동·제약하므로, 개별 구성의 합으로 환원되지 않는다.**

**구체적 반박**:
1. **입력**: 센서값을 단순 이벤트로 저장하지 않고 **재난 온톨로지 노드로 정규화** → 의미 통합
2. **위험지도**: 정규화된 의미 노드 + 공간 온톨로지를 **결합**하여 동적 화재맵 생성 → 공간·의미 일관성
3. **경로 AI**: 위험지도 + 사용자 상태 온톨로지를 **종합**하여 경로 비용 함수 계산 → 개인별 제약 자동 반영
4. **출력**: 추론 근거를 온톨로지 관계로 **설명** → 설명 가능성

**핵심**: 온톨로지가 전 단계에 전파되어 **일관된 의미 체계**를 유지 → 단순 결합보다 유기적 발명

**관통성 구절 추가 검토**:
독립항 1에 이미 "재난 이벤트 온톨로지의 의미 노드로 정규화" + "공간 온톨로지 및 사용자 상태 온톨로지를 결합" 명시 → 관통성 구절 충분

**추가 보강 불필요** — 현재 독립항으로 반박 가능
